# S36 — Plytka kopia przez spread `{...obj}` (2026-08-02)

**Koncept:** `{...obj}` tworzy NOWY obiekt tylko na najwyzszym poziomie. Kazde pole, ktore samo jest obiektem, jest kopiowane jako REFERENCJA — mutacja w "kopii" widoczna jest tez w oryginale.

**Format:** ULOZ KOLEJNOSC WYKONANIA · **Fabula:** system newsletterowy "InboxPilot"

## Starcie 1 — kopia szablonu kampanii

```js
const kampaniaBazowa = {
  temat: "Newsletter tygodniowy",
  targeting: { wyslane: false, segment: "wszyscy" }
};

const kampaniaVIP = { ...kampaniaBazowa };

console.log(kampaniaBazowa === kampaniaVIP);
console.log(kampaniaBazowa.targeting === kampaniaVIP.targeting);
```

**Zanim przewiniesz: przewidz obie linie.**

## Starcie 2 — funkcja oznaczajaca kampanie jako wyslana

```js
function oznaczWyslana(kampania) {
  const kopia = { ...kampania };
  kopia.targeting.wyslane = true;
  return kopia;
}

const bazowa = { temat: "Newsletter tygodniowy", targeting: { wyslane: false, segment: "wszyscy" } };
const vip = oznaczWyslana(bazowa);

console.log(bazowa.targeting.wyslane);
console.log(vip.targeting.wyslane);
console.log(bazowa === vip);
```

**Pytanie:** dlaczego mutacja "kopii" zmienia tez `bazowa`, skoro funkcja zwraca nowy obiekt?

## Verified (node, uruchomione przed publikacja)

```
Starcie 1: false / true
Starcie 2: true / true / false
```

Spread nie sklonowal `targeting` — oba obiekty wskazuja to samo miejsce w pamieci. Naprawa: `structuredClone(obj)` albo `JSON.parse(JSON.stringify(obj))`.

## Quiz

1. `const a = { x: 1, y: { z: 2 } }; const b = { ...a };` — ile wynosi `a === b`, a ile `a.y === b.y`? → `false` / `true` (spread kopiuje tylko poziom 1)
2. Dwa sposoby na prawdziwie niezalezna kopie? → `structuredClone(obj)`, `JSON.parse(JSON.stringify(obj))`
3. Czemu `kopia = {...zamowienie}; kopia.tagi.push(tag)` zmienia tez oryginal? → `kopia.tagi` i `zamowienie.tagi` to ta sama tablica w pamieci

## Karta (SM-2)

**Q:** Co dokladnie kopiuje `{...obj}`, a czego NIE kopiuje?
**A:** Plytka kopia: nowy obiekt na poziomie 1 (`obj === {...obj}` → false), ale zagniezdzone pola-obiekty ida jako referencje (`obj.pole === {...obj}.pole` → true). Mutacja zagniezdzonego pola w kopii zmienia tez oryginal.

---
*Puenta: `{...obj}` daje falszywe poczucie bezpieczenstwa — powloka jest nowa, ale wszystko w srodku, co samo jest obiektem, to wciaz ten sam kawalek pamieci co oryginal. Dokladnie ten wzorzec czyha w kodzie integracyjnym robiacym `{...config}` przed nadpisaniem jednego ustawienia per-request.*
