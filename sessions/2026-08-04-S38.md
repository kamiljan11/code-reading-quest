# S38 — `-0` kontra `+0`: `===` slepe na znak zera (2026-08-04)

**Koncept:** `0 === -0` i `0 == -0` daja `true` — operatory rownosci nie widza znaku zera. `Object.is(0, -0)` daje `false` — jedyna para liczb, gdzie `Object.is` i `===` sie roznia (dla `NaN` jest odwrotnie: `Object.is` widzi rownosc, ktorej `===` nie widzi). Znak przetrwa w dzieleniu (`1 / -0` -> `-Infinity`), ale ginie przy serializacji (`JSON.stringify(-0)` -> `"0"`).

**Format:** REVERSE (z outputu wywnioskuj wejscie) · **Fabula:** cicha winda serwisowa "Zero-1"

## Verified (node, uruchomione przed publikacja; wejscieA=`5-5`, wejscieB=`-1*0`)

```
Snippet 1: Winda stoi. / Winda stoi. / 0 / -0 / false / Infinity / -Infinity

```

`===` porownuje wartosc liczbowa zera (identyczna dla obu znakow), wiec obie galezie "Winda stoi." sa te same. `Object.is` i dzielenie odczytuja bit znaku i widza roznice. `JSON.stringify` normalizuje `-0` do `"0"` — znak ginie przy serializacji, mimo ze `Object.is` go widzial chwile wczesniej.

## Quiz

1. Ile wynosi `0 === -0`? A `Object.is(0, -0)`? → `true` / `false`
2. Dwa sposoby otrzymania `-0` w JS? → `-1 * 0`, `Math.round(-0.4)`
3. Czemu `1 / x` daje `Infinity` dla jednego zera i `-Infinity` dla drugiego, mimo `x === 0` w obu przypadkach? → dzielenie przez zero odczytuje bit znaku mianownika, `===` go ignoruje

## Karta (SM-2)

**Q:** Czym rozni sie `0 === -0` od `Object.is(0, -0)`, i skad sie bierze `-0`?
**A:** `0 === -0` -> `true` (operatory rownosci porownuja wartosc, identyczna dla obu znakow). `Object.is(0, -0)` -> `false` (jedyna para liczb, gdzie `Object.is` i `===` sie roznia — dla `NaN` jest odwrotnie). `-0` powstaje z `-1 * 0` albo `Math.round(-0.4)`. Znak przetrwa w dzieleniu (`1/-0` -> `-Infinity`), ginie przy `JSON.stringify(-0)` -> `"0"`.
