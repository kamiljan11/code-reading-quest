# S39 — Centrum monitoringu satelitów "SkyWatch"

**Concept:** `.indexOf()` compares via `===`, and `NaN === NaN` is always `false`, so `.indexOf(NaN)` always returns `-1` — even when `NaN` is sitting right there in the array. `.includes()` compares via the **SameValueZero** algorithm, which (like `Object.is`) treats `NaN` as equal to itself: `[NaN].includes(NaN)` → `true`. But SameValueZero differs from `Object.is` on zero: it treats `0` and `-0` as equal (like `===`), while `Object.is(0, -0)` is `false`. Same algorithm powers `Map` and `Set`.

## Snippet 1 — sensor log

```js
const odczytySensorow = [12, 15, NaN, 18, -0];

console.log(odczytySensorow.indexOf(NaN));
console.log(odczytySensorow.includes(NaN));
console.log(odczytySensorow.indexOf(0));
console.log(odczytySensorow.includes(0));
```

## Snippet 2 — "has this error already been logged?"

```js
function czyBladJuzZalogowany(historia, odczyt) {
  return historia.indexOf(odczyt) !== -1;
}

function czyBladJuzZalogowanyFix(historia, odczyt) {
  return historia.includes(odczyt);
}

const historiaBledow = [12, NaN, 18];

console.log(czyBladJuzZalogowany(historiaBledow, NaN));
console.log(czyBladJuzZalogowany(historiaBledow, 18));
console.log(czyBladJuzZalogowanyFix(historiaBledow, NaN));
console.log(czyBladJuzZalogowanyFix(historiaBledow, 18));
```

Line by line: `indexOf(NaN)` → `-1` (blind to NaN). `includes(NaN)` → `true` (SameValueZero sees it). `indexOf(0)` → `4` (finds the `-0` entry, because `0 === -0` is `true`). `includes(0)` → `true` (same reason). Then the bug: `czyBladJuzZalogowany` with `.indexOf()` returns `false` for a `NaN` that's already in the array — the dedupe check silently fails for exactly the value most likely to repeat. Swapping to `.includes()` fixes it with a one-word diff.

## Quiz

1. Why does `[NaN].indexOf(NaN)` return `-1` while `[NaN].includes(NaN)` returns `true`?
   **Key:** `indexOf` compares via `===` (`NaN === NaN` is always `false`); `includes` compares via SameValueZero, which treats `NaN` as equal to itself.
2. Where exactly do SameValueZero and `Object.is` disagree?
   **Key:** Only on zero — SameValueZero treats `0` and `-0` as equal (like `===`); `Object.is(0, -0)` is `false`. Both agree that `NaN` equals itself.
3. A dedupe check uses `historia.indexOf(odczyt) !== -1`. What's the one-line fix, and why does it work?
   **Key:** Replace with `historia.includes(odczyt)` — SameValueZero catches the `NaN` case that `===`-based `indexOf` structurally cannot.

## Card (spaced repetition)

**Front:** What's the difference between `.indexOf(NaN)` and `.includes(NaN)`, and how does SameValueZero differ from `Object.is`?
**Back:** `.indexOf()` searches via `===`, which never recognizes `NaN === NaN`, so `.indexOf(NaN)` always returns `-1`. `.includes()` searches via SameValueZero, which (like `Object.is`) treats `NaN` as equal to itself — `[NaN].includes(NaN)` → `true`. SameValueZero differs from `Object.is` only on zero: it treats `0` and `-0` as equal (like `===`), while `Object.is(0, -0)` → `false`. `Map` and `Set` use the same algorithm (`new Set([NaN, NaN]).size` → `1`).

---

Three ways to ask "is this equal" in the same language, and each one lies in a different place. Reading code safely means knowing which one you're asking.
