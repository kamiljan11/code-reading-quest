# S42 — ParkFlow: an empty form field equals zero (2026-08-08)

**Concept:** `==` is not transitive. `0 == ""` is `true` and `0 == "0"` is `true`, but `"" == "0"` is `false`.
`==` coerces **only** when the two sides have different types. Number vs string coerces the string to a number
(`""` -> 0, `"0"` -> 0). String vs string coerces nothing and compares the text itself.

**Story:** the entry barrier at the "ParkFlow" car park reads a free-slot limit from the admin panel.
The car park has 5 free slots and still refuses every car.

## Snippet 1 — three values that all "mean zero"

```js
const wolneMiejsca = 0;
const zPola = "";

console.log(wolneMiejsca == zPola);
console.log(wolneMiejsca == "0");
console.log(zPola == "0");
console.log(null == undefined);
console.log(null == 0);
```

## Snippet 2 — the barrier: one line lies

```js
function czyWpuscic(wolne, limitZFormularza) {
  if (limitZFormularza == 0) {
    return "BLOKADA: limit ustawiony na zero";
  }
  return wolne > 0 ? "OTWIERAM" : "PELNO";
}

console.log(czyWpuscic(5, 0));
console.log(czyWpuscic(5, ""));
console.log(czyWpuscic(5, "0"));
console.log(czyWpuscic(5, false));
console.log(czyWpuscic(5, 10));
```

## Quiz

1. **`0 == ""` is true and `0 == "0"` is true. Why is `"" == "0"` false?**
   `==` coerces only when the types differ. Number vs string sends the string to a number (both become 0).
   String vs string coerces nothing, so the contents are compared: empty text vs one-character text -> false.

2. **`null == undefined` is true but `null == 0` is false. How does `null` differ from `""` and `false` here?**
   `null` is never coerced to a number by `==`. The spec gives it a special rule: it is loosely equal only to
   `undefined` and to itself. `""` and `false` do get coerced to `0`, which is why they compare equal to zero.

3. **The barrier should block only when an admin deliberately set the limit to the number zero. Why is swapping `==` for `===` enough?**
   `===` performs no type conversion, so only the actual number `0` passes. An unfilled field (`""`), a string
   from the form (`"0"`) and an unchecked box (`false`) stop impersonating zero. Note that `"0"` also stops
   blocking, so a real form parser should call `Number(field)` at the input boundary.

## Card

**Front:** Why is `==` not transitive — `0 == ""` true, `0 == "0"` true, but `"" == "0"` false?

**Back:** `==` coerces only when the types differ. Number vs string sends the string to a number, so both
comparisons are `0 == 0`. String vs string does no conversion and compares the text, so `"" == "0"` is false.
Consequence: `0`, `""`, `"0"` and `false` are all "equal to zero" without being equal to each other.
Exception: `null == undefined` is true, `null == 0` is false.

## Takeaway

`==` does not lie at random. It lies exactly when the two sides have different types. When reading someone
else's condition, check the **types** of both sides before the values — if the types differ, the condition
means something other than what it says.
