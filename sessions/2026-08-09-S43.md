# S43 — One plus that doesn't add (2026-08-09)

**Concept:** `+` is the only arithmetic operator with a text mode. If either side is a string, `+` concatenates instead of adding. `-`, `*`, `/` and `%` have no such mode — they always coerce both sides to a number.

**Story:** 🏰 Guild treasury "Zloty Gryf" counts gold from quests. One reward arrived from a different API.

## Starcie 1 — evening settlement

```js
const zlotoZQuestow = [120, "80", 45];

let suma = 0;
for (const nagroda of zlotoZQuestow) {
  suma = suma + nagroda;
}
console.log(suma);
console.log(typeof suma);

console.log(120 + "80");
console.log(120 - "80");
console.log("120" * 2);
console.log("120" / "2");
```

## Starcie 2 — the payout window uses subtraction

function wyplac(skarbiec, kwota) {

## Quiz

1. `120 + "80"` gives `"12080"` but `120 - "80"` gives `40`. How does `+` differ from `-` when a string is involved?
   **Key:** `+` is the only arithmetic operator with a text mode — if either side is a string it concatenates. `-`, `*`, `/`, `%` have no text mode and always coerce both sides to numbers.

2. Summing `[120, "80", 45]` yields `"1208045"`. When exactly did the accumulator stop being a number, and why didn't `+ 45` fix it?
   **Key:** In the second iteration, at `120 + "80"`. From then on `suma` is the string `"12080"`, so `+ 45` is string-plus-number again — another concatenation. The accumulator carries its type forward, so one poisoning propagates to the end of the loop.

3. You have an array of amounts from an API, some numbers and some strings. What single change fixes the sum, and why is `parseInt` not the best choice here?
   **Key:** `suma = suma + Number(nagroda)` (or unary `+nagroda`) — explicit conversion of every element before adding. `parseInt` truncates decimals (`parseInt("12.9")` -> 12) and stops at the first non-digit (`parseInt("80zl")` -> 80), silently accepting broken data; `Number("80zl")` gives `NaN`, so the problem stays visible.

## Card (SM-2)

**Front:** Why does `120 + "80"` give `"12080"` while `120 - "80"` gives `40`?

**Back:** `+` has two jobs: with any string operand it concatenates instead of adding. `-`, `*`, `/`, `%` have no text mode and always coerce to number. In a summing loop one string poisons the whole total, because after the first concatenation the accumulator *is* a string (`[120,"80",45]` -> `"1208045"`, not `245`). The console hides it — you need `typeof`. Fix: `Number(x)` or unary `+x` per element; `parseInt("80zl")` returns 80 instead of NaN and quietly swallows bad data.

## Takeaway

A number that arrived as text doesn't shout. There is no error and no warning — only a result that looks like a number and isn't. In integration code (form fields, JSON, query strings, TEXT columns) the type of a value is the first question, not the last.
