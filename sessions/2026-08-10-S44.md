# S44 — Strike Zone bowling alley: same plus, two different results

**Concept:** `+` is left-associative. It evaluates in pairs, left to right, so `a + b + c` is always `(a + b) + c`. What decides the result is not *whether* a string is in the line, but *where* it sits. From the first pair that contains text, the result is already text and carries that type to the end of the line.

**Format:** reverse (infer the input from the output)
**Language:** JavaScript (node v22.22.3)

## Encounter 1 — the scoreboard: five plusses, five different stories

```js
const gracz = "Ola";
const rzut1 = 7;
const rzut2 = 3;

console.log("Wynik: " + rzut1 + rzut2);
console.log("Wynik: " + (rzut1 + rzut2));
console.log(rzut1 + rzut2 + " punktow");
console.log(rzut1 + " + " + rzut2);
console.log(gracz + rzut1 + rzut2);
```

## Encounter 2 — reverse: you see the code, not the calls

```js
function zapiszWynik(gracz, rzut1, rzut2) {
  const suma = rzut1 + rzut2;
  console.log(gracz + " zdobyl " + suma + " pkt (rzuty: " + rzut1 + ", " + rzut2 + ")");
}

// Four calls you cannot see. Production log below.
```

Production log (exactly these four lines, in this order):

```
Ola zdobyl 10 pkt (rzuty: 7, 3)
Bartek zdobyl 73 pkt (rzuty: 7, 3)
Cela zdobyl 73 pkt (rzuty: 7, 3)
Ewa zdobyl NaN pkt (rzuty: 7, undefined)
```

Reconstruct the four calls. One of them has **two** correct answers that produce an identical line — find both and explain why the log cannot tell them apart.

## Diagram

```
`+` evaluates in pairs from the left. The parenthesis is there even when you don't type it:

  "Wynik: " + 7 + 3          7 + 3 + " pkt"
  = ("Wynik: " + 7) + 3      = (7 + 3) + " pkt"
  = "Wynik: 7"  + 3          = 10 + " pkt"
  = "Wynik: 73"              = "10 pkt"

  TEXT PREFIX  -> poisons the rest of the line
  TEXT SUFFIX  -> leaves the arithmetic alone
  PARENS       -> rescue the prefix: "Wynik: " + (7 + 3) -> "Wynik: 10"

Encounter 2 trace:
  7   + 3         -> 10     (two numbers)
  "7" + 3         -> "73"   (string FIRST)
  7   + "3"       -> "73"   (string SECOND — same result!)
  7   + undefined -> NaN    (missing argument)
```

## Quiz

1. **`"Wynik: " + 7 + 3` gives `"Wynik: 73"` but `7 + 3 + " punktow"` gives `"10 punktow"`. Same operator, same numbers — what decided the difference?**
   Left-associativity combined with the *position* of the string. `"Wynik: " + 7 + 3` is `("Wynik: " + 7) + 3` — the first pair is string + number, so it concatenates, and the result is already text. `7 + 3 + " punktow"` is `(7 + 3) + " punktow"` — the first pair is two numbers, so it really adds (10), and the text joins at the end. A text prefix poisons the rest of the line; a suffix does not.

2. **The log says `Bartek zdobyl 73 pkt (rzuty: 7, 3)`. Why can't you tell from the log whether the string was the first or the second throw?**
   Because concatenation calls `String()` on both sides, so the number `7` and the string `"7"` render as the same character — the type information is destroyed at print time. You need `typeof rzut1` / `typeof rzut2`, or pass the values to `console.log` as separate arguments instead of concatenating (`console.log("rzuty:", rzut1, rzut2)` — node prints `'7'` with quotes for a string).

3. **A colleague "fixes" the function with `const suma = "" + rzut1 + rzut2`. What does that do to Ola's line, and why is it worse than no fix?**
   It turns every sum into concatenation, because `"" + rzut1` is a string immediately. Ola's correct line degrades from `10` to `73`. Worse than no fix, because it kills the signal: `NaN` was loudly announcing a missing argument, and now the same spot prints `7undefined`, which looks like an ordinary value in a log. The real fix is `Number(rzut1) + Number(rzut2)` — Ola, Bartek and Cela all get `10`, and Ewa still gets `NaN`, so bad input stays visible.

## Spaced repetition card

**Front:** Why does `"Wynik: " + 7 + 3` give `"Wynik: 73"` while `7 + 3 + " pkt"` gives `"10 pkt"`?

**Back:** `+` is left-associative — it evaluates in pairs from the left, so `a + b + c` is always `(a + b) + c`. In the first case the first pair is string + number, so it concatenates and every later `+` concatenates too. In the second the first pair is two numbers, so it really adds (10), and the text joins last. Rule of thumb: a text prefix poisons the rest of the line, a suffix does not, and parentheses around the sum rescue the prefix. The log does not show types (concatenation calls `String()` on both sides), so `("7", 3)` and `(7, "3")` produce the same message — only `typeof` separates them. A missing argument is `undefined`, `7 + undefined` is `NaN`, but `"text" + NaN` is `"textNaN"` — `+` pastes `NaN` into the message instead of throwing.

## Takeaway

The parenthesis you didn't write is there anyway, and JavaScript always puts it on the left. When you read someone else's line with several plusses — building a URL, a cache key, a webhook body — don't ask "is there a string here", ask "where in the queue is the *first* string". From that point on, the rest of the line is concatenation. This is everyday integration work: form fields, query strings and TEXT columns all arrive as text, and the log looks identical in the correct and the broken version.
