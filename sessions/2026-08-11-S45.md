# S45 — When `+` meets an object

**Date:** 2026-08-11
**Concept:** Operators — string conversion of objects and arrays in `+`
**Format:** predict the output
**Theme:** 🎬 Cinema "Kadr" — self-service ticket kiosk

## The idea

When one side of `+` is a structure, JS calls `String(x)`, which calls `x.toString()`.

An **array** has its own `toString()` that behaves like `.join(",")`, so its contents survive.
A **plain object** inherits the default `Object.prototype.toString()`, which never looks at the fields
and returns the constant `"[object Object]"` — the same string for `{}`, for `{row: 4}`, and for an
object with five hundred fields.

The content does not vanish with an error. It is silently replaced by a constant.

## Round 1 — the kiosk prints a ticket label

```js
const bilet = { rzad: 4, miejsce: 12 };
const miejsca = [4, 12];
const pusty = [];
const jedno = [7];

console.log("Miejsce: " + bilet);
console.log("Miejsce: " + miejsca);
console.log("Miejsce: " + pusty);
console.log(1 + jedno);
console.log("Rzad: " + bilet.rzad + ", miejsce: " + bilet.miejsce);
```

## Round 2 — same kiosk, now booking. Three viewers, three different seats, one cache

```js
const cache = {};

function kluczBiletu(widz, bilet) {
  return "bilet:" + widz + ":" + bilet;
}

function rezerwuj(widz, bilet) {
  const klucz = kluczBiletu(widz, bilet);
  if (cache[klucz]) {
    console.log("DUPLIKAT " + klucz);
    return;
  }
  cache[klucz] = true;
  console.log("OK " + klucz);
}

rezerwuj("ola", { rzad: 4, miejsce: 12 });
rezerwuj("ola", { rzad: 9, miejsce: 3 });
rezerwuj("bartek", { rzad: 9, miejsce: 3 });
console.log(Object.keys(cache).length);
```

## Verified

Run with node v22.22.3.

Round 1:

```
Miejsce: [object Object]
Miejsce: 4,12
Miejsce: 
17
Rzad: 4, miejsce: 12
```

Round 2:

```
OK bilet:ola:[object Object]
DUPLIKAT bilet:ola:[object Object]
OK bilet:bartek:[object Object]
2
```

Ola's second booking is rejected as a duplicate even though it is a different seat. The whole content
of the object disappeared from the cache key, so both of her tickets produce the same string.

Conversion table (also verified separately):

```
{}        -> "[object Object]"     {a:1}     -> "[object Object]"   (identical!)
[]        -> ""                    [7]       -> "7"
[4,12]    -> "4,12"                [1,[2,3]] -> "1,2,3"  (flattened)
null      -> "null"                [null]    -> ""       (different!)
1 + [7]   -> "17"  (a string, not 8)
1 + [7,8] -> "17,8"
[] + {}   -> "[object Object]"
```

The `JSON.stringify(bilet)` fix, run separately, produces three `OK` lines instead of two — the bug is
gone. But a fourth call `rezerwuj("ola", { miejsce: 12, rzad: 4 })` (same seat, fields written in the
opposite order) also prints `OK`, because `JSON.stringify()` follows insertion order. The fix is real
but partial.

## Quiz

1. `"Miejsce: " + [4, 12]` gives `"Miejsce: 4,12"` while `"Miejsce: " + {rzad: 4, miejsce: 12}` gives
   `"Miejsce: [object Object]"`. Same operator — where does the difference come from?
   **Key:** not in the operator, but in which `toString()` the right-hand structure has. An array has
   its own (works like `.join(",")`), a plain object inherits the default one, which ignores fields
   and returns a constant.

2. Ola's second booking is rejected as a duplicate although it is a different seat. Why doesn't the
   log help diagnose this, and what has to change?
   **Key:** the log prints `bilet:ola:[object Object]`, which looks like a complete, valid key — no
   error, no `undefined`, no empty field. The data loss is silent: the content was replaced by a
   constant that itself looks like a value. To see it, pass the object as a separate argument
   (`console.log("klucz:", widz, bilet)`) or serialize it explicitly.

3. A colleague replaces `+ bilet` with `+ JSON.stringify(bilet)`. Does it fix the bug, and is the fix
   complete?
   **Key:** it fixes this bug (verified), but it is not complete — `JSON.stringify()` serializes fields
   in insertion order, so the same ticket written as `{miejsce:12, rzad:4}` yields a different string
   and passes as a new booking. Build the key from specific fields in a fixed order instead.

## Card added

**Front:** What does `+` do when the other side is an object or an array?
**Back:** Calls `String(x)` → `x.toString()`. An array has its own `toString()` (like `.join(",")`),
so contents survive: `[4,12]` → `"4,12"`, `[7]` → `"7"`, `[]` → `""`, `[1,[2,3]]` → `"1,2,3"`.
A plain object inherits `Object.prototype.toString()`, which ignores the fields and returns the
constant `"[object Object]"`. Hence `1 + [7]` is `"17"` (a string, not 8), and a cache key glued
together from a whole object is identical for every object.

## Takeaway

`undefined` shouts. `NaN` shouts. `null` at least introduces itself. `[object Object]` does none of
that — it looks like a proper value and travels through logs, cache keys and URLs without a single
warning. In integration code, the most dangerous conversion is the one whose result looks correct.
