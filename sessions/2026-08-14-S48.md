# S48 — Default values only fire for `undefined`

**Date:** 2026-08-14 · **Concept:** operators and comparisons · **Language:** JavaScript · **Format:** predict the output

A default value written with `=` — in a function parameter or in a destructuring pattern — fires
**only** when the value is exactly `undefined`. A field explicitly set to `null` walks straight past
it, and then lands in a loop where `0 < null` becomes `0 < 0`: zero iterations, zero notifications,
and a completely calm log.

## The story

"Nocny Dyżur" sends alerts when something in the server room dies. Every channel has its own config
row in the database: how many retries, what timeout, what priority. The columns are optional, so the
developer put sensible defaults in the destructuring pattern and considered the matter closed.

One night the air conditioning failed. In the morning the log has five lines and not one of them
contains the word `error`.

## Encounter 1 — two configs side by side

```js
const cfgA = {};
const cfgB = { proby: null };
console.log(cfgA.proby, cfgB.proby);
console.log(cfgA.proby ?? 3, cfgB.proby ?? 3);
function f(x = 3) { return x; }
console.log(f(cfgA.proby), f(cfgB.proby));
console.log(0 < cfgB.proby, 0 < cfgA.proby);
console.log(cfgA.limity?.max, cfgB.proby?.toFixed);
```

## Encounter 2 — the notification service

```js
function powiadom(kanal, opcje = {}) {
  const { proby = 3, timeoutMs = 5000, priorytet = "normalny" } = opcje;
  let wyslane = 0;
  for (let i = 0; i < proby; i++) {
    wyslane = wyslane + 1;
  }
  console.log(kanal + ": proby=" + proby + " timeout=" + timeoutMs + " prio=" + priorytet + " -> wyslano " + wyslane);
}

powiadom("sms-dyzurny", {});
powiadom("mail-kierownik", { proby: 1 });
powiadom("push-technik", { proby: null, timeoutMs: null });
powiadom("slack-zespol", { priorytet: undefined });
powiadom("syrena-lokalna");
```

b) Encounter 2: write out the whole five-line log. For `push-technik`, give exactly what appears

c) The log has five lines, every one ends with a number, and nowhere does it say `error`. Which

*Directional hint, not the answer: for each of the five calls, write down separately what value
`proby` received — before computing anything else. Then, for the one value that is not a number,
evaluate the loop condition by hand and ask how many times the body runs.*

## Verified

Intermediate steps, each executed separately:

```
Number(null)                -> 0          Number(undefined)          -> NaN
0 < null                    -> false      0 < undefined              -> false
({}).x                      -> undefined  ({x: null}).x              -> null
"proby" in {proby: null}    -> true       "proby" in {}              -> false
null ?? 3                   -> 3          0 ?? 3                     -> 0
null || 3                   -> 3          0 || 3                     -> 3
JSON.stringify({a:null, b:undefined})     -> {"a":null}
```

Iteration counter, `function ile(n) { let k = 0; for (let i = 0; i < n; i++) { k++; } return k; }`:

```
ile(null) -> 0    ile(undefined) -> 0    ile(0) -> 0    ile("2") -> 2
```

Four default-value strategies, run over `[{}, {proby:1}, {proby:null}, {proby:undefined}, {proby:"2"}, {proby:0}]`:

```
const {proby = 3} = o                       -> [3, 1, null, 3, '2', 0]
o.proby ?? 3                                -> [3, 1, 3,    3, '2', 0]
o.proby || 3                                -> [3, 1, 3,    3, '2', 3]
typeof o.proby === "number" ? o.proby : 3   -> [3, 1, 3,    3, 3,   0]
```

Passing `null` as the whole options argument:

```
powiadom("test", null)       -> TypeError: Cannot read properties of null (reading 'proby')
powiadom("test", undefined)  -> proby=3
```

## Answer key

`push-technik` is the dangerous one. Its alert never went out. `proby` was `null`, the `= 3` default
did not fire (it only fires for `undefined`), and `0 < null` coerces to `0 < 0` — false on the very
first check, so the loop body never ran. An exception would have been better: it screams. Here the
log calmly reports `wyslano 0`, which reads like information but is an incident report with the word
"incident" removed.

Note the asymmetry: `null` as the *whole* argument throws a loud `TypeError`, while `null` as a
*field inside* the object produces a silent zero-iteration loop. Same cause, opposite symptoms — and
the loud one is the better outcome.

## Quiz

1. **Replacing `const { proby = 3 } = opcje` with `const proby = opcje.proby ?? 3` — which log lines
   change?** Exactly one: `push-technik`, from `wyslano 0` to `wyslano 3` (verified: `3 / 1 / 3 / 3 / 3`).
   The rest are unchanged, because there `proby` was either `undefined` or a valid number. Note that
   `syrena-lokalna` still works, but *not* because of this fix — it is saved by `opcje = {}` in the
   signature, which was left untouched. Remove that thinking `??` covers it, and that line blows up.

2. **Does `opcje = {}` protect against `powiadom("test", null)`?** No. Verified: it throws
   `TypeError: Cannot read properties of null (reading 'proby')`. Same rule, one floor up — the
   default only fires for `undefined`, so `null` sails past it into the destructuring.

3. **Which strategy rejects `null`, which breaks a deliberate `proby: 0`, which rejects `"2"` from an
   API?** `= 3` lets `null` through (the bug). `?? 3` catches both emptiness markers and preserves a
   deliberate `0`. `|| 3` also catches `0`, so a channel configured "do not retry" suddenly retries
   three times — the only variant that corrupts valid data. `typeof === "number"` is the only one that
   also rejects the string `"2"` *and* preserves `0`. For config coming from a database or API, use
   the last one. The string is sneaky: `for (let i = 0; i < "2"; i++)` runs twice correctly, so the
   type bug surfaces only later, at `"10"` or at the first `+`.

## Card

**Front:** When does a `=` default value fire in JS (function parameter and destructuring)?

**Back:** Only when the value is exactly `undefined`. Never for `null`, `0` or `""`. It is not asking
"is this value sensible" — it is asking about one specific value. A field that is *missing* yields
`undefined` and the default fires; a field explicitly set to `null` (a NULL column, an empty field in
a JSON payload) walks past it. Same rule at every level: `function f(opcje = {})` also only guards
against `undefined`, so `f(null)` throws a `TypeError`. Worst symptom is in a loop:
`for (let i = 0; i < proby; i++)` with `proby = null` computes `0 < null` → `0 < 0` → false, so the
body never runs — a retry that never retries, while the `console.log` outside the loop still prints a
calm `wyslano 0`. Fixes by strength: `x ?? 3` (catches null and undefined, keeps a valid `0`);
`x || 3` (also eats `0`); `typeof x === "number" ? x : 3` (the only one that also rejects an API
string `"2"`).

## Takeaway

Code that throws an exception is asking for help. Code that silently runs a loop zero times is
reporting success. `wyslano 0` looks like information in a log; it is an incident report with the
word "incident" removed. When reading someone else's loop, do not ask what happens on later
iterations — ask first whether the *first* one fires at all, and check what the value to the right of
`<` actually is. This is the Level-1 readiness bar verbatim (retries, rate limits, dedupe): a retry
that does not retry looks exactly like a retry that was not needed.
