# S54 — Dates: two identical dates that are not equal (2026-08-22)

**Concept:** `Date` is an object, so `===` / `==` compare references, while `<` `>` `<=` `>=` and `-` coerce to a number of milliseconds, and `+` coerces to text.

**Story.** A warranty tracker fires "due today" twice for one ticket and never for another. Both dates print identically in the log, yet `if (termin === dzis)` never matches, and sorting the list by the text field puts December before September.

```js

const b = new Date("2026-08-22");
console.log("a === b                      ?", a === b);
console.log("a == b                       ?", a == b);

```

Extra checks, run separately: `new Set([a, b]).size` -> `2`; `Object.is(a, new Date("2026-08-22"))` -> `false`; `JSON.stringify({t: a})` -> `{"t":"2026-08-22T00:00:00.000Z"}` and after `JSON.parse` the field is a **string**, not a `Date`; `new Date("2026-13-01")` -> `Invalid Date`, `.getTime()` -> `NaN`, both `t < new Date()` and `t > new Date()` -> `false`, but `t == t` -> `true` (reference comparison never reaches the `NaN`); `new Date("2026-02-30")` silently rolls over to `2026-03-02`; `[new Date("2026-01-01"), new Date("2026-01-02")].sort()` returns them **reversed**, because the default sort stringifies and `"Fri" < "Thu"`.

## Quiz

1. `daty.sort()` without a comparator "worked" on a three-date sample. Why did it work, why is that not proof, and which two dates break it?
   **Key:** default sort stringifies; `String(Date)` starts with the weekday. `2026-01-01` (Thu) and `2026-01-02` (Fri) come out reversed. Correct: `sort((x, y) => x - y)` — subtraction reads the contents, not the address.
2. `const t = new Date("2026-13-01")` — what do `String(t)`, `t.getTime()`, `t < new Date()`, `t > new Date()` and `t == t` return?
   **Key:** `Invalid Date`; `NaN`; `false`; `false`; `true`. `==` on two objects compares references, so the `NaN` rule never applies. Only valid test: `!Number.isNaN(t.getTime())`.
3. How do you spot a field that is an object even though it logs like plain text?
   **Key:** it comes from `new` or a library factory, not a literal. `Date` (and dayjs/luxon/moment), `URL`, `Buffer`/`Uint8Array`. Same log, `===` says false.

## Card

**Front:** Why does `new Date("2026-08-22") === new Date("2026-08-22")` return `false` while `<=` and `>=` on the same two dates return `true`?

**Back:** `Date` is an object. `===` and `==` compare references (two boxes), relational and arithmetic operators coerce to the millisecond number (contents), `+` coerces to text. Compare with `getTime()`, sort with `(x, y) => x - y`, and remember that date strings only sort correctly in ISO `YYYY-MM-DD`.

**Puenta:** the same object answers by address, by contents, or by text depending on the operator. Reading someone else's code, do not ask what a field holds — ask what the operator takes from it.
