# S58 - ☎️ Centrala przychodni "Vita": Jeden brakujacy break i jeden cudzyslow z webhooka

**Concept:** Operatory i porownania — `switch` jako ukryte `===` plus fallthrough

> `switch` porownuje przez `===` (bez zadnej konwersji typu) i nie jest lancuchem galezi, tylko lista ETYKIET SKOKU — sterowanie wchodzi w miejscu dopasowania i leci w DOL, dopoki nie napotka `break`.

**Format:** `order-of-execution` | **Phase:** 1 | **Date:** 2026-08-27

## Scenario

A medical clinic runs an automated phone menu. The patient presses a digit: 1 is reception, 2 is test results, 3 is prescriptions, anything else goes to a human operator. The telephony provider posts the pressed key to a webhook and this function decides where the call goes next. Manual testing in the console passes. After deployment the receptionist reports two things that sound impossible at once: the operator queue is swamped even though the menu has three valid options, and some patients hear two announcements back to back.

## Round 1 — funkcja routujaca i to, co przychodzi z webhooka

```js
function trasuj(wybor) {
  const kroki = [];
  switch (wybor) {
    case 1:
      kroki.push("rejestracja");
      break;
    case 2:
      kroki.push("wyniki badan");
    case 3:
      kroki.push("recepty");
      break;
    default:
      kroki.push("operator");
  }
  return kroki;
}

console.log('1) trasuj(1)    ->', trasuj(1));
console.log('2) trasuj(2)    ->', trasuj(2));
console.log('3) trasuj(3)    ->', trasuj(3));
console.log('4) trasuj("2")  ->', trasuj("2"));
console.log('5) trasuj(9)    ->', trasuj(9));
console.log('6) "2" == 2     ->', "2" == 2);
console.log('7) "2" === 2    ->', "2" === 2);
```

## Round 2 — cztery konsekwencje `===` w srodku plus jedyny sposob na zakresy

```js
function trasuj2(w) {
  switch (w) {
    default:  return "operator";
    case 1:   return "rejestracja";
    case "1": return "rejestracja (tekst)";
  }
}
function czyNic(x)      { switch (x) { case NaN: return "TAK"; default: return "NIE"; } }
const wzorzec = { id: 7 };
function czyWzorzec(x)  { switch (x) { case wzorzec: return "TAK"; default: return "NIE"; } }
function zero(x)        { switch (x) { case 0: return "zero"; default: return "nie zero"; } }
function prog(min) {
  switch (true) {
    case min >= 60: return "pilne";
    case min >= 15: return "zwykle";
    default:        return "info";
  }
}
console.log('1) trasuj2(1)          ->', trasuj2(1));
console.log('2) trasuj2("1")        ->', trasuj2("1"));
console.log('3) trasuj2(true)       ->', trasuj2(true));
console.log('4) czyNic(NaN)         ->', czyNic(NaN));
console.log('5) czyWzorzec({id:7})  ->', czyWzorzec({ id: 7 }));
console.log('6) czyWzorzec(wzorzec) ->', czyWzorzec(wzorzec));
console.log('7) zero(-0)            ->', zero(-0));
console.log('8) prog(90/30/5)       ->', prog(90), prog(30), prog(5));
```

## Answer key

(a) Sterowanie SKACZE do `case 2`, wykonuje `push("wyniki badan")` i nie napotyka `break`, wiec leci w dol — a `case 3:` to zwykla ETYKIETA, ktora po wejsciu do bloku niczego nie sprawdza. Stad `push("recepty")` i dopiero tam `break`. Wynik `[ 'wyniki badan', 'recepty' ]` — dwie galezie z jednego wejscia, przeciwienstwo reguly c6. (b) `trasuj("2")` -> `[ 'operator' ]`, bo `switch` porownuje przez `===`, a `"2" === 2` to `false` (linia 7), mimo ze `"2" == 2` to `true` (linia 6); `default` jest galezia ZAPLANOWANA, wiec awaria nie daje ani jednego bledu w logu. (c) Silnik liczy `w` raz i przechodzi case'y w kolejnosci zapisu, POMIJAJAC `default`: `"1" === 1` -> false, `"1" === "1"` -> true, wejscie. `default` bralby udzial dopiero po nieudanym przejsciu calej listy, dlatego `default` w pierwszej linii dziala tak samo jak na koncu.

## Quiz

1. Ten sam webhook, ta sama cyfra: `if (klawisz == 2)` przepuszcza `"2"`, a `case 2:` nie. Ktory zapis wolisz miec w produkcji i dlaczego — a gdzie naprawde nalezy to naprawic, zeby odpowiedz przestala miec znaczenie?

   <details><summary>key</summary>

   `==` dziala, ale placisz cala tabela konwersji z S29/S42 (`0 == ""`, `0 == "0"`, ale `"" != "0"`) — przy trzech opcjach nie widac, przy dwudziestu zaczyna. `case` z `===` jest uczciwszy, bo glosno odmawia. Prawdziwa naprawa jest na WEJSCIU: payload webhooka przechodzi walidacje, ktora zamienia `klawisz` na liczbe albo odrzuca go jawnie — ta sama regula co `doMs(x)` z S56 i `normalize("NFC")` z S57: typ ustala sie raz, przy wejsciu.

   </details>

2. Brakujacy `break` w `case 2` daje dwa komunikaty. Dlaczego ten sam brak w OSTATNIM `case` przed `default` bylby gorszy, i dlaczego wersja z `return` nie da sie tak zepsuc?

   <details><summary>key</summary>

   Bo sterowanie wpadnie w `default`, czyli poprawnie rozpoznane wejscie dodatkowo wykona galaz "nic nie pasowalo" — jedyna, ktorej nikt nie testuje, bo z definicji jest "na wszelki wypadek". `return` wychodzi z calej FUNKCJI, nie tylko z bloku `switch`, wiec fallthrough jest niemozliwy — dlatego `switch` z `return` w kazdej galezi jest odporniejszy na czytanie i na edycje niz `push` + `break`.

   </details>

3. Ktos przepisuje `prog` na `switch (min)` z `case min >= 60:`. Z czym silnik porowna `min >= 60`, jaki bedzie wynik `prog(90)` i dlaczego test na jednej wartosci tego nie zlapie?

   <details><summary>key</summary>

   Porowna `min === (min >= 60)`, czyli liczbe z booleanem: `90 === true` -> `false`, `90 === false` -> `false`, wiec nic nie pasuje i funkcja zwraca `default`, czyli `"info"`. Test na jednej wartosci przechodzi, bo ta jedna wartosc czesto i tak trafia w galaz domyslna, a wynik jest poprawnym stringiem z listy, nie bledem. Jedyny dzialajacy uklad to `switch (true)` z warunkami w `case`.

   </details>

## Spaced-repetition card

**Front:** `switch` — ktorego operatora uzywa do dopasowania, i co dokladnie zatrzymuje wykonanie?

**Back:** Uzywa `===` (scisla rownosc, zero konwersji typu), a zatrzymuje go wylacznie `break` / `return` / koniec bloku. (1) `"2"` z webhooka NIE trafia w `case 2:` i cicho spada do `default` (`trasuj("2")` -> `[ 'operator' ]`, przy `"2" == 2` -> `true` i `"2" === 2` -> `false`); z tego samego `===`: `case NaN` nie zlapie `NaN` (S34), `case obiekt` porownuje referencje (S35), `case 0` lapie `-0` (S38). (2) `case` to ETYKIETA SKOKU, nie galaz — bez `break` sterowanie leci w dol, wiec `trasuj(2)` -> `[ 'wyniki badan', 'recepty' ]` przy `trasuj(3)` -> `[ 'recepty' ]`; odwrotnosc reguly c6. (3) `default` nie jest "else na koncu" — silnik najpierw przechodzi wszystkie `case`, wiec `default` w pierwszej linii dziala tak samo. (4) Zakresy tylko przez `switch (true)` z warunkami w `case` (`prog(90/30/5)` -> `pilne zwykle info`).

## Why it matters

Przez ostatnie dni pytanie brzmialo "czy ta wartosc jest tym, na co wyglada". Dzis pytanie sie przesuwa: nie o wartosc, tylko o to, GDZIE KOD SIE ZATRZYMUJE. Dla kogos, kto spina webhooki telefonii, formularzy i IVR-ow, `switch` jest miejscem, gdzie obie te rzeczy pekaja naraz — typ wchodzi jako string, a brak jednego `break` nie jest bledem skladni, wiec nikt go nie zglosi. Na rozmowie o Poziom 1 ("error handling, retries, dedupe") to jest dokladnie ta klasa pytan: nie "co robi ten kod", tylko "co ten kod robi z wejsciem, ktorego autor sie nie spodziewal".
