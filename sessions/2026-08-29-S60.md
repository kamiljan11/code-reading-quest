# S60 - ♟ planszowka online "Kamienny Most": Trzy guardy zwracaja false, a bledu nie ma w zadnym z nich

**Concept:** Operatory i porownania — JSON.parse/JSON.stringify jako konwersja stratna na granicy systemu

> JSON.stringify + JSON.parse to nie zapis i odczyt tej samej rzeczy, tylko konwersja STRATNA: w obiekcie znikaja cale klucze o wartosci undefined (a takze funkcje i symbole), w tablicy te same wartosci staja sie null, NaN/Infinity/-Infinity staja sie null, Date wraca jako string, Set i Map jako puste {}, -0 jako 0, a klasa jako goly obiekt bez metod. Glosno rzuca tylko cykl i BigInt.

**Format:** `find-bug` | **Phase:** 1 | **Date:** 2026-08-29

## Scenario

An online board game keeps the whole match state in one jsonb column. Saving goes through JSON.stringify, loading through JSON.parse. It has worked for six months and nobody has touched it. Then a player writes in: "I refreshed the page and the game started me from zero. I had 120 points and unlimited time." The resume function has three guards, all of them look correct, and all three return false.

## Answer key

Przyczyna jest linia A, a nie B, C ani D. JSON.parse oddaje obiekt, ktory tylko WYGLADA jak zapisany stan. B zwraca false, bo Infinity zapisalo sie jako null, a null === Infinity to false. C zwraca false, bo s.ostatniRuch jest teraz STRINGIEM, a nie Date — porownanie stringa z liczba idzie przez Number("2026-08-29T10:00:00.000Z") -> NaN, wiec > i < sa OBA false naraz (powrot S34/S47/S56). D zwraca false, bo Set wrocil jako {}, wiec .size to undefined, a undefined > 0 to false (powrot S47). Trzy guardy, trzy rozne mechanizmy, jeden wspolny powod. Naprawa pojedynczego guardu NIE zalatwia sprawy — zamieni jeden cichy false na jeden poprawny odczyt i zostawi dwa pozostale. Naprawa nalezy do linii A: reviver w JSON.parse albo jawna funkcja zdeserializujStan(), ktora odtwarza Date, Set i Infinity. Do (c): s.odwiedzone.has("most") rzuca TypeError: s.odwiedzone.has is not a function i ta wersja jest TANSZA — size > 0 zwraca ciche false, gracz traci postep, a w logach nie ma niczego.

## Quiz

1. Pole bonus: undefined znika z obiektu, ale tury: [1, undefined, 3] wraca jako [1, null, 3] — ta sama wartosc, dwa rozne losy. Dlaczego JSON nie moze potraktowac obu tak samo i co by sie stalo z indeksami w tablicy, gdyby probowal?

   <details><summary>key</summary>

   W OBIEKCIE klucz jest nazwany, wiec da sie go pominac i struktura zostaje spojna ({"x":undefined} -> {}). W TABLICY pozycja elementu JEST jego kluczem: gdyby undefined zniknelo, [1, undefined, 3] stalo by sie [1, 3] i 3 przejechaloby z indeksu 2 na 1, czyli ciche przesuniecie calej reszty. JSON nie ma zapisu na "dziura tutaj", wiec wstawia null i zachowuje dlugosc oraz indeksy. Zweryfikowane: JSON.stringify([1, undefined, 3]) -> [1,null,3], JSON.stringify({x: undefined}) -> {}. Ta sama regula dotyczy funkcji i symboli.

   </details>

2. JSON.parse(JSON.stringify(x)) jest najczestsza rada na gleboka kopie obiektu (padla w S35 i S40). Wymien trzy typy z dzisiejszego stanu gry, dla ktorych ta rada daje zla kopie, i powiedz przy kazdym, czy blad bedzie GLOSNY czy CICHY.

   <details><summary>key</summary>

   Date (ostatniRuch): kopia jest STRINGIEM, blad CICHY dopoki ktos nie wywola metody. Set/Map (odwiedzone): kopia to puste {}, blad CICHY i najgorszy, bo danych po prostu nie ma. NaN/Infinity (srednia, limitCzasu): kopia to null, blad CICHY, a null jeszcze przechodzi przez porownania relacyjne jako 0 (S47). Do kompletu dwa GLOSNE: cykl w strukturze i BigInt — obydwa rzucaja TypeError. Wniosek: jedyne dwa przypadki obslugiwane glosno to te, ktorych prawie nigdy nie masz. Poprawna wersja to structuredClone().

   </details>

3. Payload {"gracz":"Mallory","__proto__":{"admin":true}} przechodzi przez JSON.parse niegroznie, przez {...payload} tez, a przez Object.assign(cel, payload) juz nie. Na czym polega roznica i dlaczego to ten sam ksztalt reguly co ?. w S49 i typeof w S50?

   <details><summary>key</summary>

   Spread uzywa definicji wlasnosci (CreateDataProperty) — tworzy zwykle wlasne pole o nazwie __proto__ i zaden setter sie nie odpala (profil2.admin -> undefined, Object.keys(profil2) -> [ 'gracz', '__proto__' ]). Object.assign uzywa przypisania ([[Set]]), a __proto__ to akcesor odziedziczony po Object.prototype, wiec przypisanie PODMIENIA prototyp celu: profil.admin -> true przy Object.keys(profil).length -> 1. To podmiana prototypu JEDNEGO obiektu, nie zatrucie globalne — ({}).admin nadal undefined. Ten sam ksztalt reguly co ?. i typeof: ochrona/zachowanie dotyczy jednego konkretnego miejsca skladni, nie calej operacji.

   </details>

## Spaced-repetition card

**Front:** Co gubi JSON.parse(JSON.stringify(x)) i ktore z tych strat sa ciche?

**Back:** To konwersja STRATNA, nie kopia. W OBIEKCIE znikaja cale klucze o wartosci undefined, funkcje i symbole; w TABLICY te same wartosci staja sie null, zeby nie przesunac indeksow (JSON.stringify([1,undefined,3]) -> [1,null,3], JSON.stringify({x:undefined}) -> {}). Na null podmieniane sa tez NaN, Infinity i -Infinity. Date wraca jako STRING, Set i Map jako puste {}, -0 jako 0, klasa jako goly obiekt bez metod. Glosno rzuca tylko cykl (TypeError: Converting circular structure to JSON) i BigInt — czyli dwa przypadki, ktorych prawie nigdy nie masz. Skutek: guard s.limitCzasu === Infinity -> false (bo null), s.ostatniRuch > Date.now()-86400000 -> false I < tez false (string przez Number() -> NaN), s.odwiedzone.size > 0 -> false (bo {}) — trzy guardy padaja naraz, a przyczyna jest jedna linia wyzej. Przy wczytywaniu: duplikat klucza wygrywa OSTATNI bez bledu, klucze calkowitoliczbowe wychodza PIERWSZE i rosnaco, a __proto__ jest niegrozny dla JSON.parse i spreadu, ale Object.assign puszcza go przez setter. Naprawa: structuredClone() do kopii, reviver albo jawna zdeserializuj() na granicy systemu.

## Why it matters

S56 to S59 all said the same thing from four angles: normalise at the boundary. S60 is the first one where the symptom appears in three places at once and none of them is the bug. Every integrator who reads a payload from someone else API or a state blob from a jsonb column hits this weekly: JSON.parse hands back an object that only looks like what was saved, and the guards downstream fail one by one for three unrelated-looking reasons. Reading code in a real job is not about finding the line that returns the wrong thing. It is about walking back to the line where the data stopped being itself.
