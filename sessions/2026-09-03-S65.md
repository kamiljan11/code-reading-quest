# S65 — Jeden refaktor, trzy rozne konce

**Data:** 2026-09-03  
**Faza:** 1 — Alfabet czytania  
**Koncept:** Funkcje - `this` nie nalezy do funkcji, tylko do WYWOLANIA  
**Format:** `predict-output`  
**Motyw:** 🚲 Serwis rowerowy "Kedja" w Reykjaviku - jeden refaktor na trzech modulach

## Koncept

O wartosci `this` NIE decyduje miejsce, w ktorym funkcja zostala NAPISANA - decyduje wylacznie SPOSOB, w jaki zostala WYWOLANA, czyli to, czy w chwili wywolania po LEWEJ stronie kropki stoi jakikolwiek obiekt. `obiekt.metoda()` daje `this === obiekt`; `goleWywolanie()` nie daje nic i silnik podstawia zastepstwo: `globalThis` w trybie sloppy, `undefined` w strict (moduly ESM i KAZDE cialo klasy). Funkcja pozostaje przy tym bit w bit ta sama, wiec naprawy szuka sie w miejscu WYWOLANIA, nigdy w definicji.

## Fabula

Serwis rowerowy "Kedja" w Reykjaviku. Po zamknieciu naprawy zlecenie idzie przez trzy niezalezne moduly: kolejke wydan, statystyki dnia i audyt. Wszystkie trzy dzialaly poprawnie od pol roku. W poniedzialek nowy programista zrobil porzadki: zauwazyl, ze w trzech miejscach stoi `z => obiekt.metoda(z)`, i skrocil to do `obiekt.metoda`, bo "to jest dokladnie to samo, tylko krocej". Review przeszlo w cztery minuty. Trzy obiekty wygladaja identycznie, dostaly identyczna zmiane — i skonczyly na trzy rozne sposoby, przy czym najgorszy z nich nie zostawil w logu ani jednej linii.

## Starcie 2 - serwis rowerowy "Kedja": jeden refaktor, trzy rozne konce

```js
// STARCIE 2 - serwis rowerowy "Kedja": jeden refaktor, trzy rozne konce (plik .js, node, tryb sloppy)
const kolejka = {
  nazwa: "Kedja",
  pozycje: [],
  dodaj(z) { this.pozycje.push(z.id); return this.pozycje.length; }
};

const statystyki = {
  przyjete: 0,
  odrzucone: 0,
  zlicz(z) {
    if (z.telefon) { this.przyjete = this.przyjete + 1; }
    else { this.odrzucone = this.odrzucone + 1; }
    return this.przyjete;
  }
};

class Audyt {
  constructor() { this.wpisy = 0; }
  zapisz(z) { this.wpisy = this.wpisy + 1; return this.wpisy; }
}
const audyt = new Audyt();

const zlecenia = [
  { id: "R-1", telefon: "8990001" },
  { id: "R-2", telefon: null },
  { id: "R-3", telefon: "8990003" }
];

function zeruj() { kolejka.pozycje = []; statystyki.przyjete = 0; statystyki.odrzucone = 0; audyt.wpisy = 0; }

// A) wersja SPRZED refaktoru - kazde wywolanie stoi po kropce
zlecenia.forEach(z => kolejka.dodaj(z));
zlecenia.forEach(z => statystyki.zlicz(z));
zlecenia.forEach(z => audyt.zapisz(z));
console.log("1)", kolejka.pozycje.length, statystyki.przyjete, statystyki.odrzucone, audyt.wpisy);

// B) wersja PO refaktorze - "krotsze, to samo"
zeruj();
try { zlecenia.forEach(statystyki.zlicz); console.log("2) statystyki: bez wyjatku"); }
catch (e) { console.log("2) statystyki:", e.constructor.name + ":", e.message); }
console.log("3)", statystyki.przyjete, statystyki.odrzucone);
console.log("4)", globalThis.przyjete, globalThis.odrzucone);

try { zlecenia.forEach(kolejka.dodaj); console.log("5) kolejka: bez wyjatku"); }
catch (e) { console.log("5) kolejka:", e.constructor.name + ":", e.message); }
console.log("6)", kolejka.pozycje.length);

try { zlecenia.forEach(audyt.zapisz); console.log("7) audyt: bez wyjatku"); }
catch (e) { console.log("7) audyt:", e.constructor.name + ":", e.message); }
console.log("8)", audyt.wpisy);

// C) trzy rozne naprawy tego samego bledu
zeruj();
zlecenia.forEach(statystyki.zlicz, statystyki);
zlecenia.forEach(kolejka.dodaj.bind(kolejka));
zlecenia.forEach(z => audyt.zapisz(z));
console.log("9)", statystyki.przyjete, statystyki.odrzucone, kolejka.pozycje.length, audyt.wpisy);

// D) drugi argument nie wszedzie znaczy to samo
zeruj();
try { console.log("10) reduce:", zlecenia.reduce(statystyki.zlicz, statystyki), statystyki.przyjete); }
catch (e) { console.log("10) reduce:", e.constructor.name + ":", e.message); }

zeruj();
console.log("11) map:", zlecenia.map(kolejka.dodaj, kolejka), kolejka.pozycje.length);

zeruj();
const oderwana = kolejka.dodaj;
console.log("12)", typeof oderwana, oderwana === kolejka.dodaj, kolejka.dodaj.name);
```

## Klucz

Trzy zakonczenia, trzy rozne przyczyny, i tylko jedno z nich jest widoczne. `statystyki.zlicz` NIE RZUCA, bo w trybie sloppy `this` zsuwa sie na `globalThis`, a `globalThis.przyjete` przy pierwszym zapisie jest `undefined` - `undefined + 1` to `NaN`, dzialanie LEGALNE, nie blad. Powstaja dwie nowe globalne, obiekt `statystyki` nie jest dotkniety ani razu (`3)` -> `0 0`, `4)` -> `NaN NaN`), a raport dnia pokazuje zero przyjec przy trzech obsluzonych zleceniach. `kolejka.dodaj` rzuca, bo pierwsza rzecza, ktora robi, jest ODCZYT `this.pozycje`: `TypeError: Cannot read properties of undefined (reading 'push')`. `audyt.zapisz` ma cialo ZNAK W ZNAK takie samo jak `statystyki.zlicz`, a mimo to rzuca - `TypeError: Cannot read properties of undefined (reading 'wpisy')` - bo cialo klasy jest ZAWSZE w trybie strict, wiec `this` zostaje `undefined` i nie ma na czym wykonac zapisu. NAJDROZSZE jest pierwsze: dwa wyjatki wpadaja do monitoringu tego samego dnia, a ciche `0` w statystykach wyglada jak spokojny dzien i moze przezyc cala serie raportow miesiecznych. `"use strict"` zamienia wersje cicha w glosna i nie rusza tej, ktora juz krzyczala: linia `2)` staje sie `TypeError: ... (reading 'przyjete')`, `4)` z `NaN NaN` na `undefined undefined`, `5)` zmienia KOMUNIKAT z `(reading 'push')` na `(reading 'pozycje')`, `10)` z `NaN 0` na `TypeError: ... (reading 'odrzucone')`; bez zmian `1)`, `3)`, `6)`, `7)`, `8)`, `9)`, `11)` i `12)` - w tym `7)`, czyli klasa. W Starciu 1 zmiana konczy program: `1)` wypisuje sie normalnie, a `2)` rzuca `TypeError: ... (reading 'suma')` i przerywa plik.

## Quiz

1. `const f = obiekt.metoda;` - po tej linii `f === obiekt.metoda` daje `true`, a `f.name` jest takie samo jak przed. Co wobec tego "zgubilo sie" przy przypisaniu, skoro funkcja jest ta sama, i gdzie nalezy szukac naprawy - w definicji metody czy gdzie indziej?
   - **Klucz:** Zgubila sie nie funkcja, tylko KROPKA - czyli informacja o tym, na czym ta funkcja ma pracowac. `this` nie jest czescia funkcji, tylko czescia WYWOLANIA, wiec przypisanie do zmiennej nie kopiuje niczego mniej; ono po prostu przygotowuje wywolanie, w ktorym nie bedzie zadnego obiektu po lewej stronie. Naprawy szuka sie W MIEJSCU WYWOLANIA, nigdy w definicji metody.
2. Trzy sposoby na to samo: `forEach(obj.m, obj)`, `forEach(obj.m.bind(obj))` i `forEach(x => obj.m(x))`. Powiedz dla kazdego, DLACZEGO dziala (mechanizm, nie efekt), i wskaz ten jeden, ktorego NIE da sie uzyc przy `reduce` - z uzasadnieniem, co sie stanie, jesli ktos sprobuje.
   - **Klucz:** `forEach(obj.m, obj)` dziala, bo `forEach` przyjmuje DRUGI ARGUMENT `thisArg` i sam wykonuje wywolanie z podstawionym kontekstem. `obj.m.bind(obj)` dziala, bo `bind` tworzy NOWA funkcje z na stale doklejonym `this` (jednorazowo i nieodwracalnie). `x => obj.m(x)` dziala, bo w srodku strzalki stoi normalne wywolanie PO KROPCE - zadnej magii z `this` tam nie ma. Przy `reduce` nie da sie uzyc pierwszego: `reduce` nie ma parametru `thisArg`, jego drugi argument to WARTOSC POCZATKOWA akumulatora, wiec `reduce(obj.m, obj)` nie zglosi bledu, tylko wstawi caly obiekt jako pierwszy akumulator i policzy bzdure - zweryfikowane: zwraca `NaN`, a licznik zostaje `0`.
3. Dwa obiekty maja metode o identycznym ciele: `licz(z) { this.n = this.n + 1 }`. Pierwszy powstal jako `const a = { n: 0, licz(z) {...} }`, drugi jako `class B { constructor() { this.n = 0 } licz(z) {...} }`. Oba trafiaja do `forEach(obiekt.licz)`. Co zrobi kazdy, dlaczego roznica w ogole istnieje i ktora sytuacja jest dla firmy TANSZA?
   - **Klucz:** Obiekt literalny MILCZY (`this` zsuwa sie na `globalThis`, powstaje globalna `n` o wartosci `NaN`, oryginal nietkniety), klasa RZUCA `TypeError: Cannot read properties of undefined (reading 'n')`. Roznica istnieje, bo CIALO KLASY JEST Z DEFINICJI JEZYKA ZAWSZE W TRYBIE STRICT, niezaleznie od tego, jak plik zostal uruchomiony. Tansza dla firmy jest KLASA: wyjatek zatrzymuje przetwarzanie w linii przyczyny i trafia do monitoringu tego samego dnia, a ciche `NaN` na globalnej zmiennej leci dalej i ujawnia sie dopiero w raporcie, ktorego nikt nie porownuje z rzeczywistoscia.

## Karta do powtorek (SM-2)

**Front:** Od czego zalezy `this` wewnatrz funkcji w JS?

**Back:** NIE od miejsca, w ktorym funkcja zostala NAPISANA, tylko od SPOSOBU, w jaki zostala WYWOLANA. Jedno pytanie przy czytaniu: czy w chwili wywolania po LEWEJ stronie kropki stoi jakis obiekt? `obiekt.metoda()` -> `this === obiekt`. `goleWywolanie()` -> nie stoi nic, wiec silnik podstawia `globalThis` (sloppy) albo zostawia `undefined` (strict, ESM i KAZDE cialo klasy). Funkcja nie zmienia sie ani o bit: `const f = obj.m` daje `f === obj.m` -> `true` i `f.name` bez zmian - gubi sie KROPKA, nie funkcja, wiec naprawy szuka sie w miejscu WYWOLANIA. `forEach(obj.m)` jest golym wywolaniem; trzy naprawy: `forEach(obj.m, obj)` (`thisArg`), `obj.m.bind(obj)` (nowa funkcja, jednorazowo i nieodwracalnie) albo `x => obj.m(x)`. `thisArg` maja `forEach`/`map`/`filter`/`some`/`every`/`find`/`flatMap`, ale NIE `reduce` - tam drugi argument to wartosc poczatkowa, wiec `reduce(obj.m, obj)` nie rzuca, tylko liczy bzdure. STRZALKA nie ma wlasnego `this` i bierze go leksykalnie: ratuje wewnatrz metody, ale postawiona JAKO metoda bierze `this` z gory pliku (w CommonJS `module.exports`, czyli `{}`). Najwazniejsze: ten sam blad przy obiekcie LITERALNYM MILCZY (`NaN` na `globalThis`), a przy METODZIE KLASY RZUCA `TypeError` - bo cialo klasy jest zawsze strict. W Node callback `setTimeout` dostaje jako `this` obiekt `Timeout`.

## Puenta

Trzy moduly, jedna zmiana, trzy rozne konce - i jedyny, ktory nie zostawil sladu, jest tym, ktory kosztuje. To nie jest lekcja o `this`. To jest lekcja o tym, ze przy czytaniu cudzego kodu odruch "zajrze do definicji funkcji" jest tu z definicji bezowocny, bo definicja jest poprawna. Roznica siedzi w linii wywolania, ktora ma cztery znaki mniej niz przed refaktorem i przeszla review w cztery minuty.
