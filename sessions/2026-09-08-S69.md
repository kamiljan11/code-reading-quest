# S69 — Objects: spread merge overwrites by KEY, not by value (2026-09-08)

**Concept:** `{ ...defaults, ...patch }` overwrites by KEY, not by value. Whether a default survives depends on whether the key EXISTS in the patch — not on what value it holds. And the merge is SHALLOW, so a nested object is replaced wholesale, not merged.

**Scene:** 🏨 Guesthouse "Gistihús Vík". The owner calls with one sentence: *"the system says we have too many guests, and it's two people."* Nothing throws. Nothing in the logs.

**Format:** BUG-HUNT

## Snippet 1 — the mechanics

```js
const domyslne = { limit: 10, waluta: "ISK", retry: { proby: 3, backoff: 500 }, aktywny: true };
const zModelu  = { limit: undefined, waluta: null, retry: { proby: 5 } };

const scalone = { ...domyslne, ...zModelu };

console.log("1)", scalone.limit);
console.log("2)", scalone.waluta);
console.log("3)", JSON.stringify(scalone.retry));
console.log("4)", "limit" in scalone, Object.keys(scalone).length);
console.log("5)", scalone.retry.backoff);
console.log("6)", Object.keys(scalone).join(","));

const przezAssign = Object.assign({}, domyslne, zModelu);
console.log("7)", przezAssign.limit, JSON.stringify(przezAssign.retry));

const tylkoWaluta = { waluta: "EUR" };
console.log("8)", { ...domyslne, ...tylkoWaluta }.limit);

console.log("9)", scalone.limit ?? 10, scalone.waluta ?? "ISK");
console.log("10)", JSON.stringify(domyslne.retry));
```

## Snippet 2 — the night agent merges defaults with the model's structured output

```js
const DOMYSLNE = {
  maxGosci: 4,
  minNocy: 2,
  waluta: "ISK",
  powiadomienia: { email: true, sms: false, webhook: "https://gistihus.is/hook" },
  autoPotwierdzenie: true,
};

// arrived from the model as structured output, went through JSON.parse
const PATCH = JSON.parse(
  '{"maxGosci": null, "minNocy": 1, "powiadomienia": {"sms": true}}'
);

function zbudujKonfig(domyslne, patch) {
  return { ...domyslne, ...patch };
}

const konfig = zbudujKonfig(DOMYSLNE, PATCH);

function przyjmij(rez) {
  if (rez.gosci > konfig.maxGosci) return "ODRZUCONA: za duzo gosci";
  if (rez.nocy < konfig.minNocy) return "ODRZUCONA: za krotki pobyt";
  const kanaly = [];
  if (konfig.powiadomienia.email) kanaly.push("email");
  if (konfig.powiadomienia.sms) kanaly.push("sms");
  if (konfig.powiadomienia.webhook) kanaly.push("webhook");
  return `PRZYJETA (${rez.gosci} os., ${rez.nocy} nocy) -> ${kanaly.join("+") || "BRAK KANALU"}`;
}

console.log("A)", konfig.maxGosci, konfig.minNocy);
console.log("B)", JSON.stringify(konfig.powiadomienia));
console.log("C)", Object.keys(konfig).length, "maxGosci" in konfig);
console.log("D)", przyjmij({ gosci: 9, nocy: 3 }));
console.log("E)", przyjmij({ gosci: 2, nocy: 1 }));
console.log("F)", konfig.powiadomienia === DOMYSLNE.powiadomienia);
console.log("G)", JSON.stringify(DOMYSLNE.powiadomienia));
```

## Verified

Run with node v24.13.1.

```text
1) undefined
2) null
3) {"proby":5}
4) true 4
5) undefined
6) limit,waluta,retry,aktywny
7) undefined {"proby":5}
8) 10
9) 10 ISK
10) {"proby":3,"backoff":500}
```

```text
A) null 1
B) {"sms":true}
C) 5 true
D) ODRZUCONA: za duzo gosci
E) ODRZUCONA: za duzo gosci
F) false
G) {"email":true,"sms":false,"webhook":"https://gistihus.is/hook"}
```

**The bug:** `return { ...domyslne, ...patch };` inside `zbudujKonfig`. The patch DID supply the `maxGosci` key — just with `null`. Spread therefore overwrote the default `4`. The key still exists (`"maxGosci" in konfig` → `true`), the key count still matches (`5`), the value is gone. Then `rez.gosci > konfig.maxGosci` is `2 > null`, which coerces to `2 > 0` → `true`, so **every** booking with at least one guest fails the first guard with a plausible-sounding message. Second, quieter effect of the same line: `powiadomienia` ends up with one field instead of three, so even an accepted booking would go out by SMS only. The original `DOMYSLNE` is untouched (`F)` → `false`), which makes the diagnosis harder: anyone opening the defaults sees a correct config.

## Quiz

1. Given `const cfg = { retry: 3 }` and patch `{ retry: undefined }` — does `retry` exist after `{ ...cfg, ...patch }`, and what is its value? How does that differ from `const { retry = 3 } = patch`?
   **Key:** The key EXISTS with value `undefined` — spread copies the key along with the empty value. Destructuring with a default does the opposite: `undefined` TRIGGERS the default and you get `3`. Same value, opposite outcome.

2. Defaults have `powiadomienia: { email: true, sms: false }`, patch has `powiadomienia: { sms: true }`. How many fields does `powiadomienia` have after a spread merge, and why?
   **Key:** One — `{"sms":true}`. Spread merges only the top level, so a nested object is replaced wholesale, not merged. `email` is gone even though the patch never mentioned it.

3. Does `Object.assign({}, defaults, patch)` behave differently from `{ ...defaults, ...patch }` when the patch contains `undefined`?
   **Key:** No — identical (verified: `7)` → `undefined {"proby":5}`). The difference lies elsewhere: `Object.assign` assigns through SETTERS (hence its `__proto__` exposure), spread defines properties directly.

## Card (SM-2)

**Front:** What decides whether a default survives `{ ...defaults, ...patch }`?
**Back:** Only whether the key EXISTS in the patch — the value is irrelevant. `{ limit: undefined }` and `{ limit: null }` both ERASE the default (key present, value empty); a missing key leaves it alone. This is the opposite of destructuring defaults, where `undefined` TRIGGERS the default. Spread merges shallowly, so a nested object is REPLACED wholesale, not merged.

## Why this matters

Every pipeline that merges a model's response into a default config — which is exactly what structured output does in n8n, in an agent, and in any integration — rests on this one line. A model that "didn't know" and filled a field with `null` leaves no error to catch: it leaves a correct-looking config that quietly rejects every customer. In job ads this skill hides under "structured outputs / data validation".
