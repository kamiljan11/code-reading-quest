# S73 — The trust boundary between two languages (2026-09-15)

**Concept:** `fetch` does not throw on 4xx/5xx, and `NaN` loses every comparison — so a failed upstream call silently falls through to the most permissive branch of an `if/else` chain.

**Story:** "Straumur Score", a small Reykjavik fintech. The scoring model runs in Python (FastAPI), the rest of the system runs in Node. Between them, one line: `await res.json()`. An AI-generated handler shipped on Friday, described as "scoring service integration + decision handling, ready". It passed review. On Saturday the scoring service was down for two hours and returned `500`. On Monday risk asks: *"why did eight applications get auto-approved on Saturday, and why does the nightly report say we processed ZERO applications?"*

## Snippet 1 — eight traps on a single JSON response

```js
const raw = '{"id": 9007199254740993, "score": 0, "prog": "0", "pewnosc": "0.94 (kalibrowane)", "cechy": [10, 9, 100, 2]}';
const r = JSON.parse(raw);

console.log('1)', r.id, '|', r.id === 9007199254740992);
console.log('2)', r.score || 50, '|', r.score ?? 50);
console.log('3)', r.prog == r.score, '|', r.prog === r.score);
console.log('4)', parseInt(r.pewnosc), '|', Number(r.pewnosc), '|', Number(""));
console.log('5)', r.cechy.sort(), '|', 'oryginal:', r.cechy);
console.log('6)', r.cechy.indexOf(NaN), '|', r.cechy.includes(NaN), '|', [NaN].includes(NaN));
const licznik = { [r.score]: "z liczby", ["0"]: "z tekstu" };
console.log('7)', licznik, '|', Object.keys(licznik).length);

```

## Snippet 2 — the AI-generated handler

Scoring service: `200` for id=1 (`score: 940`), `500` with body `{"error": "model unavailable"}` for id=2, `200` for id=3 with `score` as the string `"820 pkt"`.

```js
async function pobierzScore(idKlienta) {
  const res = await fetch(`http://scoring.local/score/${idKlienta}`);
  const body = await res.json();
  return body;
}

const PROGI = [900, 700, 500];

function decyzja(score) {
  if (score >= 500) return "manual";
  if (score >= 700) return "odrzuc";
  if (score >= 900) return "blokada";
  return "auto-akcept";
}

async function obsluz(wnioski) {
  const wyniki = [];
  wnioski.forEach(async (w) => {
    try {
      const b = await pobierzScore(w.id);
      const score = parseInt(b.score);
      wyniki.push({ id: w.id, decyzja: decyzja(score) });
    } catch (e) {
      wyniki.push({ id: w.id, decyzja: "blad" });
    }
  });
  console.log('A)', wyniki.length, JSON.stringify(wyniki));
  return wyniki;
}

(async () => {
  const zwrot = await obsluz([{ id: 1 }, { id: 2 }, { id: 3 }]);
  console.log('B)', JSON.stringify(zwrot));
  await new Promise(r => setTimeout(r, 50));
  console.log('C)', JSON.stringify(zwrot));
})();
```

## The four bugs

1. **`forEach(async ...)` awaits nothing.** `forEach` discards the returned promise, so `obsluz` reaches its `return` with `wyniki` still empty. The caller logs "processed 0 applications" while three decisions land in that same array milliseconds later. Fix: `for...of` with `await`, or `await Promise.all(wnioski.map(...))`.
2. **No `res.ok` check.** `fetch` does not reject on HTTP `500` — it hands back a perfectly normal response, so `body` is `{ error: "model unavailable" }` and `b.score` is `undefined`. The neighbouring `try/catch` never fires, because nothing was thrown.
3. **`NaN` falls through to the default branch.** `parseInt(undefined)` is `NaN`, and `NaN >= 500`, `NaN >= 700`, `NaN >= 900` are all `false` — as is `NaN < 500`. The chain selects nothing and control reaches the final `return "auto-akcept"`. An upstream outage becomes an automatic credit approval.
4. **Thresholds in reverse order.** `>= 500` comes first, so `700` and `900` are dead code: a score of `940` is labelled `manual` instead of `blokada`. The unused `PROGI = [900, 700, 500]` constant sits in the file looking like someone remembered the ordering — nobody checked whether it was wired in anywhere.

Separately, on the boundary itself: `JSON.parse` silently truncates integers above `Number.MAX_SAFE_INTEGER`. Python's `int` has no upper bound, JS has 53 bits of mantissa, and nothing reports the loss — the only trace left is in the original response text. The fix belongs in the API contract, not the code: identifiers longer than 15 digits cross the boundary as strings.

## Quiz

1. **`fetch` doesn't throw on HTTP 500. Name three places in this handler where a check could go, and what the caller sees for each: a loud error, a silent fallback, or a retry.** — `if (!res.ok) throw` inside `pobierzScore` gives a loud error the existing `catch` turns into `decyzja: "blad"`. Validating `typeof b.score !== "number"` after `res.json()` gives a loud error while the data is still readable. `if (!res.ok) return { score: null }` gives a silent fallback and reintroduces the same bug, because `null` becomes `NaN` via `parseInt`. Retry only for `5xx` and `429`, with an attempt limit and backoff.
2. **Python returns `id` as an unbounded `int`, JS has 53 bits of mantissa. How do you even notice this in Node, given `JSON.parse` reports nothing?** — The loss happens during conversion to `Number`, not during parsing, so the only evidence is the original text: compare `String(obj.id)` against what came over the wire, or read such fields through a reviver with `ctx.source` (Node 22+), or use `BigInt`.
3. **`parseInt(x)`, `Number(x)`, `+x` and `Math.round(x)` for `"820 pkt"`, `""`, `null` and `undefined` — write the 4x4 table. Which never returns `NaN` for `null`, and which always returns `NaN` for `undefined`?** — `parseInt` -> 820, NaN, NaN, NaN. `Number` -> NaN, 0, 0, NaN. `+x` -> NaN, 0, 0, NaN. `Math.round` -> NaN, 0, 0, NaN. For `null`, the last three all return `0` — missing data quietly becomes zero. For `undefined`, all four return `NaN`.

## Spaced-repetition card

**Front:** An HTTP service returned `500` with a JSON body. What does `fetch` do, and what does the code below it see?

**Back:** `fetch` does NOT throw — it rejects only on network/DNS failure. The HTTP status must be read from `res.ok` or `res.status`. Without that, `await res.json()` cheerfully returns the ERROR BODY as data, `body.field` is `undefined`, `parseInt(undefined)` is `NaN`, and `NaN` loses EVERY comparison (`>=`, `>`, `<`) — so control falls to the last, most permissive branch of the `if/else` chain. Rule: at every `fetch` in someone else's code, look for `res.ok`; if it isn't there, find out which branch is the default one.

## Takeaway

Every one of the four defects is a defect of the *boundary*, not of either language. The handler that turns a service outage into an automatic credit approval does not contain a single syntax error.
