# S74 — Validating structured output from an LLM (2026-09-16)

**Concept:** an LLM response is *text that pretends to be data*. A validator written with `typeof`
and truthiness does the opposite of its name: it lets `null` and a wrong scale through, and throws
away a correct answer that arrived wrapped in a code fence.

**Story:** "Verkbeidni", a small service-ticket system in Reykjavik. A model reads the customer's
description and returns JSON: `priorytet` 0-4, `pewnosc`, `tagi`. An assistant-generated function
("schema validation + queue routing, done") passed review. On Monday the coordinator asks why a
ticket about a flooded apartment has been sitting in the normal queue for three days, why one
ticket vanished, and why the night worker crashed on `null` that the validator had approved.

## Round 1 — eight Phase 1 traps on one model response

```js
const odp = '```json\n{"priorytet": "0", "pewnosc": 0.9, "tagi": ["pilne","hydraulika"], "koszt": "12 500 ISK", "eta": null}\n```';

console.log('1)', odp.startsWith('{'), '|', odp.trim().startsWith('{'));
const czysty = odp.replace('```json', '').replace('```', '').trim();
const m = JSON.parse(czysty);
console.log('2)', typeof m.priorytet, '|', m.priorytet == 0, '|', m.priorytet === 0);
console.log('3)', Number(m.koszt), '|', parseInt(m.koszt), '|', parseFloat(m.koszt));
console.log('4)', m.eta ?? 'brak', '|', m.eta || 'brak', '|', m.eta?.dlugosc);
console.log('5)', m.tagi.includes('Pilne'), '|', m.tagi.join() === 'pilne,hydraulika');
console.log('6)', m.pewnosc * 3 === 2.7, '|', 0.1 + 0.2 === 0.3, '|', m.pewnosc * 100 === 90);
const licz = {};
m.tagi.forEach(t => licz[t] = (licz[t] || 0) + 1);
licz[m.priorytet] = "prio";
console.log('7)', JSON.stringify(licz), '|', Object.keys(licz)[0]);
console.log('8)', [m.priorytet, 1, 2].sort(), '|', typeof (m.priorytet + 1));
```

## Round 2 — the assistant-generated validator and router

```js
const SCHEMAT = { priorytet: "number", pewnosc: "number", tagi: "object" };

function waliduj(surowa) {
  let dane;
  try {
    dane = JSON.parse(surowa);
  } catch (e) {
    return null;
  }
  for (const pole in SCHEMAT) {
    if (typeof dane[pole] !== SCHEMAT[pole]) return null;
  }
  return dane;
}

const PROG_PEWNOSCI = 0.75;

function decyzja(dane) {
  if (!dane) return "do-czlowieka";
  if (dane.pewnosc < PROG_PEWNOSCI) return "do-czlowieka";
  if (dane.priorytet >= 1) return "kolejka-standard";
  if (dane.priorytet >= 3) return "kolejka-pilna";
  return "auto-zamkniete";
}

const odpowiedzi = [
  '{"priorytet": 3, "pewnosc": 0.91, "tagi": ["hydraulika"]}',
  '{"priorytet": 0, "pewnosc": 0.99, "tagi": ["spam"]}',
  '{"priorytet": 4, "pewnosc": 95, "tagi": null}',
  '```json\n{"priorytet": 2, "pewnosc": 0.88, "tagi": ["elektryka"]}\n```'
];

const litery = ['A', 'B', 'C', 'D'];
odpowiedzi.forEach((s, i) => {
  const d = waliduj(s);
  console.log(litery[i] + ')', JSON.stringify(d), '->', decyzja(d));
});

try {
  const d = waliduj(odpowiedzi[2]);
  console.log('E)', d.tagi.length);
} catch (e) {
  console.log('E)', e.constructor.name + ':', e.message);
}
```

```
A) {"priorytet":3,"pewnosc":0.91,"tagi":["hydraulika"]} -> kolejka-standard
B) {"priorytet":0,"pewnosc":0.99,"tagi":["spam"]} -> auto-zamkniete
C) {"priorytet":4,"pewnosc":95,"tagi":null} -> kolejka-standard
D) null -> do-czlowieka
E) TypeError: Cannot read properties of null (reading 'length')
```

### The four bugs

1. **`typeof null === "object"`.** The schema check accepts `tagi: null`; the program crashes two
   layers later on `tagi.length`, with a message that points at neither the model nor the validator.
   `typeof x === "object"` also accepts arrays, `Date` and any other object.
2. **A numeric threshold without a scale check is not a threshold.** `95 < 0.75` is `false`, so a
   confidence returned as a percentage passes the guard every single time.
3. **Reversed thresholds.** `>= 1` comes before `>= 3`, so `kolejka-pilna` is dead code and the
   flooded apartment (priority 4) lands in the normal queue.
4. **`catch { return null }` plus no fence stripping.** `D)` is a correct classification that differs
   from `A)` only by six backticks; parse throws, the catch returns `null`, and three different
   failure causes collapse into one indistinguishable value with no log line.

Fix (1) first: it is the only one that *stops* processing and lies about its own cause. The other
three misroute a ticket, which is recoverable because the record still exists.

## Quiz

1. What does `typeof` return for `null`, `[]`, `{}`, `new Date()`, `NaN`, `undefined`, `() => {}`
   and an undeclared variable? What replaces `typeof x === "object"`?
   **Key:** `"object"` four times, then `"number"`, `"undefined"`, `"function"`, `"undefined"` (no
   throw — the single hole in the `ReferenceError` rule). Use `Array.isArray(x)`;
   `x !== null && typeof x === "object" && !Array.isArray(x)`; `Object.prototype.toString.call(x)`.
   In a real project: a schema library, not hand-written `typeof`.
2. This validator returns `null` for three different reasons. Design a return value that separates
   them without throwing.
   **Key:** `{ ok: true, dane }` / `{ ok: false, powod: "parse" | "brak_pola" | "zly_typ", pole }`.
   Three log lines, three different decisions: retry, route to a human, raise an alarm (a type change
   is about to hit every ticket at once).
3. Name three defence layers against a model that wraps JSON in a fence, and what each does *not* fix.
   **Key:** enforced format at call time (does not catch semantically wrong values); fence stripping
   plus schema validation at parse time (does not catch a changed scale); a counter of rejected
   responses by reason (shows the change, fixes nothing in the moment).

## SM-2 card

**Front:** Why is `typeof x === "object"` unusable for validating external data?
**Back:** Four different things share the result `"object"`: a plain object, an array, `new Date()`
and — worst — `null` (a 1995 bug that will never be fixed). So `tagi: null` passes the schema check
and the program dies two layers later on `tagi.length`. Use `Array.isArray`, an explicit `!== null`
guard, or `Object.prototype.toString.call`; in production, a schema library.

## Takeaway

This function has a schema, `typeof`, a confidence threshold and a `try/catch` — all four words that
sound like the right answer in an interview. It still lets `null` through, lets a wrong scale
through, sends a flooded apartment to the normal queue, and bins an answer that was correct.
