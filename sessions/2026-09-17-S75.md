# S75 — Context selection in a RAG pipeline (2026-09-17)

**Concept:** In RAG you don't lose on retrieval — you lose on *selection*. A comparator sorted the wrong way, combined with a `slice` two lines below it, hands the model everything except the answer. And an empty array is truthy, so "no context" silently becomes "a prompt with no context".

**Story:** "Leigusamningur" — a small knowledge base about rental agreements in Reykjavík. A PR described as *"top-K fragment selection with dedupe, done"* passed review: it has a confidence threshold, a context limit, a dedupe step and a `powod` (reason) field for the no-hits case. Three complaints arrived on Monday: the chatbot quotes the wrong deposit amount even though the amount is the first sentence of the regulations; it answers confidently about topics the knowledge base contains nothing on; and once it returned two paragraphs when the limit was three.

## Round 2 — the reranker from the PR, plus the consumer that trusts it

```js
const PROG = 0.75;
const MAX_FRAGMENTOW = 3;

function wybierzKontekst(trafienia) {
  const dobre = trafienia.filter(t => t.score > PROG);
  if (!dobre.length) return { fragmenty: [], powod: "brak-trafien" };

  const posortowane = dobre.sort((a, b) => a.score - b.score);
  const najlepsze = posortowane.slice(0, MAX_FRAGMENTOW);

  const unikalne = [];
  for (const t of najlepsze) {
    if (!unikalne.includes(t.tekst)) unikalne.push(t.tekst);
  }
  return { fragmenty: unikalne, powod: null };
}

function zbudujPrompt(wynik) {
  if (!wynik.fragmenty) return "BRAK KONTEKSTU - nie odpowiadaj";
  return "Kontekst:[" + wynik.fragmenty.join(" / ") + "] Pytanie: ile wynosi kaucja?";
}

const A = [
  { id: "d1", score: 0.95, tekst: "Kaucja wynosi 150 000 ISK." },
  { id: "d2", score: 0.91, tekst: "Kaucje zwracamy w 14 dni." },
  { id: "d3", score: 0.88, tekst: "Regulamin parkingu, zalacznik 3." },
  { id: "d4", score: 0.80, tekst: "Zwrot kaucji po protokole." },
  { id: "d5", score: 0.76, tekst: "Zwrot kaucji po protokole." }
];
const B = [
  { id: "e1", score: 0.75, tekst: "Kaucja wynosi 150 000 ISK." },
  { id: "e2", score: 0.75, tekst: "Kaucje zwracamy w 14 dni." }
];
const C = [
  { id: "f1", score: 0.31, tekst: "Godziny otwarcia biura." }

[['A', A], ['B', B], ['C', C]].forEach(function (para) {
```

## The four bugs

1. **The comparator sorts ascending and `slice` takes from the front.** `(a, b) => a.score - b.score` puts the worst matches first, so `slice(0, 3)` picks `0.76`, `0.80` and `0.88`. The `0.95` fragment that contains the answer never reaches the model. Each of the two lines is correct on its own — what is wrong is the *relationship* between them, and nobody sees a relationship without walking it with concrete numbers. Fix: `(a, b) => b.score - a.score`, or `toSorted` so it doesn't mutate either.
2. **`t.score > PROG` rejects the value sitting exactly on the threshold.** Case `B)` is two fragments at `0.75`, one of which holds the answer. In RAG this is not an edge case: thresholds get set to round numbers and search engines return scores that land on round numbers. Switching to `>=` fixes that one value; the real question is what the threshold *means*, which is a product decision, not a constant in a file.
3. **Dedupe runs after `slice`, so a duplicate eats a slot.** In `A)` two of the selected three are identical, so the function returns **two** fragments with `MAX_FRAGMENTOW = 3` and reports nothing unusual. Dedupe has to run before slicing. Second half of the same bug: `includes` compares strings exactly (SameValueZero), and overlapping chunks are near-duplicates by construction.
4. **`powod` is dead code, because `[]` is truthy.** The function honestly fills in `powod: "brak-trafien"`, but the consumer asks `if (!wynik.fragmenty)` — whether the *field exists*, not whether anything is in it. So instead of refusing to answer, the model gets `Kontekst:[] Pytanie: ...`: a question with no material and no instruction to decline. Worse, `B)` and `C)` produce identical output downstream, although one means "the answer was in the index and lost by zero at the threshold" and the other means "the index has nothing on this". The first needs a threshold change, the second needs more documents — and they are indistinguishable.

**Which to fix first: (1).** Bugs 2, 3 and 4 fire conditionally — a score exactly on the threshold, a duplicate inside the top-K, no hits at all. Bug 1 fires on every query with more hits than `MAX_FRAGMENTOW`, i.e. on normal traffic, and it is the only one that produces output that looks completely fine: a full context, the right number of fragments, sensible sentences, nothing empty in the logs. Its only symptom is worse answers — a metric nobody collects.

**One thing that is *not* a bug:** `dobre.sort(...)` does not corrupt the caller's array (`D) d1,d2,d3,d4,d5`), because it mutates `dobre`, the new array returned by `filter`. Had the author written `trafienia.sort(...)`, the leak would be immediate. `sort` on its own is not a red flag — what matters is *what* is being sorted and where it came from.

## Quiz

**1.** One empty array, three ways to ask it "are you empty": `arr.length || 'brak'`, `arr.length ?? 'brak'`, `arr ? 'jest' : 'brak'`. Build the table for `[]`, `[0]`, `undefined`, `null`; say which form belongs in a guard.

*Key (verified):* `[]` → `"brak"` / `0` / `jest`; `[0]` → `1` / `1` / `jest`; `undefined` and `null` → `TypeError` / `TypeError` / `brak`. Only `if (!arr || arr.length === 0)` works, in that order, because `.length` throws on `undefined`/`null` and `||` short-circuits left to right. `arr.length || x` conflates "empty" with "absent" and overrides a legitimate `0`; `arr.length ?? x` lets `0` through (sometimes right, never right in an emptiness guard); `arr ? :` is true for *every* array — exactly the bug in Round 2.

**2.** What do positive, negative and zero mean from a `sort` comparator? What does `.sort()` do without one? Write a comparator sorting by `score` descending with ties broken by `id` ascending. What happens if a comparator returns `true`/`false`?

*Key (verified):* negative → `a` first; positive → `b` first; zero → order irrelevant (sort is stable, input order kept). Without a comparator, `sort()` stringifies every element and compares UTF-16 code points. Comparator: `(a, b) => (b.score - a.score) || a.id.localeCompare(b.id)` — for `[{b,0.9},{a,0.9},{c,0.95}]` this gives `c:0.95,a:0.9,b:0.9`; it works because `||` passes the `0` from the first term through. A boolean comparator throws nothing: `sort` coerces the result to a number (`true` → 1, `false` → 0), so it can never say "a before b". Verified: `(x, y) => y.score > x.score` gives `b:0.9,a:0.9,c:0.95` — the best element stays last and nothing complains.

**3.** The function returns `{ fragmenty, powod }` but the consumer reads only `fragmenty`, so it cannot tell "lost by zero at the threshold" from "nothing in the index". Design the boundary so missing context *cannot* silently become a context-free prompt. What belongs in the log and the metric for `A)`, `B)`, `C)`?

*Key:* make the boundary a type, not a convention — `{ ok: true, fragmenty }` or `{ ok: false, powod: "ponizej-progu" | "pusty-indeks" | "blad-wyszukiwania", najlepszyScore, zapytanie }`, with `zbudujPrompt` accepting only `ok: true`; the decision not to answer belongs one layer up, because it is a product decision. Without types: `if (!wynik.fragmenty?.length) throw new BrakKontekstu(wynik.powod)`. Logs: `A)` → `rag.ok fragmentow=2 limit=3 best=0.95 wybrane=[0.76,0.80,0.88]` — that `best` vs `wybrane` pairing alone would have exposed bug 1 on day one; `B)` → `rag.odrzucone powod=ponizej-progu best=0.75 prog=0.75` → change the threshold; `C)` → `rag.odrzucone powod=pusty-indeks best=0.31` → add documents. Minimum metric: rejection counter split by reason **plus** a histogram of `best` — without the second you cannot tell a bad threshold from a bad index.

## SM-2 card

**Front:** Three ways to ask an array "are you empty" — `arr.length || 'brak'`, `arr.length ?? 'brak'`, `arr ? 'jest' : 'brak'`. What does each return for `[]`, and which belongs in a guard?

**Back:** For `[]`: `length || 'brak'` → `'brak'` (because `0` is falsy), `length ?? 'brak'` → `0` (because `??` only reacts to `null`/`undefined`), and `arr ? :` → `'jest'`, because **an empty array is truthy**. Only `if (!arr || arr.length === 0)` belongs in a guard — in that order, because `.length` on `undefined`/`null` throws `TypeError`. Consequence: `if (!wynik.fragmenty)` never fires for an empty array, so "no context" silently becomes a prompt with no context.

## Takeaway

Yesterday a validator threw away a correct model response. Today a reranker threw away a correct answer from the company's *own* knowledge base — one it wrote, indexed and proof-read itself. No external system failed, no API went down, and retrieval put the right fragment in first place. One character in a comparator was enough to hand the model everything except the answer, and one `!` in front of an array was enough to turn "I have no data on this" into a confident answer out of nothing. Nobody loses at RAG on retrieval. You lose on line five of a function that the PR calls "tidying up the results".
