# S77 — Operators and comparisons on a webhook receiver (2026-09-21)

**Concept:** in a webhook receiver every decision is a single comparison, and a comparison in JS can be true for a reason that is not written anywhere in the code. `!` binds tighter than `==`, `||` cannot tell `0` from "unset", `includes` compares strictly, and `200 <= status <= 299` is not a range check.

**Story:** the "Móttaka" webhook gateway in Reykjavik answered `200 OK` to every request — including the ones it believed it had rejected.

## Starcie 1 — eight operator traps on one API response

```js
const odp = { status: "200", ok: false, retries: 0, body: "", sig: "abc" };
const oczek = "abc ";   // signature copied by hand from the provider panel (trailing space)
const kody = [];

console.log("1)", odp.status == 200);
console.log("2)", odp.status === 200);
console.log("3)", odp.retries || 3);
console.log("4)", odp.retries ?? 3);
console.log("5)", 200 <= odp.status <= 299);
console.log("6)", odp.sig == oczek, odp.sig === oczek.trim());
console.log("7)", kody == false, Boolean(kody));
console.log("8)", odp.ok || odp.status == 200 && odp.retries > 0);
```

## Starcie 2 — the real gateway: four gates, four bugs

```js
const KODY_RETRY = [429, 500, 502, 503];

function obsluz(zd, konf) {
  const proby = konf.proby || 3;
  const status = zd.status;
  if (!zd.sig == konf.sig) return "A) odrzucone: zly podpis";
  if (KODY_RETRY.includes(status) && proby > 0) return "B) ponawiam, zostalo " + (proby - 1);
  if (200 <= status <= 299) return "C) przyjete";
  return "D) porzucone";
}

console.log(obsluz({ status: 503,   sig: "podrobiony" }, { proby: 0, sig: "prawdziwy" }));
console.log(obsluz({ status: "503", sig: "prawdziwy"  }, { proby: 3, sig: "prawdziwy" }));
console.log(obsluz({ status: 404,   sig: "prawdziwy"  }, { proby: 3, sig: "prawdziwy" }));
```

## Verified

Run with `node v22.23.2`:

```
1) true
2) false
3) 3
4) 0
5) true
6) false true
7) true true
8) false
B) ponawiam, zostalo 2
C) przyjete
C) przyjete
```

Branch `D) porzucone` is unreachable — no input can ever produce it.

## What each gate actually does

1. `if (!zd.sig == konf.sig)` parses as `(!zd.sig) == konf.sig` → `false == "prawdziwy"` → `false`. The signature gate never fires; every signature passes, forged ones included.
2. `konf.proby || 3` turns a configured `0` into `3`, because `0` is falsy. `??` is the fix.
3. `KODY_RETRY.includes(status)` compares with SameValueZero (effectively `===`), so a status code arriving as the string `"503"` misses the retry list.
4. `200 <= status <= 299` evaluates `(200 <= status)` first, producing a boolean, then `true <= 299` → `1 <= 299` → always true. `404` and `503` are reported as accepted.

## Quiz

1. Fix gate [1] in one line — and explain why `if (!(zd.sig == konf.sig))` is logically correct but still wrong for a webhook signature.
   **Key:** `if (zd.sig !== konf.sig)`. The `!(... == ...)` form keeps `==`, which coerces types; a signature is always a string and the comparison must be strict. In production it also needs `crypto.timingSafeEqual` on buffers, since string comparison leaks timing.
2. In gate [2], `{ proby: 0 }` must mean "do not retry". Which operator fixes it with one character change, and why does it work where `||` does not?
   **Key:** `konf.proby ?? 3`. `||` falls back on every falsy value, so it eats `0`, `""` and `false`; `??` only reacts to `null` and `undefined`, i.e. to an actual absence of a value.
3. Write the correct success range for gate [4] — and say what happens to call 3 (`404`) after that single fix, if gates [1]-[3] stay untouched.
   **Key:** `if (status >= 200 && status <= 299)`. Call 3 stops being "accepted" and falls to `D) porzucone`, correctly; branch D stops being dead code. Gates [1]-[3] remain broken: forged signatures still pass, `proby: 0` still becomes 3, and `"503"` as a string still misses the retry list.

## SM-2 card

**Front:** What does `if (!signature == expected)` actually check?
**Back:** `!` binds tighter than `==`, so the engine reads `(!signature) == expected` — a boolean compared to a string. For a non-empty signature that is `false == "abc"` → `false`, so the gate never fires and every signature passes. Correct form: `if (signature !== expected)`.

## Takeaway

Four gates, four sensible names, zero working checks. Three of these bugs break the handling of your own traffic and somebody will eventually report them. The first one lets in somebody else's traffic, and nobody reports it — from the outside the system looks like it works. A gate that always passes is not visibly broken. It is decoration.
