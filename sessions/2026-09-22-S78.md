# S78 — Default parameters: an expression, not a value (2026-09-22)

**Concept:** a default parameter value in JS is an *expression* re-evaluated on every call where the argument is `undefined`. An object literal therefore builds a fresh object each time (the opposite of Python). But if the expression is the *name* of an outer object, every call resolves to the same address and the default becomes shared state.

**Story:** ticket queue "Bidrod" in Reykjavik, pushing requests into a Python scoring service. Same function, six calls, three different ways of supplying (or not supplying) the same two arguments.

## Encounter 1 — six calls, three ways of passing the arguments

```js
const KOLEJKA = ["A-1", "A-2", "A-3"];

function wyslij(id, opcje = { retry: 2 }, log = null) {
  opcje.retry = opcje.retry - 1;
  log = log ?? [];
  log.push(`${id}:${opcje.retry}`);
  return log;
}

console.log("1)", wyslij("A-1"));
console.log("2)", wyslij("A-2"));

const wspolne = { retry: 2 };
console.log("3)", wyslij("A-3", wspolne));
console.log("4)", wyslij("A-4", wspolne));
console.log("5)", wspolne);

const zebrane = [];
console.log("6)", wyslij("A-5", undefined, zebrane));
console.log("7)", wyslij("A-6", undefined, null), zebrane);

const zadania = [];
for (var i = 0; i < 3; i++) {
  zadania.push(() => KOLEJKA[i] ?? "poza lista");
}
console.log("8)", zadania.map(f => f()));
console.log("9)", i);
```

## Encounter 2 — the code review that hoisted the literal into a constant

```js
const DOMYSLNE = { retry: 2 };

function wyslijV2(id, opcje = DOMYSLNE) {
  opcje.retry = opcje.retry - 1;
  return `${id}:${opcje.retry}`;
}

console.log("10)", wyslijV2("B-1"));
console.log("11)", wyslijV2("B-2"));
console.log("12)", wyslijV2("B-3", { retry: 2 }));
console.log("13)", DOMYSLNE);
```

## Verified

Run with `node v22.23.2` before the answer key was written.

```
1) [ 'A-1:1' ]
2) [ 'A-2:1' ]
3) [ 'A-3:1' ]
4) [ 'A-4:0' ]
5) { retry: 0 }
6) [ 'A-5:1' ]
7) [ 'A-6:1' ] [ 'A-5:1' ]
8) [ 'poza lista', 'poza lista', 'poza lista' ]
9) 3
10) B-1:1
11) B-2:0
12) B-3:1
13) { retry: 0 }
```

**Review verdict:** the reviewer was right on the *fact* (an object literal in the signature really does allocate on every call without an argument) and wrong on the *change*. Hoisting it into `const DOMYSLNE` turns a fresh default into process-wide shared state: the retry counter walks 2 -> 1 -> 0 -> -1 for the lifetime of the process. Line 12 shows it sharply — the call that passes its own `{ retry: 2 }` is the only one that returns a sane value.

## Quiz

1. **Python has the same signature `def wyslij(id, opcje={"retry": 2}):` and behaves the opposite way — all calls share one dict. Why, and what is the standard fix?**
   Python evaluates the default *once*, at definition time, and stores it in `__defaults__`. JS evaluates the expression on every call. Fix: `def wyslij(id, opcje=None):` plus `if opcje is None: opcje = {"retry": 2}` in the body.

2. **Why did line 7 leave `zebrane` untouched, even though the body calls `log.push(...)`?**
   `log = log ?? []` *assigns to the parameter*, which only rebinds the local name — assignment to a parameter never travels back to the caller. When a real array arrives (line 6), `??` leaves it alone, so `push` mutates the caller's object.

3. **Swap `var i` for `let i` and change nothing else. What do lines 8 and 9 print?**
   Line 8 becomes `[ 'A-1', 'A-2', 'A-3' ]` — `let` creates a fresh binding per iteration, so each closure captures its own `i`. Line 9 throws a `ReferenceError`: `let i` is scoped to the loop, while `var i` outlived it.

## SM-2 card

**Front:** In JS, `function f(x = { a: 1 })` — does every argument-less call get the same object?

**Back:** No. The default is an *expression* re-evaluated on every call where the argument is `undefined`, so the literal builds a new object each time (the opposite of Python, where the default dict is created once at definition). But when the expression is the *name* of an outer object, it still re-evaluates — to the same address — and every call mutates one shared object.

## Takeaway

This is exactly the class of PR an implementation engineer gets asked to approve: one line, a sensible performance rationale, a technically true premise, and a global-state bug that no unit test catches, because a unit test calls the function once.
