# S80 - Comparison operators: two rules, chosen by the types on both sides

**Concept:** a relational operator (`>` `<` `>=` `<=`) does not have one rule, it has two - and it picks between them by looking at BOTH operands. Two strings are compared lexicographically, character by character; any other combination converts both sides to numbers. That makes `>` more lenient than `===`, and on uniformly formatted strings the bug is invisible.

**Story:** a district heating company runs a RAG assistant over its tariff rules. The retriever returns fragments with a `score`, a reranker adds a `pozycja`, and a filter decides what goes into the prompt. A customer gets an answer from a 2019 archive, and every test is green.

## Round 1

```js
const FRAGMENTY = [
  { id: "A", score: 0.92,  pozycja: 1,    zaufane: true  },
  { id: "B", score: "0.9", pozycja: "9",  zaufane: false },
  { id: "C", score: 0.85,  pozycja: 2,    zaufane: true  },
  { id: "D", score: "0.1", pozycja: "10", zaufane: false },
];
const PROG = 0.85;
console.log("1)", FRAGMENTY[1].score > PROG, FRAGMENTY[1].score === 0.9);
console.log("2)", FRAGMENTY[2].score > PROG, FRAGMENTY[2].score >= PROG);
console.log("3)", FRAGMENTY[1].pozycja > FRAGMENTY[3].pozycja);
console.log("4)", FRAGMENTY[1].pozycja > Number(FRAGMENTY[3].pozycja));
console.log("5)", FRAGMENTY[1].score + 0.05, FRAGMENTY[1].score - 0.05);
const wybrane = FRAGMENTY.filter(f => f.score > PROG || f.score > 0.5 && f.zaufane);
console.log("6)", wybrane.map(f => f.id).join(","));
const wybrane2 = FRAGMENTY.filter(f => (f.score > PROG || f.score > 0.5) && f.zaufane);
console.log("7)", wybrane2.map(f => f.id).join(","));
```

## Round 2

```js
function progDla(konf) { return konf.prog || 0.75; }
function najlepszy(lista) { return Math.max(...lista.map(f => f.score)); }
const KONF_A = { prog: 0.9 }; const KONF_B = { prog: 0 }; const KONF_C = {};
console.log("8)", progDla(KONF_A), progDla(KONF_B), progDla(KONF_C));
console.log("9)", KONF_B.prog ?? 0.75);
console.log("10)", najlepszy([]));
console.log("11)", najlepszy([]) > progDla(KONF_C));
console.log("12)", najlepszy([FRAGMENTY[1]]));
console.log("13)", najlepszy([FRAGMENTY[1]]) === FRAGMENTY[1].score);
```

What-if check: (a) if `PROG` arrives as the string `"0.85"`, lines 1, 2, 6 and 7 print exactly the same - for strings shaped `"0.xx"` lexicographic order matches numeric order; (b) rewriting line 6 as `f.score > PROG && f.score > 0.5 || f.zaufane` still prints `A,B,C`; (c) neither change turns a test red on this data. The data has no discriminating power, so a green test here is absence of counter-evidence, not evidence.

## Quiz

1. When do "compare as text" and "compare as number" diverge for numeric strings? Give the shortest `score` that would break line 6 if `PROG` were also a string.
   **Key:** when the strings differ in digits before the decimal point or in notation (`"10"` vs `"9"`, `".9"` vs `"0.85"`, `" 0.9"`). `".9" > "0.85"` is `false` because `"."` (46) < `"0"` (48), although numerically 0.9 > 0.85.
2. What does `Math.max` do with the argument `"0.9"`, and which added line would catch the problem at the input?
   **Key:** it converts every argument with `Number()`, so it returns the number `0.9` - a different type than went in. A schema check before the filter, e.g. `if (typeof f.score !== "number") throw ...`.
3. Two independent defences against a string `score`: one at the input, one in retrieval evaluation. Which one also catches the wrong `&&`/`||` precedence?
   **Key:** input: schema validation (number, range 0-1). Eval: questions with expected fragments and a hit-rate metric. Only the eval catches the precedence bug (it is a logic bug, not a type bug) - and only if the test data contains a case where the two variants differ.

## Card

**Front:** How does JS choose the rule for `>` `<` `>=` `<=`, and how is that different from `===`?
**Back:** If BOTH sides are strings - lexicographic comparison (`"9" > "10"` is `true`). Otherwise both sides go to numbers (`"0.9" > 0.85` is `true`). So `>` lets text through, while `"0.9" === 0.9` is `false`. On uniformly formatted strings the two orders coincide, so the bug stays hidden. `+` with a string concatenates, `-` converts. `&&` binds tighter than `||`.

## Takeaway

A reranker and a threshold filter are nothing more than score comparisons. If a score arrives as text, the filter keeps working - until the day a differently formatted value shows up.
