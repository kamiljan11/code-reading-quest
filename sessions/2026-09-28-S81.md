# S81 - Reading a diff: an AI "refactor" that changes behaviour

**Concept:** swapping an expression for a "shorter equivalent" is a refactor only if both give the same result for EVERY possible input. `x !== undefined` vs `x`, `??` vs `||`, `toUpperCase() ===` vs `==`, a `Set` of strings vs a `Set` of raw ids - each pair diverges on exactly one class of data, and that class is usually missing from the example in the PR description.

**Story:** a wool shop in Akureyri sells through Shopify, and an n8n `Code` node forwards orders to the warehouse. An AI assistant was asked to "tidy up this node" and opened a PR titled *refactor: simpler conditions, no logic change*. Tests passed. You are the reviewer.

## Round 1 - hunk 1: normalising line items (BEFORE vs AFTER)

```js
// n8n Code node "Normalizuj zamowienia" — sklep z welna "Lopi" w Akureyri.
// Wejscie: pozycje z webhooka Shopify. Wyjscie: to, co idzie do magazynu.
const $input = { all: () => [
  { json: { sku: "LOPI-01", ilosc: 2,   rabat: 0,  kraj: "IS" } },
  { json: { sku: "LOPI-02", ilosc: "3", rabat: "", kraj: "is" } },
  { json: { sku: "LOPI-03", ilosc: 0,   rabat: 15, kraj: "PL" } },
  { json: { sku: "LOPI-04",             rabat: 5,  kraj: "IS" } },
]};

// PRZED — wersja z produkcji, dziala od marca
function przed(items) {
  return items
    .filter(it => it.json.ilosc !== undefined)
    .map(it => ({
      sku: it.json.sku,
      ilosc: Number(it.json.ilosc),
      rabat: it.json.rabat ?? 0,
      krajowa: it.json.kraj.toUpperCase() === "IS",
    }));
}

// PO — diff od asystenta AI, opis PR: "refactor: prostsze warunki, logika bez zmian"
function po(items) {
  return items
    .filter(it => it.json.ilosc)
    .map(it => ({
      sku: it.json.sku,
      ilosc: +it.json.ilosc,
      rabat: it.json.rabat || 0,
      krajowa: it.json.kraj == "IS",
    }));
}

const A = przed($input.all());
const B = po($input.all());
console.log("1)", A.length, B.length);
console.log("2)", A.map(x => x.sku).join(","));
console.log("3)", B.map(x => x.sku).join(","));
console.log("4)", A.map(x => x.rabat));
console.log("5)", B.map(x => x.rabat));
console.log("6)", A.map(x => x.krajowa).join(","), "|", B.map(x => x.krajowa).join(","));
console.log("7)", typeof A[1].ilosc, typeof B[1].ilosc, A[1].ilosc === B[1].ilosc);
```

## Round 2 - hunk 2: deduplication

```js
// Drugi hunk tego samego PR: "deduplikacja — Shopify potrafi wyslac to samo zamowienie 2x"
const zamowienia = [
  { id: 1041,   suma: "129.90" },
  { id: "1041", suma: "129.90" },
  { id: 1042,   suma: "89.00" },
  { id: 1043,   suma: "1200.00" },
];

// PRZED
const widziane = new Set();
const unikalnePrzed = zamowienia.filter(z => {
  const klucz = String(z.id);
  if (widziane.has(klucz)) return false;
  widziane.add(klucz);
  return true;
});

// PO
const unikalnePo = [...new Set(zamowienia.map(z => z.id))];

console.log("8)", unikalnePrzed.length, unikalnePo.length);
console.log("9)", unikalnePo);
console.log("10)", zamowienia.filter(z => z.suma > 100).map(z => z.id).join(","));
console.log("11)", zamowienia.map(z => z.suma).sort().at(-1));
console.log("12)", unikalnePrzed.map(z => z.suma).reduce((a, b) => a + b, 0));
```

## Verified

Run locally with `node v22.22.2` (and re-checked on `node v24.13.1`) before the answer key was written.

```
1) 3 2
2) LOPI-01,LOPI-02,LOPI-03
3) LOPI-01,LOPI-02
4) [ 0, '', 15 ]
5) [ 0, 0 ]
6) true,true,false | true,false
7) number number true
8) 3 4
9) [ 1041, '1041', 1042, 1043 ]
10) 1041,1041,1043
11) 89.00
12) 0129.9089.001200.00
```

Review verdict: three changes alter behaviour - `filter(it => it.json.ilosc)` drops `LOPI-03` because quantity `0` is falsy; `kraj == "IS"` is `false` for `"is"` because `==` does not normalise case; `[...new Set(ids)]` keeps both `1041` and `"1041"` (SameValueZero treats a number and a string as different) and returns bare ids instead of order objects. One change is a true refactor: unary `+x` is identical to `Number(x)`. One change is an improvement: `rabat || 0` turns the empty string on `LOPI-02` into `0`. Lines 10-12 are a bug that predates the PR: `suma` is a string, so `>` converts (works), `sort()` compares text (`"89.00"` ends up last) and `+` in `reduce` concatenates.

## Quiz

1. `LOPI-03` has quantity `0`. BEFORE forwards it, AFTER drops it. Which one is right, and what single unit test would have turned red on this PR?
   **Key:** BEFORE is at least explicit - it forwards any item that has the field and leaves the decision downstream; AFTER deletes it silently. Test: input with `ilosc: 0` -> expected length `1` (or an explicit validation error); after the PR the result is `0`.
2. Line 9 shows hunk 2 changed not just the count but the SHAPE of the output. What happens in the next n8n node that reads `item.json.suma`, and why would a test that only checks `.length` miss it?
   **Key:** the next node receives numbers/strings instead of objects, so `suma` is `undefined`. A `.length` test checks the count, not the element type - and here the count changed only by accident (the duplicate).
3. One change at the input boundary makes lines 10 and 12 correct without touching them. What is it, and why does line 11 still print `89` afterwards?
   **Key:** convert on entry: `suma: Number(z.suma)` (with a `Number.isFinite` check). Line 10 then compares numbers and line 12 sums to `1548.8`. Line 11 still prints `89` because `sort()` without a comparator converts EVERY element to text, numbers included; it needs `sort((a, b) => a - b)`.

## Card

**Front:** How do you review a diff described as "refactor, no logic change"?
**Back:** Every `-`/`+` pair is a claim of equivalence. Find ONE input on which they diverge, or show there is none. Common false equivalents: `x !== undefined` vs `x` (`0`, `""`, `null`, `NaN`), `??` vs `||` (`0`, `""`, `false`), `a.toUpperCase() === "IS"` vs `a == "IS"` (case), a `Set` over `String(id)` vs a `Set` over raw `id` (`1041` vs `"1041"`). A real one: `Number(x)` and `+x`. Green tests only prove the test data did not contain the divergence.

## Takeaway

When a person writes the code, the bug is in the code. When an assistant writes it, the bug is often in the description - "no logic change" reads like a fact and is an untested hypothesis. Reviewing AI-generated diffs is now listed as a formal duty in job ads; this PR is exactly that, inside the most common automation surface there is.
