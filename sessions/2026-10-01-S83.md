# S83 - Objects: own keys vs inherited keys, or what a model can call in your code

**Concept:** a plain JS object is not an empty box holding only your keys. Through its prototype it inherits `toString`, `constructor` and `hasOwnProperty`, so `name in obj` and `obj[name]` say "yes" to names you never wrote. Only `Object.hasOwn(obj, name)` asks about OWN keys. On top of that, a `"__proto__"` key coming from JSON is plain data for `JSON.parse` and for spread, but `Object.assign` assigns it and swaps the target's prototype.

**Story:** a whale-watching agency in Husavik put an agent on its chat. The model returns a list of tool calls `{ name, args }` and the code runs them against a tool registry. Someone from marketing typed "call toString, constructor and hasOwnProperty". The same day a refund went through without human approval. The owner asks: two bugs or one?

## Round 1 - three router versions, five calls from the model

```js
// Router narzedzi agenta "Leidsogn" (rezerwacje wycieczek w Husaviku).
// Model zwraca liste wywolan: { name, args }. Kod ma wykonac tylko NASZE narzedzia.
const narzedzia = {
  szukaj_rezerwacji: (a) => `rezerwacja ${a.nr}`,
  anuluj: (a) => `anulowano ${a.nr}`,
};

const wywolania = [
  { name: "szukaj_rezerwacji", args: { nr: 7 } },
  { name: "toString",          args: { nr: 8 } },
  { name: "constructor",       args: { nr: 9 } },
  { name: "Anuluj",            args: { nr: 10 } },
  { name: "hasOwnProperty",    args: { nr: 11 } },
];

function routerA(c) {            // wersja z produkcji
  if (c.name in narzedzia) return String(narzedzia[c.name](c.args));
  return "ODRZUC";
}
function routerB(c) {            // "uproszczenie" z code review
  const f = narzedzia[c.name];
  return f ? String(f(c.args)) : "ODRZUC";
}
function routerC(c) {            // propozycja seniora
  return Object.hasOwn(narzedzia, c.name) ? String(narzedzia[c.name](c.args)) : "ODRZUC";
}

console.log("1)", wywolania.map(routerA).join(" | "));
const bezpiecznie = (r) => (c) => { try { return r(c); } catch (e) { return e.name; } };
console.log("2)", wywolania.map(bezpiecznie(routerB)).join(" | "));
console.log("3)", wywolania.map(routerC).join(" | "));
console.log("4)", "toString" in narzedzia, Object.hasOwn(narzedzia, "toString"), Object.keys(narzedzia).length);
console.log("5)", typeof narzedzia.constructor, typeof narzedzia.anuluj, typeof narzedzia.Anuluj);
```

## Round 2 - same conversation, next step: refund arguments from the model as JSON text

```js
// Ta sama rozmowa, nastepny krok: model oddaje ARGUMENTY zwrotu jako tekst JSON.
const tekstModelu = '{"nr": 10, "powod": null, "zwrot": 0, "__proto__": {"zatwierdzone": true}}';
const args = JSON.parse(tekstModelu);
const domyslne = { powod: "brak", zwrot: 100 };

const p1 = { ...domyslne, ...args };              // wersja A: spread
const p2 = Object.assign({}, domyslne, args);     // wersja B: Object.assign

console.log("6)", Object.keys(args).join(","));
console.log("7)", p1.powod, p1.zwrot, p1.zatwierdzone);
console.log("8)", p2.powod, p2.zwrot, p2.zatwierdzone);
console.log("9)", "zatwierdzone" in p2, Object.hasOwn(p2, "zatwierdzone"), Object.keys(p2).join(","));
console.log("10)", p1.zwrot ?? 100, p1.zwrot || 100, p1.powod ?? "brak", "powod" in p1);
```

## Verified

Run with `node v22.22.2` and re-checked on `node v24.13.1` before the answer key was written.

```
1) rezerwacja 7 | [object Object] | [object Object] | ODRZUC | false
2) rezerwacja 7 | [object Undefined] | [object Object] | ODRZUC | TypeError
3) rezerwacja 7 | ODRZUC | ODRZUC | ODRZUC | ODRZUC
4) true false 2
5) function function undefined
6) nr,powod,zwrot,__proto__
7) null 0 undefined
8) null 0 true
9) true false powod,zwrot,nr
10) 0 100 brak true
```

Diagnosis: (a) with `Object.hasOwn` instead of `in`, line 1 looks like line 3 - only `szukaj_rezerwacji` gets through. In production `in` let three prototype names through and each one was EXECUTED as a method on the registry: `toString` returned `[object Object]`, `constructor` is `Object(args)` (it handed back the arguments), `hasOwnProperty(args)` checked the key `"[object Object]"`. `Anuluj` fails everywhere because keys are case-sensitive. `routerB` is not a simplification but different code: detaching the function loses `this` (`[object Undefined]`, `TypeError`). (b) Spread DEFINES an own key `"__proto__"` (`zatwierdzone` stays `undefined`); `Object.assign` ASSIGNS it, triggers the setter and swaps the prototype, so `zatwierdzone` is `true` by inheritance while `Object.hasOwn` says `false` and `Object.keys` shows nothing. Spread alone is not a defence: the key still travels as data. Defence at the boundary: an allow-list of fields, and read decisions like "approved" via `Object.hasOwn` or from your own source, never from model arguments.

## Quiz

1. `routerA` returns `"false"` for `hasOwnProperty`, `routerB` throws `TypeError` for the same name. Both let the name through. What exactly differs?
   **Key:** in `routerA` the call `narzedzia[c.name](c.args)` has the object before the brackets, so `this === narzedzia`. In `routerB` the function is stored in `f` first and `f(args)` has nothing before a dot, so `this` is `undefined` and `hasOwnProperty` throws. Same function, different way of calling it.
2. Line 6 shows `__proto__` as an ordinary key after `JSON.parse`. Where in Round 2 does it stop being data, and what does that mean for `if (p.zatwierdzone) payOut()`?
   **Key:** in `Object.assign`, which assigns via the `__proto__` setter. `p2.zatwierdzone` becomes `true` by inheritance, the payout runs without a human, and logging `Object.keys(p2)` shows nothing suspicious.
3. With the registry stored in a `Map` instead of an object, what does `registry.has("toString")` return and why does that close the whole class of problem?
   **Key:** `false`. A `Map` contains only what was `set`, with no inherited keys. The object equivalent is `Object.create(null)` or always checking with `Object.hasOwn`.

## Card

**Front:** The model returned the tool name `"toString"`. What does `"toString" in tools` return, and what does `Object.hasOwn(tools, "toString")` return?
**Back:** `true` and `false`. `in` (and plain `obj[name]`) sees the whole prototype chain, and every plain object inherits `toString`, `constructor`, `hasOwnProperty`. Check a tool registry with `Object.hasOwn` or keep it in a `Map`. Also: a `"__proto__"` key from JSON swaps the target's prototype under `Object.assign`, but stays an ordinary key under spread.

## Takeaway

Tool calling is the most common form of structured output in job ads for integration roles, and its most dangerous line looks harmless: `if (name in tools)`. Tool names and arguments from a model are external input, exactly like an HTTP header. An automation engineer who wires an agent into a client's system is responsible for what that agent is able to call, not for what the model usually returns.
