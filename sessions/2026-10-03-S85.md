# S85 - Functions: closures decide which state a function shares

**Concept:** a function returned from a factory remembers the VARIABLES of the call that created it (a closure). Every call to the factory creates a new, separate state, so calling the factory inside a callback - or once per item in an n8n Code node - resets the state for every item. A field like `{ odrzucone }` in the returned object is a COPY of the number at the moment of `return`, not a window onto the variable; only a function or a getter reads it live. Second thread: a `function` declaration is hoisted whole, `var` is hoisted as `undefined`, and `const` is not usable at all before its line.

**Story:** an auto-parts wholesaler in Reykjavik collects offers from three webhooks into one n8n `Code` node and removes duplicates. The dashboard says "duplicates rejected: 0", while a customer receives the same offer three times. Then an AI assistant sends a PR titled "moved helpers to the bottom of the file, logic unchanged", and the node crashes on the first item.

## Round 1 - a filter factory and four ways to use it

```js
// Node `Code` w n8n ("Run Once for All Items"): dedupe ofert z trzech webhookow hurtowni "Varahlutir".
function zrobFiltr() {
  const widziane = new Set();
  let odrzucone = 0;
  function przepusc(id) {
    if (widziane.has(id)) { odrzucone++; return false; }
    widziane.add(id);
    return true;
  }
  return { przepusc, odrzucone, ile: () => odrzucone };
}

const items = [{ id: "K-7" }, { id: "K-9" }, { id: "K-7" }, { id: "K-7" }];

const f = zrobFiltr();
const A = items.filter((it) => f.przepusc(it.id)).map((it) => it.id);
console.log("1)", A.join(","), f.odrzucone, f.ile());

const B = items.filter((it) => zrobFiltr().przepusc(it.id)).map((it) => it.id);
console.log("2)", B.join(","));

const g = zrobFiltr();
const h = zrobFiltr();
g.przepusc("K-1");
h.przepusc("K-1");
console.log("3)", g.przepusc("K-1"), h.ile(), g.ile());

const { przepusc, ile } = zrobFiltr();
["X", "X", "Y"].forEach(przepusc);
console.log("4)", ile());
```

## Verified

Run with `node v22.22.0` and re-checked on node on the local machine before the answer key was written.

```
1) K-7,K-9 0 2
2) K-7,K-9,K-7,K-7
3) false 0 1
4) 1
5) K-7
6) TypeError: normalizujVar is not a function
7) ReferenceError: Cannot access 'normalizujConst' before initialization
8) K-9 K-9
```

Diagnosis: (a) `odrzucone` in the returned object was copied as a number (0) when the factory returned; `ile()` reads the closed-over variable on every call, and it has grown to 2. Line 2 creates a new filter for every item, so every item is "first" and all duplicates pass. (b) The PR description is false: the `function` declaration still works, the `var` one is `undefined` at call time (TypeError), the `const` one is in the temporal dead zone (ReferenceError). Fix: move the helper definitions back above their first use, or make them `function` declarations.

## Quiz

1. You switch the n8n Code node to "Run Once for Each Item", with `const f = zrobFiltr()` at the top. Why does dedupe stop working although the code did not change?
   **Key:** the node's code runs separately for every item, so `zrobFiltr()` builds a fresh, empty state per item (exactly line 2). Cross-item dedupe needs "Run Once for All Items" or state outside the node (`$getWorkflowStaticData`, a database).
2. How do you change `return { przepusc, odrzucone, ile }` so that `f.odrzucone` shows the current count without parentheses?
   **Key:** a getter: `return { przepusc, get odrzucone() { return odrzucone; } }` - every read calls the function and reads the variable live.
3. Why does `const { przepusc } = zrobFiltr()` work, while the same move with a method that relies on `this` would crash?
   **Key:** `przepusc` reaches its state through the closure (where it was created), not through `this` (how it was called). A method reading `this.widziane` called bare gets `this === undefined` and throws a TypeError.

## Card

**Front:** A factory returns `{ odrzucone, ile: () => odrzucone }` and the filter has already rejected 2 duplicates. What do `f.odrzucone` and `f.ile()` print?
**Back:** `0` and `2`. The field copied the NUMBER at `return`; `ile()` reads the closed-over VARIABLE on each call. Every factory call is a new, separate state, so calling it inside a loop or per item in n8n resets it. Live state = a function or a getter, never a copied field.

## Takeaway

In automation work the real question behind most duplicate bugs is "where does the state live": in a function's closure, in one run of a node, or outside the workflow. Asking "how many times will this factory be called?" catches the bug in review instead of in a customer complaint.
