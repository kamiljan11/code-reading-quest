# S87 - Loops: a "1:1 port from Python" that changes three loops

**Concept:** a loop in JS and in Python looks the same, but three rules differ. `for...of` over a plain object throws (Python iterates the keys of a dict), `break` inside `for...of` CLOSES a generator (in Python the generator stays open), and `var` in a loop is ONE variable shared by every callback, so callbacks that run later all see the final value (`let` creates a new binding per iteration). One rule is shared by both languages: an iterator stored in a variable is exhausted after a single pass.

**Story:** a hostel in Vik had a Python script for its daily bed report and check-in SMS messages. An AI assistant ported it to Node with the PR title "ported 1:1 from Python, logic unchanged". Since then the report crashes, one booking disappears from the follow-up list, and three SMS messages go out with no name.

## Round 1 - the bed report ported from Python

```js
// Port z Pythona (wymog #3 z Ledgera): raport lozek hostelu "Farfuglar" w Vik.
// PR od asystenta AI: "przepisane 1:1 z Pythona, logika bez zmian".
const lozka = { dorm: 6, prywatny: 2, rodzinny: 0 };

try {
  for (const typ of lozka) console.log(typ);      // Python: for typ in lozka:
} catch (e) {
  console.log("1)", e.name + ":", e.message);
}

const wolne = Object.entries(lozka).filter(([, n]) => n > 0);
const it = wolne.values();                         // Python: it = iter(wolne)
const pierwsze = [...it].map(([t]) => t);
const drugie = [...it].map(([t]) => t);
console.log("2)", pierwsze.join(","), "|", drugie.length);

function* rezerwacje() { yield "R-1"; yield "R-2"; yield "R-3"; }
const gen = rezerwacje();
for (const r of gen) { if (r === "R-2") break; }   // Python: for r in gen: if r == "R-2": break
console.log("3)", [...gen].length);                // Python: len(list(gen))

const m = new Map([["dorm", 6], ["prywatny", 2]]);
const wpisy = m.entries();
console.log("4)", [...wpisy].length, [...wpisy].length, [...m.entries()].length);
```

## Round 2 - check-in SMS messages sent "later"

```js
// Ten sam PR: SMS-y o zameldowaniu wysylane "pozniej" (Python: asyncio.create_task w petli).
const goscie = ["Anna", "Bjorn", "Chen"];
const wyslane = [];

for (var i = 0; i < goscie.length; i++) {
  setTimeout(() => wyslane.push(goscie[i]), 0);
}
for (let j = 0; j < goscie.length; j++) {
  setTimeout(() => wyslane.push(goscie[j]), 0);
}

setTimeout(() => {
  console.log("5)", wyslane.join(","));
  console.log("6)", i, typeof j);
}, 0);
console.log("7)", wyslane.length);
```

**Question:** write the seven output lines in the ORDER they appear (each round runs as its own file). Then: (a) which lines of the port behave differently from the Python original, and why; (b) which one-word change fixes the SMS messages.

## Verified

Run with `node v22.22.0` and re-checked with `node v24.21.0` on the local machine before the answer key was written. The Python side of the comparison was checked with Python 3.13.

```
1) TypeError: lozka is not iterable
2) dorm,prywatny | 0
3) 0
4) 2 0 2
7) 0
5) ,,,Anna,Bjorn,Chen
6) 3 undefined
```

Diagnosis: (a) Line 1: a plain object is not iterable, while Python iterates the keys of a dict (port: `Object.keys(lozka)`). Line 2 behaves exactly like Python: the iterator is used up by the first spread. Line 3: `break` in `for...of` calls `gen.return()` and closes the generator, so `R-3` is lost; in Python `list(gen)` after the `break` gives `['R-3']`. Line 4: `m.entries()` is a one-shot iterator, but calling `m.entries()` again creates a fresh one. (b) `var` -> `let`. With `var` there is one variable that equals `3` once the loop ends, and `goscie[3]` is `undefined` (`join` prints empty slots). `let` creates a new `j` for every iteration. Line 7 prints first because `setTimeout` only queues the callbacks.

## Quiz

1. How do you port Python's `for typ, n in lozka.items():` to JS so it works on a plain object?
   **Key:** `for (const [typ, n] of Object.entries(lozka))`. `Object.entries` returns an array of pairs, and arrays are iterable. Keys only: `Object.keys`, values only: `Object.values`.
2. Why does `[...m.entries()]` give 2 both times, while the second `[...wpisy]` gives 0?
   **Key:** every call to `m.entries()` creates a NEW iterator from the start. `wpisy` is a single iterator stored in a variable; the first spread ran it to the end, so nothing is left.
3. In Python `[lambda: i for i in range(3)]` gives `[2, 2, 2]`. Does Python have an equivalent of `let`, and how do you fix this in Python?
   **Key:** Python has no per-iteration binding (it behaves like `var`). Freeze the value instead: `lambda i=i: i` (the default is evaluated at definition time) or `functools.partial`. In JS, `let` is enough.

## Card

**Front:** What does `const it = arr.values(); [...it]; [...it].length` print, and what is left in a generator after `break` in `for...of`?
**Back:** `0`, and nothing. An iterator is exhausted after one pass (same as `iter()` in Python). `break` in `for...of` calls `return()` and CLOSES the generator, so the remaining values are lost (in Python the generator stays open after `break`). `for...of` over a plain object throws `TypeError`: iterate over `Object.entries/keys/values`.

## Takeaway

A lot of integration work is not writing Python, it is porting a Python script into a Node step of an automation tool. Asking at every loop "what does it iterate over, and how many times can it be iterated" catches lost records in review instead of in the client's report.
