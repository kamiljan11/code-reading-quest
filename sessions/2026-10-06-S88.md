# S88 - Arrays: an LLM scored four enquiries, and the report lost two of them

**Concept:** `map` calls its callback with THREE arguments (element, index, array), so `map(parseInt)` treats the index as the radix and returns `NaN`. `filter(Boolean)` drops every falsy value, including a valid score of `0`. `Array(3)` is three holes that `map` never visits, while `Array("3")` is an array with ONE element, `"3"`. `concat` flattens an array argument by one level and appends a string as a single element.

**Story:** a boat tour office in the Westman Islands sends every customer enquiry through a model that returns, as structured output, a score from 0 to 10, the number of seats needed and some tags. An AI assistant opened a PR titled "shorter score parsing, logic unchanged". Since then the daily report shows two enquiries fewer than the inbox, and a group of three got a booking for one seat.

## Round 1 - scores from the model after the "shorter parsing" PR

```js
// Biuro rejsow "Lundi" w Vestmannaeyjar: model ocenia 4 zapytania od klientow (structured output, JSON).
// PR od asystenta AI: "krotszy parsing ocen, logika bez zmian".
const odp = JSON.parse('{"oceny":["8","10","0","7"],"liczba":"3","tagi":"pilne"}');

console.log("1)", odp.oceny.map(parseInt));
console.log("2)", odp.oceny.map(Number).filter(Boolean));
console.log("3)", odp.oceny.map((s) => parseInt(s, 10)));
console.log("4)", Math.max(...odp.oceny), odp.oceny.sort().join(","), odp.oceny[1]);
```

## Round 2 - seats and tags from the model's response

```js
// Ten sam PR: sloty na rejs i tagi z odpowiedzi modelu.
const odp = JSON.parse('{"liczba":"3","tagi":"pilne","tagi2":["pilne","vip"],"tagi3":[["pilne"],"vip"]}');

const sloty = Array(odp.liczba);
console.log("5)", sloty.length, sloty);

const sloty2 = Array(Number(odp.liczba)).map((_, i) => `slot-${i}`);
console.log("6)", sloty2.length, sloty2[0]);

const sloty3 = Array.from({ length: Number(odp.liczba) }, (_, i) => `slot-${i}`);
console.log("7)", sloty3.join(","));

const tA = [].concat(odp.tagi);
const tB = [].concat(odp.tagi2);
const tC = [].concat(odp.tagi3);
console.log("8)", tA.length, tB.length, tC.length, Array.isArray(tC[0]), tC.flat().join("+"));
```

**Question:** write the eight output lines (each round runs as its own file). Then, as a reviewer: (a) which two enquiries did the report lose, and why did a "logic unchanged" PR cause it; (b) why does a group of three get one seat, and which single line fixes it.

## Verified

Run with `node v22.22.0` and re-checked with `node v24.21.0` on the local machine before the answer key was written.

```
1) [ 8, NaN, 0, NaN ]
2) [ 8, 10, 7 ]
3) [ 8, 10, 0, 7 ]
4) 10 0,10,7,8 10
5) 1 [ '3' ]
6) 3 undefined
7) slot-0,slot-1,slot-2
8) 1 2 2 true pilne+vip
```

Diagnosis: (a) `map(parseInt)` passes the index as the radix: `parseInt("10", 1)` and `parseInt("7", 3)` are `NaN`, so the enquiries scored 10 and 7 disappear. The `map(Number).filter(Boolean)` variant loses the score `0` instead, which is a valid value. Fix: `map((s) => parseInt(s, 10))` (line 3), or `map(Number)` without `filter(Boolean)`. Line 4: `Math.max` converts the strings to numbers (10), but `sort()` compares TEXT and also MUTATES `odp.oceny`. (b) The model returned the count as the string `"3"`, and `Array("3")` is an array with one element. Even `Array(3)` would not help, because it is three holes that `map` skips (line 6). Fix: `Array.from({ length: Number(odp.liczba) }, fn)` (line 7).

## Quiz

1. Why does `["1","1","1"].map(parseInt)` give `[1, NaN, 1]`?
   **Key:** `map` passes `(element, index)`. `parseInt("1", 0)`: 0 means the default radix 10, so 1. `parseInt("1", 1)`: radix 1 does not exist, so `NaN`. `parseInt("1", 2)`: "1" in binary is 1.
2. What is the difference between `Array(3).map(fn)` and `Array.from({ length: 3 }, fn)`?
   **Key:** `Array(3)` has three HOLES and `map` skips holes, so `fn` never runs. `Array.from` creates real `undefined` elements and calls `fn` for each of them.
3. The model returns tags sometimes as a string and sometimes as a list. How do you always get a flat list of strings?
   **Key:** `[].concat(x).flat()` or `Array.isArray(x) ? x.flat() : [x]`. `concat` flattens only one level, `flat()` handles the rest. Better still: require an array in the structured output schema and validate before use.

## Card

**Front:** What does `["8","10","0","7"].map(parseInt)` return, and what is left after `.map(Number).filter(Boolean)`?
**Back:** `[8, NaN, 0, NaN]`, because `map` passes the index as the second argument and `parseInt` reads it as the radix. After `filter(Boolean)` the score `0` is gone (falsy). Write `map((s) => parseInt(s, 10))` or `map(Number)`, and never filter numbers through `Boolean`.

## Takeaway

In integration code, structured output from a model usually meets one line of `map` or `filter`. Asking at every `map` how many arguments the callback receives, and at every `filter(Boolean)` whether zero is a valid value, catches lost records in review instead of in the client's report.
