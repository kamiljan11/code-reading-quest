# S90 - Reading a diff: "fewer allocations, logic unchanged", and the archive that got someone else's fields

**Concept:** a diff that replaces building a NEW object (`{ ...it.json, ... }`) with writing into the input object (`it.json.field = ...`) gives identical output for a single call, so the test passes. The behaviour changes for everyone else who still holds the same objects: a second branch of the workflow sees the added fields, and a retry on the same input runs `push` a second time. `map` always returns a new array, but not new objects. In the same PR, `[...out].sort` -> `out.sort` is harmless, because `out` came from `map`.

**Story:** a fish wholesaler in Grindavik prices its morning deliveries in an n8n `Code` node. An AI assistant opened a PR titled "refactor: fewer allocations, logic unchanged". Tests stayed green because the prices are identical. A week later accounting asks why the raw-deliveries archive has a `wartosc` field, and the warehouse asks why the cod is tagged "wycenione" twice. (Plain node simulation: both branches and the retry receive THE SAME item objects.)

## Round 1 - before and after the PR, one call

```js
// Hurtownia ryb "Fiskmarkadur" w Grindaviku: node `Code` w n8n wycenia dostawy.
// PR od asystenta AI: "refactor: mniej alokacji, logika bez zmian".
const wejscie = () => [
  { json: { id: "D-1", kg: 120, cenaKg: 900 } },
  { json: { id: "D-2", kg: 0, cenaKg: 1100 } },
  { json: { id: "D-3", kg: 45, cenaKg: 3000, tagi: ["dorsz"] } },
];

// - PRZED PR
function wycenA(items) {
  return items.map((it) => ({
    json: {
      ...it.json,
      wartosc: it.json.kg * it.json.cenaKg,
      tagi: [...(it.json.tagi ?? []), "wycenione"],
    },
  }));
}

// + PO PR
function wycenB(items) {
  return items.map((it) => {
    it.json.wartosc = it.json.kg * it.json.cenaKg;
    it.json.tagi = it.json.tagi ?? [];
    it.json.tagi.push("wycenione");
    return it;
  });
}

const a = wejscie();
const outA = wycenA(a);
console.log("1)", outA.map((it) => it.json.wartosc).join(","));
console.log("2)", a[0].json.wartosc, outA[0] === a[0]);

const b = wejscie();
const outB = wycenB(b);
console.log("3)", outB.map((it) => it.json.wartosc).join(","));
console.log("4)", b[0].json.wartosc, outB[0] === b[0], outB === b);
```

## Round 2 - a second branch and a retry on the same items (separate file)

```js
// Starcie 2 — ten sam workflow, dwie sytuacje z produkcji.
// (a) Te same items ida tez do drugiej galezi: "archiwum surowych dostaw" do ERP.
// (b) Node ma wlaczone "Retry On Fail": po bledzie API odpala sie drugi raz na TYCH SAMYCH items.
const wejscie = () => [
  { json: { id: "D-1", kg: 120, cenaKg: 900 } },
  { json: { id: "D-2", kg: 0, cenaKg: 1100 } },
  { json: { id: "D-3", kg: 45, cenaKg: 3000, tagi: ["dorsz"] } },
];
function wycenA(items) {
  return items.map((it) => ({
    json: { ...it.json, wartosc: it.json.kg * it.json.cenaKg, tagi: [...(it.json.tagi ?? []), "wycenione"] },
  }));
}
function wycenB(items) {
  return items.map((it) => {
    it.json.wartosc = it.json.kg * it.json.cenaKg;
    it.json.tagi = it.json.tagi ?? [];
    it.json.tagi.push("wycenione");
    return it;
  });
}
const archiwum = (items) => JSON.stringify(items[1].json);
const najdrozsza = (out) => out.sort((x, y) => y.json.wartosc - x.json.wartosc)[0].json.id; // PR: bylo [...out].sort(...)

for (const [nazwa, wycen, nr] of [["A", wycenA, 5], ["B", wycenB, 8]]) {
  const items = wejscie();
  wycen(items);                 // proba 1: API padlo po wycenie
  const out = wycen(items);     // proba 2 (retry) na tych samych items
  console.log(`${nr})`, nazwa, archiwum(items));
  console.log(`${nr + 1})`, nazwa, out[2].json.tagi.join(","));
  console.log(`${nr + 2})`, nazwa, najdrozsza(out), "| out:", out.map((it) => it.json.id).join(","), "| items:", items.map((it) => it.json.id).join(","));
}
```

**Question (format: what would change if...):** write the ten output lines (each round runs as its own file). Then: (a) what would change in lines 1-4 if the PR were reverted, and why could a single-call test never catch it; (b) which two effects of the PR only show up in Round 2, and which change in `wycenB` removes them; (c) does swapping `[...out].sort` for `out.sort` break anything?

## Verified

Run with `node v22.22.0` and re-checked with `node v24.21.0` on the local machine before the answer key was written.

```
1) 108000,0,135000
2) undefined false
3) 108000,0,135000
4) 108000 true false
```

```
5) A {"id":"D-2","kg":0,"cenaKg":1100}
6) A dorsz,wycenione
7) A D-3 | out: D-3,D-1,D-2 | items: D-1,D-2,D-3
8) B {"id":"D-2","kg":0,"cenaKg":1100,"wartosc":0,"tagi":["wycenione","wycenione"]}
9) B dorsz,wycenione,wycenione
10) B D-3 | out: D-3,D-1,D-2 | items: D-1,D-2,D-3
```

Diagnosis: (a) after reverting the PR, lines 1 and 3 stay the same and only line 4 changes, to `undefined false false`: a test that looks at one call's result sees the same numbers, the difference lives in what was left in the INPUT. (b) the archive branch receives `wartosc` and `tagi` that were never part of the delivery (line 8), and the retry adds `"wycenione"` a second time because `push` hits the same array (lines 8-9; version A starts from clean input on every call, so line 6 has a single tag). Fix: build a new object and a new `tagi` array again (`({ json: { ...it.json, wartosc, tagi: [...(it.json.tagi ?? []), "wycenione"] } })`); a spread without copying `tagi` would still share the array. (c) no: `map` returned a new array, so `out.sort` only reorders `out` and `items` stays `D-1,D-2,D-3` (lines 7 and 10). That is the one change in the PR that really is "fewer allocations, logic unchanged".

## Quiz

1. Why is `outB === b` false while `outB[0] === b[0]` is true?
   **Key:** `map` creates a new array, but the callback returned `it`, i.e. the same objects that sit in `b`.
2. What does a second workflow branch see if the node before it mutates `it.json`, and what if it builds a new object with spread?
   **Key:** with mutation it sees objects already changed by the first branch (as long as both get the same references); with spread it sees the original, because the first branch worked on new objects.
3. `{ ...it.json, tagi: [...it.json.tagi, "x"] }` versus `{ ...it.json }` followed by `kopia.tagi.push("x")`: which one changes the original and why?
   **Key:** the second: spread copies one level, so `kopia.tagi` is the same array as `it.json.tagi` and `push` changes the original. The first builds a new `tagi` array.

## Card

**Front:** Diff in an n8n `Code` node: `items.map(it => ({ json: { ...it.json, x: 1 } }))` -> `items.map(it => { it.json.x = 1; return it; })`. What changes?
**Back:** One call's output is the same, but the new version writes into the INPUT objects: whoever holds the same items (another branch, a retry) sees `x`, and any `push` into arrays repeats on every retry. `map` gives a new array, not new objects.

## Takeaway

Automation work means dozens of `Code` nodes that an AI assistant is happy to "optimise". Asking at every diff whether a line creates a new object or writes into someone else's, and what happens on the second run, catches in review the bug that otherwise shows up as mysterious fields in an archive.
