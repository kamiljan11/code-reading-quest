# S93 - Reading errors: one try around parsing and business logic, and a finally that ate a timeout

**Concept:** a `catch` does not know WHICH line threw: it catches everything inside the `try`. When `JSON.parse` and business logic share one `try`, a `TypeError` from our own price table gets the label "bad JSON from the model" and triggers a paid model retry that cannot fix anything. Meanwhile `"two" * 9900` is `NaN`, throws nothing, and a bad model answer passes as OK. `finally` always runs BEFORE the caller receives the result or the exception, and a `return` inside `finally` overrides both: the thrown error disappears without a trace.

**Story:** a whale-watching office in Husavik classifies customer emails with an LLM that returns structured JSON (intent + number of people). An AI assistant opened a PR: "one try around everything, simpler and safer", plus a wrapper that "always returns something so the workflow never stops". The next day the model bill tripled, one customer was quoted `NaN`, and a timed-out request came back as a question nobody asked. (Pure node simulation; the model is a stub.)

## Round 1 - one try for parsing and pricing

```js
// Biuro "Hvalaskodun" w Husaviku: klasyfikacja maili przez LLM (structured output).
// PR od asystenta AI: "jeden try na calosc, prosciej i bezpieczniej".
const CENNIK = { rezerwacja: { zaOsobe: 9900 }, zwrot: { zaOsobe: 0 } };

const odpowiedzi = [
  '{"intencja":"rezerwacja","osoby":4}',
  '```json\n{"intencja":"zwrot","osoby":2}\n```',
  '{"intencja":"pytanie","osoby":1}',
  '{"intencja":"rezerwacja","osoby":"dwie"}',
];

function przetworz(tekst) {
  try {
    const dane = JSON.parse(tekst);
    const kwota = dane.osoby * CENNIK[dane.intencja].zaOsobe;
    return `OK ${dane.intencja} ${kwota}`;
  } catch (e) {
    return `ZLY JSON -> ponow model (${e.name})`;
  }
}

odpowiedzi.forEach((t, i) => console.log(`${i + 1})`, przetworz(t)));
```

## Round 2 - the "always return something" wrapper (separate file)

```js
// Starcie 2 - osobny plik: wrapper "zawsze cos zwroc" od asystenta AI.
function zapytajModel(proba) {
  if (proba < 3) throw new Error(`timeout proba ${proba}`);
  return '{"intencja":"zwrot"}';
}

function bezpiecznie(proba) {
  try {
    return zapytajModel(proba);
  } catch (e) {
    throw new Error("model niedostepny", { cause: e });
  } finally {
    console.log(`   finally (proba ${proba})`);
    if (proba === 1) return '{"intencja":"pytanie"}'; // "zeby workflow sie nie zatrzymal"
  }
}

for (const p of [1, 2, 3]) {
  try {
    console.log(`${p + 4})`, bezpiecznie(p));
  } catch (e) {
    console.log(`${p + 4})`, "BLAD:", e.message, "<-", e.cause.message);
  }
}
```

## Verified

Run with `node v22.22.0` and re-checked with `node v24.21.0` on the local machine (each round as a separate file) before the answer key was written.

```
1) OK rezerwacja 39600
2) ZLY JSON -> ponow model (SyntaxError)
3) ZLY JSON -> ponow model (TypeError)
4) OK rezerwacja NaN
```

```
   finally (proba 1)
5) {"intencja":"pytanie"}
   finally (proba 2)
6) BLAD: model niedostepny <- timeout proba 2
   finally (proba 3)
7) {"intencja":"zwrot"}
```

Diagnosis: (a) only 2) is really bad JSON (a fenced ```json block); 3) is a `TypeError` from our own price table, which has no `pytanie` key, and retrying the model will never fix it. (b) 4): `"dwie" * 9900` is `NaN`, nothing throws. (c) the timeout from attempt 1 vanished: `return` in `finally` overrode the `throw` from `catch`, and the workflow received an invented intent. Note also that every `finally` line prints BEFORE the caller's numbered line. Fix: a narrow `try` around `JSON.parse` only, explicit checks (`Number.isInteger(dane.osoby)`, `Object.hasOwn(CENNIK, dane.intencja)`) before any arithmetic, and no `return` inside `finally`.

## Quiz

1. In `try { JSON.parse(t); x.y.z; } catch { log("bad JSON") }` the field `x.y` is undefined. What gets logged, and is it true?
   **Key:** "bad JSON", and it is false: the `TypeError` came from `x.y.z`. A catch does not tell lines apart; check `e.name` or narrow the try to the parse.
2. What does `function f(){ try { throw new Error("x") } finally { return 1 } }` return?
   **Key:** `1`. A `return` in `finally` swallows the exception.
3. Does `"dwie" * 9900` throw?
   **Key:** No, it is `NaN`. Types coming from a model must be validated explicitly; try/catch will not see this.

## Card

**Front:** One `try` around `JSON.parse` and business logic, and the `catch` logs "bad JSON, retry the model". What is wrong?
**Back:** The catch also catches `TypeError`s from our own code and pays for model retries that change nothing. Narrow the try to the parse, validate fields separately, check `e.name`.

## Takeaway

Structured output from an LLM is one of the most frequent requirements in automation job posts. Asking "which line could have thrown?" at every `catch` keeps you from paying for a thousand useless model calls because of one missing key in a price table, and from answering a question the customer never asked.
