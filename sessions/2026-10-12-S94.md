# S94 - Operators: short-circuit decides which steps of a RAG pipeline run at all

**Concept:** `||`, `??` and `&&` do not just compute a value, they decide whether the right-hand side RUNS. `||` runs it only when the left side is falsy (an empty array `[]` is truthy, `0` is falsy), `??` only for `null`/`undefined`, `&&` only when the left side is truthy, and `&&` binds tighter than `||`. Operands of ordinary operators (`+`, `>=`) are always all evaluated, left to right.

**Story:** a town hall in Akureyri runs a RAG assistant that answers residents' questions about regulations (cache -> search -> relevance threshold -> model). An AI assistant opened a PR: "shorter conditions, no logic change". Since then the assistant says "no information" about the deposit for council flats, although the regulation sits in the index, and the diagnostic mode `prog: 0` stopped showing anything extra. (Pure node simulation; the search engine is a plain object.)

## Round 1 - trace of pipeline steps (put in order of execution)

```js
// Asystent "Upplysingar" w urzedzie miasta Akureyri: RAG nad regulaminami.
// Kazdy krok pipeline'u loguje sie, zanim zwroci wynik.
let slad = [];
function krok(nazwa, wynik) { slad.push(nazwa); return wynik; }
function pokaz(nr, wynik) { console.log(`${nr})`, slad.join(" > "), "=>", JSON.stringify(wynik)); slad = []; }

pokaz(1, krok("cache", []) || krok("wektory", ["d1"]));
pokaz(2, krok("cache", null) ?? krok("wektory", ["d1"]));
pokaz(3, krok("score", 0) || krok("reranker", 0.4));
pokaz(4, krok("score", 0) ?? krok("reranker", 0.4));
pokaz(5, krok("filtrJezyk", false) && krok("filtrData", true) || krok("fallback", "ogolne"));
pokaz(6, krok("filtrJezyk", true) || krok("filtrData", false) && krok("fallback", "ogolne"));
pokaz(7, krok("bm25", 0.3) + krok("wektor", 0.4) >= krok("prog", 0.7));
```

## Round 2 - the "shorter conditions" PR (separate file)

```js
// Starcie 2 - osobny plik: PR od asystenta AI "krotsze warunki, logika bez zmian".
const CACHE = { kaucja: [] };          // wczoraj indeks lezal, zapisalo sie puste
const INDEKS = {
  kaucja:  [{ id: "K1", score: 0.92 }, { id: "K2", score: 0.41 }],
  parking: [{ id: "P1", score: 0.77 }, { id: "P2", score: null }],
};

function kontekst(pytanie, opcje = {}) {
  const kroki = [];
  const zCache = () => { kroki.push("cache"); return CACHE[pytanie]; };
  const zIndeksu = () => { kroki.push("indeks"); return INDEKS[pytanie] ?? []; };

  const docs = zCache() || zIndeksu();
  const prog = opcje.prog || 0.5;   // bylo: opcje.prog ?? 0.5
  const wybrane = docs.filter(d => d.score >= prog);
  return `${kroki.join(">")} | ${wybrane.map(d => d.id).join(",") || "BRAK"}`;
}

console.log("8)", kontekst("kaucja"));
console.log("9)", kontekst("parking"));
console.log("10)", kontekst("parking", { prog: 0 }));
```

## Verified

Run with `node v22.22.0` and re-checked with `node v24.21.0` on the local machine (each round as a separate file) before the answer key was written.

```
1) cache => []
2) cache > wektory => ["d1"]
3) score > reranker => 0.4
4) score => 0
5) filtrJezyk > fallback => "ogolne"
6) filtrJezyk => true
7) bm25 > wektor > prog => true
```

```
8) cache | BRAK
9) cache>indeks | P1
10) cache>indeks | P1
```

Diagnosis: (a) `CACHE.kaucja` is `[]`, and an empty array is truthy, so `zCache() || zIndeksu()` never asks the index; yesterday's empty result blocks the answer until the cache expires. (b) `0 || 0.5` is `0.5`, so the diagnostic `prog: 0` silently behaves like the default. (c) before the PR (`??`) line 10 printed `cache>indeks | P1,P2` (checked separately), but that was wrong too: `P2` has `score: null`, and `null >= 0` is `true` because relational operators coerce `null` to `0`. Fix: `const c = zCache(); const docs = c?.length ? c : zIndeksu();` (or never cache empty results), `prog = opcje.prog ?? 0.5`, and filter with `typeof d.score === "number" && d.score >= prog`.

## Quiz

1. In `cached || await search(q)`, does the search run when the cache returned `[]`?
   **Key:** No. `[]` is truthy, so `||` never evaluates the right side; check `.length`.
2. What is `opts.limit || 5` for `opts.limit = 0`, and what is `opts.limit ?? 5`?
   **Key:** `0 || 5` is `5`, `0 ?? 5` is `0`.
3. Which calls run in `a() || b() && c()` when `a()` returns `true`?
   **Key:** Only `a()`. It parses as `a() || (b() && c())`, and a truthy `a()` ends the expression.

## Card

**Front:** `const docs = fromCache() || fromIndex();` and the cache returned `[]`. Is the index queried?
**Back:** No. An empty array is truthy, so `||` never runs the right side. Check `.length` or do not cache empty results.

## Takeaway

RAG shows up in more and more automation job posts, and in an integrator's code it comes down to two lines: where the documents come from and which ones reach the model. Asking "can the left side be empty but still truthy?" at every `||` keeps an assistant from answering "I don't know" for a whole day while the answer sits in the index.
