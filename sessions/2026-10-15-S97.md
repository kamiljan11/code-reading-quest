# S97 - Reading a diff: a "1:1 port from Python" where `in`, `//`, `%` and `[-1]` look the same and compute something else

**Concept:** a line translated from Python to JS can look identical and behave differently. In JS `x in array` checks KEYS (indexes `"0"`, `"1"`... and prototype methods), not values, so `"VIP" in KODY` is `false` while `2 in KODY` is `true`. Python's `//` is `Math.floor`, not `Math.trunc` (they differ only for negatives). JS `%` takes the sign of the DIVIDEND (`-7 % 3` is `-1`, in Python `2`). `array[-1]` in JS is `undefined` (the last element is `.at(-1)`), and `Math.round(2.5)` is `3` while Python's `round(2.5)` is `2`.

**Story:** the "Hestaleiga Hella" horse farm sells three-hour rides. Group billing (splitting the amount per person, discount codes, refunds for cancelled rides) used to run as `rozlicz.py` from cron. The owner wants everything in one n8n workflow, so an AI assistant moved the script into a `Code` node and opened a PR: "1:1 port of rozlicz.py, no logic change". Every changed line carries its Python original in a comment and looks identical. Since then VIP guests pay full price, a refund is one krona smaller than the amount in the system, and the SMS to the customer says "last ride undefined". (Pure node simulation; amounts in ISK.)

## Round 1 - the same lines in two languages (predict the output)

```js
// Stadnina "Hestaleiga Hella": rozlicz.py przeniesiony do node Code w n8n (symulacja w czystym node).
// W komentarzach: co ta sama linia dawala w Pythonie.
const KODY = ["LATO", "VIP", "GRUPA"];
console.log("1)", "VIP" in KODY, 2 in KODY, "map" in KODY);      // py: "VIP" in KODY -> True
const zwrot = -7;                                                   // korona zwrotu na 2 i na 3 osoby
console.log("2)", Math.trunc(zwrot / 2), Math.floor(zwrot / 2), zwrot % 3);   // py: -7 // 2 -> -4, -7 % 3 -> 2
const tury = ["10:00", "13:00", "16:00"];
console.log("3)", tury[-1], tury.at(-1), tury.length);             // py: tury[-1] -> '16:00'
console.log("4)", Math.round(2.5), Math.round(-2.5), Math.round(3.5));   // py: round(2.5) -> 2, round(-2.5) -> -2, round(3.5) -> 4
```

## Round 2 - the "1:1 port of rozlicz.py" PR (separate file)

```js
// Starcie 2 - osobny plik: PR od asystenta AI "port 1:1 z rozlicz.py, logika bez zmian".
// Kwoty w koronach. Kod rabatowy = 1000 kr mniej. Reszta z dzielenia idzie do pierwszych osob.
const KODY = ["LATO", "VIP", "GRUPA"];

function przed(kwota, osoby, kod, tury) {
  const kw = KODY.includes(kod) ? kwota - 1000 : kwota;
  const baza = Math.floor(kw / osoby);
  const reszta = kw - baza * osoby;
  const czesci = Array(osoby).fill(baza);
  for (let i = 0; i < reszta; i++) czesci[i] += 1;
  const suma = czesci.reduce((a, b) => a + b, 0);
  return `${czesci.join("/")} = ${suma} | ostatnia tura ${tury.at(-1)}`;
}

function po(kwota, osoby, kod, tury) {
  const kw = kod in KODY ? kwota - 1000 : kwota;      // py: kod in KODY
  const baza = Math.trunc(kw / osoby);                // py: kw // osoby
  const reszta = kw % osoby;                          // py: kw % osoby
  const czesci = Array(osoby).fill(baza);
  for (let i = 0; i < reszta; i++) czesci[i] += 1;    // py: for i in range(reszta)
  const suma = czesci.reduce((a, b) => a + b, 0);
  return `${czesci.join("/")} = ${suma} | ostatnia tura ${tury[-1]}`;   // py: tury[-1]
}

const tury = ["10:00", "13:00", "16:00"];
console.log("5)", przed(10000, 3, "VIP", tury));
console.log("6)", po(10000, 3, "VIP", tury));
console.log("7)", przed(-1000, 3, "", tury));    // zwrot za odwolana ture
console.log("8)", po(-1000, 3, "", tury));
```

**Question:** give all eight output lines (each round as a separate file). Then: (a) which of the three changes in `po` matches `przed` for every positive amount, and which one breaks the result every time; (b) for which values of `kod` does `kod in KODY` return `true`; (c) why does `po(-1000, ...)` sum to `-999`, and what is the smallest fix.

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 8/8 lines identical. Python equivalents from the comments checked with python3 3.13.16 (`True -4 2 16:00 2 -2 4`).

```
1) false true true
2) -3 -4 -1
3) undefined 16:00 3
4) 3 -2 4
```

```
5) 3000/3000/3000 = 9000 | ostatnia tura 16:00
6) 3334/3333/3333 = 10000 | ostatnia tura undefined
7) -333/-333/-334 = -1000 | ostatnia tura 16:00
8) -333/-333/-333 = -999 | ostatnia tura undefined
```

Diagnosis: line 6: `"VIP" in KODY` looks for a key named "VIP" in the array, there is none, so the 1000 ISK discount is skipped and the group pays 10000 instead of 9000; `tury[-1]` reads a key "-1" that does not exist. Line 8: `Math.trunc(-333.3)` is `-333` and `-1000 % 3` is `-1`, so `for (i = 0; i < -1; ...)` never runs and one krona of the refund disappears; `przed` computes the remainder as `kw - baza * osoby` from `Math.floor`, which is always between 0 and `osoby - 1`. (a) `Math.trunc` + `%` match `przed` for every amount >= 0; `tury[-1]` breaks every time; `kod in KODY` breaks every real code. (b) Array keys: `"0"`, `"1"`, `"2"` (and numbers 0-2), `"length"`, and prototype names like `"map"` or `"includes"` (checked separately: `"VIP":false "LATO":false "0":true "2":true "3":false "length":true "includes":true 1:true`). (c) `przed`: floor gives `-334`, remainder `2`, the first two people get +1. `po`: trunc gives `-333`, remainder `-1`, zero iterations. Smallest fix: `Math.floor` and `((kw % osoby) + osoby) % osoby` (checked: `-333/-333/-334 = -1000`, `3334/3333/3333 = 10000`, `-3/-4 = -7`), plus `KODY.includes(kod)` and `tury.at(-1)`.

## Quiz

1. What does `"VIP" in ["LATO", "VIP"]` return in JS, and how do you check whether a value is in an array? (Key: `false`; `in` checks keys. Use `includes`.)
2. What is `-7 % 3` in JS, and in Python? (Key: JS `-1`, sign of the dividend; Python `2`, sign of the divisor.)
3. What does `tury[-1]` give in JS, and how do you get the last element? (Key: `undefined`; `tury.at(-1)` or `tury[tury.length - 1]`.)

## Card

**Front:** A diff replaces `KODY.includes(kod)` with `kod in KODY` and a comment "like in Python". What changes?
**Back:** Everything: in JS `in` checks array keys (`"0"`, `"1"`, `"length"`, `"map"`), not values. `"VIP" in ["VIP"]` is `false`. Only `includes` checks values.

## Takeaway

In automation work Python is often not written but moved: a cron script lands in an n8n `Code` node and an AI assistant translates it line by line. Asking at every `py:` comment "does this operator do the same thing, or does it only look the same?" catches a vanished discount and a missing krona in review instead of in a customer complaint.
