# S98 - Functions: `this` depends on HOW a function is called, not where it was written

**Concept:** in a regular function or method `this` is decided at CALL time. `w.sprawdz(x)` gets `this = w`, but the same method passed on as a value (`odp.map(w.sprawdz)`, `zRetry(klient.zapytaj)`) is called "bare" and loses its object. Inside a class (always strict) `this` is `undefined` and you get a TypeError; in a plain CommonJS file without `"use strict"` `this` is `globalThis` and the bug is SILENT (`model: undefined`, `proba: NaN`). An arrow function has no `this` of its own and takes it from where it was defined, so as a class field it saves you, and inside an object literal it does not.

**Story:** the "Silfra Dive" agency in Thingvellir gets dozens of emails a day: dive bookings, drysuit questions, date changes. An n8n workflow sends each email to a model, the model returns JSON with `intent` and `data`, and a validator in a `Code` node checks the fields before anything reaches the calendar. An AI assistant opened a PR: "shorter code: methods passed directly, no logic change". Instead of `(p) => klient.zapytaj(p)` it passes `klient.zapytaj` to the retry helper, and instead of `(o) => w.sprawdz(o)` it passes `w.sprawdz`. Since then one node crashes on the first email and the other one goes green and logs model responses as `undefined`. (Pure node simulation; `klient` stands in for the model client.)

## Round 1 - the validator as a class (predict the output)

```js
// Agencja nurkowa "Silfra Dive" w Thingvellir: walidator odpowiedzi modelu (structured output) w node Code.
class Walidator {
  constructor(wymagane) { this.wymagane = wymagane; }
  sprawdz(odp) { return this.wymagane.every((k) => k in odp); }
  sprawdzStrzalka = (odp) => this.wymagane.every((k) => k in odp);
}
const w = new Walidator(["intent", "data"]);
const odp = [{ intent: "rezerwacja", data: "2026-10-20" }, { intent: "pytanie" }];
console.log("1)", w.sprawdz(odp[0]), w.sprawdz(odp[1]));
console.log("2)", odp.map(w.sprawdzStrzalka));
try { odp.map(w.sprawdz); } catch (e) { console.log("3)", e.constructor.name, e.message); }
console.log("4)", odp.map(w.sprawdz, w), odp.map(w.sprawdz.bind(w)));
const luzem = w.sprawdz;
const inny = { wymagane: ["intent"], sprawdz: luzem };
console.log("5)", inny.sprawdz(odp[1]));
```

## Round 2 - the "methods passed directly" PR (separate file)

```js
// Starcie 2 - osobny plik: PR od asystenta AI "krotszy kod: metody przekazane bezposrednio, logika bez zmian".
// Symulacja w czystym node (plik CommonJS, bez "use strict").
const klient = {
  model: "claude-haiku",
  proby: 0,
  async zapytaj(prompt) {
    this.proby++;
    return { model: this.model, prompt, proba: this.proby };
  },
  zapytajStrzalka: async (prompt) => ({ model: this.model, prompt }),
};
async function zRetry(fn, arg) {
  return fn(arg);
}
(async () => {
  console.log("6)", await zRetry((p) => klient.zapytaj(p), "mail-1"));   // przed PR
  console.log("7)", await zRetry(klient.zapytaj, "mail-2"));              // po PR
  console.log("8)", klient.proby, globalThis.proby);
  console.log("9)", await klient.zapytajStrzalka("mail-3"));
  console.log("10)", await zRetry(klient.zapytaj.bind(klient), "mail-4"));
})();
```

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 10/10 lines identical. The strict variant from (b) was run separately on both.

```
1) true false
2) [ true, false ]
3) TypeError Cannot read properties of undefined (reading 'wymagane')
4) [ true, false ] [ true, false ]
5) true
```

```
6) { model: 'claude-haiku', prompt: 'mail-1', proba: 1 }
7) { model: undefined, prompt: 'mail-2', proba: NaN }
8) 1 NaN
9) { model: undefined, prompt: 'mail-3' }
10) { model: 'claude-haiku', prompt: 'mail-4', proba: 2 }
```

Diagnosis: line 3: `map` calls `sprawdz` with nothing before the dot, a class body is always strict, so `this` is `undefined` and `this.wymagane` throws. Line 5: the borrowed method runs on the fields of `inny` (which only requires `intent`), so a response without `data` passes as `true`: same function, different rule. Line 7: CommonJS file without strict mode, `fn(arg)` gives `this = globalThis`, `globalThis.proby++` turns `undefined` into `NaN`, the model is `undefined`, no exception, nothing for the retry to retry. Line 8: the client counter stays at 1 and the garbage lands on the global object. Line 9: an arrow in an object literal takes the module's `this`, not `klient`. With `"use strict";` at the top of Round 2, line 7 throws `TypeError: Cannot read properties of undefined (reading 'proby')` - better, because the failure is loud where it starts. Smallest fixes that keep the "shorter code": `klient.zapytaj.bind(klient)` (line 10) and `odp.map(w.sprawdz, w)` or `.bind(w)` (line 4), or turn the validator method into a class-field arrow like `sprawdzStrzalka` (line 2).

## Quiz

1. What is `this` in a class method passed to `map` without `bind`? (Key: `undefined`; classes are strict, the first `this.x` throws a TypeError.)
2. How does an arrow in a class field differ from an arrow in an object literal regarding `this`? (Key: class field: `this` from the constructor, the new object. Object literal: `this` from the surrounding scope, not the object.)
3. Two ways to pass `klient.zapytaj` to a helper without losing the object? (Key: `klient.zapytaj.bind(klient)` or `(p) => klient.zapytaj(p)`; for `map` also the `thisArg` argument.)

## Card

**Front:** A PR replaces `zRetry((p) => klient.zapytaj(p))` with `zRetry(klient.zapytaj)`. What changes?
**Back:** The method loses its object: `this` is `undefined` (strict, TypeError) or `globalThis` (sloppy, silent `undefined`/`NaN`). Fix: `.bind(klient)` or keep the arrow.

## Takeaway

A model client as an object, a retry helper, a schema validator and a `map` over responses is the everyday shape of LLM integration code. Asking at every method passed on as a value "what will be before the dot when someone finally calls it?" keeps `undefined` bookings out of the calendar and saves you from wondering why the retry never retries anything.
