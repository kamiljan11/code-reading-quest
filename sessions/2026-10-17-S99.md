# S99 - Objects: a key set to `undefined` EXISTS, and `JSON.stringify` pretends it does not

**Concept:** `{ jezyk: params.jezyk, dzial: params.dzial }` with no `dzial` parameter creates a key `dzial` whose value is `undefined`. The key exists: `"dzial" in f` is `true`, `Object.keys` counts it and `Object.entries` returns it, so a metadata filter built this way looks for documents WITHOUT a department instead of "any department". `JSON.stringify` silently drops the same key, so two different filters produce the same cache key and the second query gets someone else's results. `Object.freeze` only freezes the first level, and in a non-strict file a rejected write says nothing.

**Story:** a tourist office in Egilsstadir runs a RAG assistant called "Hraun". A visitor asks about hiking routes, an n8n workflow builds a metadata filter from the form fields (language, department), narrows the index and only then searches for similar passages. An AI assistant opened a PR: "frozen config + result cache, no logic change". The retriever config got `Object.freeze` and filter results are cached under `JSON.stringify(filtr)`. Since then English questions without a chosen department return one document instead of two, and the similarity threshold that "is frozen" was lowered to 0.2 by another node. (Pure node simulation, three documents instead of an index.)

## Round 1 - the metadata filter (predict the output)

```js
// Biuro turystyczne w Egilsstadir: asystent RAG "Hraun", filtr metadanych przed wyszukiwaniem w indeksie.
const docs = [
  { id: "D1", meta: { jezyk: "is", dzial: "trasy" } },
  { id: "D2", meta: { jezyk: "en", dzial: "trasy" } },
  { id: "D3", meta: { jezyk: "en" } },
];
const zbudujFiltr = (params) => ({ jezyk: params.jezyk, dzial: params.dzial });
const pasuje = (doc, filtr) => Object.entries(filtr).every(([k, v]) => doc.meta[k] === v);
const f1 = zbudujFiltr({ jezyk: "en" });
console.log("1)", Object.keys(f1).length, "dzial" in f1, JSON.stringify(f1));
console.log("2)", docs.filter((d) => pasuje(d, f1)).map((d) => d.id));
const f2 = Object.fromEntries(Object.entries(f1).filter(([, v]) => v !== undefined));
console.log("3)", docs.filter((d) => pasuje(d, f2)).map((d) => d.id));
console.log("4)", JSON.stringify(f1) === JSON.stringify(f2), f1 === f2);
const f3 = { ...f1 };
delete f3.dzial;
console.log("5)", Object.keys(f3), docs.filter((d) => pasuje(d, f3)).map((d) => d.id));
```

## Round 2 - the "frozen config + result cache" PR (separate file)

```js
// Starcie 2 - osobny plik: PR od asystenta AI "zamrozona konfiguracja + cache wynikow, logika bez zmian".
// Symulacja w czystym node (plik CommonJS, bez "use strict").
const docs = [
  { id: "D1", meta: { jezyk: "is", dzial: "trasy" } },
  { id: "D2", meta: { jezyk: "en", dzial: "trasy" } },
  { id: "D3", meta: { jezyk: "en" } },
];
const pasuje = (doc, filtr) => Object.entries(filtr).every(([k, v]) => doc.meta[k] === v);
const KONFIG = Object.freeze({ topK: 3, progi: { min: 0.7 }, zrodla: ["faq"] });
KONFIG.topK = 10;
KONFIG.progi.min = 0.2;
KONFIG.zrodla.push("blog");
console.log("6)", KONFIG.topK, KONFIG.progi.min, KONFIG.zrodla, Object.isFrozen(KONFIG), Object.isFrozen(KONFIG.progi));
const cache = {};
function szukaj(filtr) {
  const klucz = JSON.stringify(filtr);
  if (cache[klucz]) return "cache:" + cache[klucz].join(",");
  const wynik = docs.filter((d) => pasuje(d, filtr)).map((d) => d.id);
  cache[klucz] = wynik;
  return "indeks:" + wynik.join(",");
}
console.log("7)", szukaj({ jezyk: "en", dzial: undefined }));
console.log("8)", szukaj({ jezyk: "en" }));
console.log("9)", szukaj({ dzial: "trasy", jezyk: "en" }));
console.log("10)", szukaj({ jezyk: "en", dzial: "trasy" }), Object.keys(cache).length);
```

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 10/10 lines identical. The strict variant from the diagnosis was run separately.

```
1) 2 true {"jezyk":"en"}
2) [ 'D3' ]
3) [ 'D2', 'D3' ]
4) true false
5) [ 'jezyk' ] [ 'D2', 'D3' ]
```

```
6) 3 0.2 [ 'faq', 'blog' ] true false
7) indeks:D3
8) cache:D3
9) indeks:D2
10) indeks:D2 3
```

Diagnosis: line 1: the `dzial` key exists with the value `undefined` (2 keys, `in` is `true`), and `JSON.stringify` skips it. Line 2: `every` also checks `dzial`, and `undefined === undefined` holds only for D3 (a document with no department), so D2 drops out. Lines 3 and 5: removing the key (filtering by value or `delete`) gives the correct D2, D3. Line 4: two different filters, the same JSON. Line 6: the write to `topK` is rejected silently, while the nested `progi` and `zrodla` change even though `isFrozen(KONFIG)` is `true`. Lines 7-8: both filters map to the cache key `{"jezyk":"en"}`, so the second query receives the first one's (already wrong) result. Lines 9-10: the same filter with a different key order is a different JSON string, the cache misses and the index works twice (3 cache keys). With `"use strict";` at the top of Round 2, `KONFIG.topK = 10` throws `TypeError: Cannot assign to read only property 'topK' of object '#<Object>'` - better, because the failure is loud where it starts. Smallest fixes: build the filter only from keys that have a value (`Object.fromEntries(Object.entries(f).filter(([, v]) => v !== undefined))`, as in line 3), and compute the cache key from the sorted entries of the cleaned filter (`JSON.stringify(Object.entries(f).sort())`), which fixes 7-8 and 9-10 at once.

## Quiz

1. What do `Object.keys({ a: 1, b: undefined }).length` and `JSON.stringify({ a: 1, b: undefined })` return? (Key: `2` and `{"a":1}`; the key exists, JSON skips it.)
2. How does `delete f.dzial` differ from `f.dzial = undefined` for a loop over `Object.entries(f)`? (Key: `delete` removes the key, the loop never sees it; `= undefined` keeps it, and the loop gets `["dzial", undefined]` and compares against it.)
3. Does `Object.freeze(K)` protect `K.progi.min`? What happens to a rejected write in strict mode and without it? (Key: no, freeze is shallow. A write to a frozen field throws a TypeError in strict mode and is silently ignored otherwise.)

## Card

**Front:** Filter `{ jezyk: p.jezyk, dzial: p.dzial }` with no `p.dzial`: what does `Object.entries` see, and what does `JSON.stringify` see?
**Back:** `Object.entries` sees `["dzial", undefined]` (the filter now requires NO department); `JSON.stringify` skips it (same cache key as no department). Fix: do not write keys with `undefined`, or `delete` them.

## Takeaway

In integration code RAG rarely fails at the vector search itself. It fails just before it: at the metadata filter and at the cache. Asking "should this key exist at all?" before asking "what is its value?" for every object built from a form is the difference between a full list of routes and half of one.
