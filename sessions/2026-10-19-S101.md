# S101 - Operators and comparisons: every operator converts an HTTP header its own way

**Concept:** an HTTP header is always a string or `undefined`, and each operator converts it by its own rule. `!r` only asks whether the string is empty, so `"0"` is truthy. `==`, `>` and `<` convert to a number: `""` and `" 0 "` become 0, while `undefined` and `"brak"` become NaN, and NaN loses every comparison (it is neither `> 0` nor `<= 0`). `===` converts nothing. And `/` is not integer division, so `204 / 100 == 2` is `false`.

**Story:** a mountain-gear rental shop in Reykjavik syncs crampon and tent availability with six partners. Before each batch of requests, the API client (an n8n `Code` node) reads the `X-RateLimit-Remaining` header: wait at zero, send when it is positive. Every partner sends that header differently: `"0"`, `"12"`, an empty string, nothing at all, `" 0 "` with spaces, and one writes `"brak"` ("none"). An AI assistant opened a PR titled "shorter conditions in the API client, no logic change". Since then, 201 and 204 responses are logged as errors and the partner with an `"unlimited"` limit only ever gets "wait".

## Round 1 - six conditions on the same header (predict who passes each one)

```js
// Wypozyczalnia sprzetu "Fjallaleiga" w Reykjaviku: klient API partnerow czyta naglowek X-RateLimit-Remaining.
const partnerzy = [["A", "0"], ["B", "12"], ["C", ""], ["D", undefined], ["E", " 0 "], ["F", "brak"]];
const testy = [
  ["!r", (r) => !r],
  ["r == 0", (r) => r == 0],
  ["r === 0", (r) => r === 0],
  ["parseInt(r) === 0", (r) => parseInt(r) === 0],
  ["r > 0", (r) => r > 0],
  ["!(r > 0)", (r) => !(r > 0)],
];
testy.forEach(([nazwa, fn], i) => {
  const kto = partnerzy.filter(([, r]) => fn(r)).map(([p]) => p).join(",");
  console.log(`${i + 1})`, nazwa, "->", kto || "-");
});
```

## Round 2 - the "shorter conditions" PR (separate file, what would change)

```js
// Starcie 2 - osobny plik: PR od asystenta AI "krotsze warunki w kliencie API, logika bez zmian".
const odpowiedzi = [
  { id: "R1", status: 200, h: { "x-ratelimit-remaining": "3" } },
  { id: "R2", status: 201, h: { "x-ratelimit-remaining": "0" } },
  { id: "R3", status: 204, h: {} },
  { id: "R4", status: "200", h: { "x-ratelimit-remaining": "unlimited" } },
  { id: "R5", status: 302, h: { "x-ratelimit-remaining": "" } },
];
const przed = {
  ok: (o) => o.status >= 200 && o.status < 300,
  dalej: (o) => {
    const r = Number(o.h["x-ratelimit-remaining"] ?? NaN);
    return Number.isNaN(r) ? "ostroznie" : r > 0 ? "wysylaj" : "czekaj";
  },
};
const po = {
  ok: (o) => o.status / 100 == 2,
  dalej: (o) => (o.h["x-ratelimit-remaining"] > 0 ? "wysylaj" : "czekaj"),
};
const raport = (w) => odpowiedzi.map((o) => `${o.id}:${w.ok(o) ? "ok" : "blad"}/${w.dalej(o)}`).join(" ");
console.log("7)", raport(przed));
console.log("8)", raport(po));
const rozne = odpowiedzi.filter((o) => przed.ok(o) !== po.ok(o) || przed.dalej(o) !== po.dalej(o));
console.log("9)", rozne.map((o) => o.id).join(","));
const kody2xx = Array.from({ length: 100 }, (_, i) => 200 + i);
console.log("10)", kody2xx.filter((s) => po.ok({ status: s })).length, "z", kody2xx.length);
```

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 10/10 lines identical. The fix from the diagnosis was run separately.

```
1) !r -> C,D
2) r == 0 -> A,C,E
3) r === 0 -> -
4) parseInt(r) === 0 -> A,E
5) r > 0 -> B
6) !(r > 0) -> A,C,D,E,F
```

```
7) R1:ok/wysylaj R2:ok/czekaj R3:ok/ostroznie R4:ok/ostroznie R5:blad/czekaj
8) R1:ok/wysylaj R2:blad/czekaj R3:blad/czekaj R4:ok/czekaj R5:blad/czekaj
9) R2,R3,R4
10) 1 z 100
```

Diagnosis: line 1: the only falsy string is `""`, so partner A with a zero limit would not be stopped, while D (no header) would. Line 2: `==` converts to a number, `undefined == 0` is `false` (undefined only equals null). Line 3: `===` never converts. Line 4: `parseInt("")` is NaN, so C drops out although `==` let it in. Lines 5-6: NaN loses every comparison, so D and F are neither `> 0` nor `<= 0`; only `!(r > 0)` catches them together with the zeros. Line 8: `201 / 100` is 2.01 and `204 / 100` is 2.04, so both successes become errors; a missing header, `"unlimited"` and `""` all collapse into "wait". Line 10: of the whole 2xx family only 200 passes. The most dangerous change is R4: a partner with no limit never gets another batch, and in the log it looks like ordinary throttling. Fix: `const s = Number(o.status); s >= 200 && s < 300` (or `Math.trunc(s / 100) === 2`) and an explicit missing check, `raw == null || String(raw).trim() === "" ? NaN : Number(raw)`, keeping three outcomes (checked separately: `R1:ok/wysylaj R2:ok/czekaj R3:ok/ostroznie R4:ok/ostroznie R5:blad/ostroznie`, 100 of 100 2xx codes).

## Quiz

1. `X-RateLimit-Remaining` arrived as `"0"`. What does `if (!r)` do and why? (Key: `!"0"` is `false`, so the branch is skipped and the client sends despite a zero limit; any non-empty string is truthy. Convert with `Number(r)` first.)
2. What do `undefined > 0` and `!(undefined > 0)` return, and what does that mean for "wait unless limit > 0"? (Key: `false` and `true`; the client stops on every missing header and every non-numeric value, including a partner with no limit.)
3. Why does `status / 100 == 2` not check for the 2xx family, and how should it be written? (Key: `/` gives a fraction, 201 / 100 = 2.01, so only 200 passes; use `s >= 200 && s < 300` or `Math.trunc(s / 100) === 2`.)

## Card

**Front:** `X-RateLimit-Remaining` arrived as `"0"`. What do `!r` and `r == 0` give?
**Back:** `!r` is `false` (a non-empty string is truthy), `r == 0` is `true` (numeric conversion). A header is text: convert with `Number(r)` and check for NaN before comparing.

## Takeaway

REST work is mostly reading headers and status codes that always arrive as text, sometimes empty, sometimes missing. Asking "what will this operator convert it to" before reading the comparison is what keeps a partner with no limit from being throttled by `> 0`, and a 204 from turning into an error after one "shorter" division.
