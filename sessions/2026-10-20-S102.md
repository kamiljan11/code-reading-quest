# S102 - Loops: a line ported from Python looks the same and turns a different number of times

**Concept:** a loop ported from Python to JavaScript keeps its shape and changes its bounds. `for...in` over an object yields keys only, and destructuring `[k, v]` from a key string takes its first two characters. `map` with an index does not stop at the shorter list the way `zip` does. JavaScript has no `for...else`, so code placed under the loop also runs after `break`. An empty array is truthy, so `while (queue)` never ends on its own. `forEach` counts from 0, not from `start=1`. `range(1, n)` excludes `n`, and `range(len - 1, -1, -1)` starts at the last index, not at `length`.

**Story:** a network of mountain huts on the Laugavegur trail in Iceland assigns trekking groups to huts. Until yesterday a cron job ran `przydziel.py`. An AI assistant moved it into an n8n `Code` node with the PR description "1:1 port from Python, logic unchanged" and a `// py:` comment above every loop. Since then the free-beds report is unreadable, a group assigned to a hut is also left waiting in the queue, the nightly workflow spins until timeout, and the extra-night billing is too high. (Plain node simulation; the guard in the `while` loop exists only so the file terminates.)

## Round 1 - four loops with a `py:` comment (find the bug: which one does what Python does?)

```js
// Schroniska "Ferdafelag" na szlaku Laugavegur: port przydziel.py do node Code w n8n ("1:1 z Pythona, logika bez zmian").
const wolne = { Hrafntinnusker: 4, Alftavatn: 0, Emstrur: 6 };
const chaty = Object.keys(wolne);

// py: for chata, miejsca in wolne.items():
const raport = [];
for (const [chata, miejsca] in wolne) raport.push(`${chata}=${miejsca}`);
console.log("1)", raport.join(" "));

// py: for chata, jutro in zip(chaty, [2, 5]):
const jutro = [2, 5];
const pary = chaty.map((c, i) => `${c}:${jutro[i]}`);
console.log("2)", pary.length, pary.at(-1));

// py: for c in chaty: ... break / else: kolejka.append(grupa)
const kolejka = [];
function przydziel(grupa) {
  let gdzie = "-";
  for (const c of chaty) {
    if (wolne[c] >= grupa) { gdzie = c; break; }
  }
  // py: else:  (tylko gdy petla NIE trafila na break)
  kolejka.push(grupa);
  return gdzie;
}
console.log("3)", przydziel(5), przydziel(9), kolejka.join(","));

// py: while kolejka:
let obroty = 0;
while (kolejka) {
  kolejka.shift();
  obroty++;
  if (obroty === 5) break; // bezpiecznik symulacji, w Pythonie go nie ma
}
console.log("4)", obroty, kolejka.length);
```

## Round 2 - same PR, night billing (separate file)

```js
// Starcie 2 - osobny plik: ten sam PR, rozliczenie nocy (pierwsza noc w cenie, kazda kolejna 1500 ISK).
const grupy = [["G1", 2], ["G2", 3]]; // [id, noce]

// py: for nr, (gid, noce) in enumerate(grupy, start=1):
const linie = [];
grupy.forEach(([gid, noce], nr) => linie.push(`${nr}.${gid}`));
console.log("5)", linie.join(" "));

// py: for noc in range(1, noce): doplaty += 1500
let doplaty = 0;
for (const [, noce] of grupy) {
  for (let noc = 1; noc <= noce; noc++) doplaty += 1500;
}
console.log("6)", doplaty);

// py: for i in range(len(grupy) - 1, -1, -1):   (od konca)
const odKonca = [];
for (let i = grupy.length; i >= 0; i--) odKonca.push(grupy[i]?.[0] ?? "?");
console.log("7)", odKonca.join(","));
```

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 7/7 lines identical. The original Python script was run on python3 3.13.16 and 3.14.4; the fixes were run separately and reproduce the Python output.

```
1) H=r A=l E=m
2) 3 Emstrur:undefined
3) Emstrur - 5,9
4) 5 0
```

```
5) 0.G1 1.G2
6) 7500
7) ?,G2,G1
```

What the Python original prints: `1) Hrafntinnusker=4 Alftavatn=0 Emstrur=6` · `2) 2 Alftavatn:5` · `3) Emstrur - 9` · `4) 1 0` · `5) 1.G1 2.G2` · `6) 4500` · `7) G2,G1`.

Diagnosis: none of the seven lines matches Python. Line 1: `for...in` yields key strings and `[chata, miejsca]` destructures the string. Line 2: `map` walks all three huts, `jutro[2]` is `undefined`; `zip` stops at two. Line 3: `kolejka.push` sits under the loop and also runs after `break`, so group 5 is both placed and queued. Line 4: `[]` is truthy, so the loop would never end without the guard. Line 5: `forEach` index starts at 0. Line 6: `range(1, noce)` gives `noce - 1` turns (first night included), 1 + 2 = 3 charges = 4500; `noc <= noce` gives 2 + 3 = 5 charges = 7500. Line 7: starting at `length` reads one element past the end. Most dangerous in production: line 4 (a hung node) and line 3 (double assignment). Smallest fixes: `return c` inside the loop with `kolejka.push` below it (return replaces `else`), and `noc < noce`.

## Quiz

1. What ends up in `k` and `v` in `for (const [k, v] in { Emstrur: 6 })`, and how do you port Python's `d.items()` correctly? (Key: `k = "E"`, `v = "m"`: `for...in` yields the key as a string and array destructuring takes its characters. Use `for (const [k, v] of Object.entries(d))`.)
2. Python has `for ... else`. When does the `else` run, and how do you express it in JavaScript without a flag? (Key: only when the loop finishes without `break`. Put the loop in a function, use `return` instead of `break`, and place the `else` code below the loop.)
3. Why does `while (queue)` with an empty array not stop in JavaScript when `while queue:` stops in Python? (Key: in Python an empty list is falsy, in JavaScript every array, including `[]`, is truthy; write `while (queue.length > 0)`.)

## Card

**Front:** Python port: `while kolejka:` became `while (kolejka)`. What happens when the queue empties?
**Back:** The loop never ends: in JavaScript `[]` is truthy (in Python an empty list is falsy). Write `while (kolejka.length > 0)`.

## Takeaway

Python skills in automation roles often mean reading a Python script that was ported into an n8n `Code` node, not writing Python. Asking of every loop "what does it walk over, how many times will it turn, and should the code below it run after a `break`" catches the double booking before the nightly workflow hangs on an empty queue.
