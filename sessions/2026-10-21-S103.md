# S103 - Arrays: text that pretends to be an array

**Concept:** a field the schema calls `string[]` can come back from an LLM as a string or as `null`. A string has its own `length`, `includes` and iterator, so array code does not throw, it just computes something else. `typeof` returns `"object"` for an array and for `null`, so it cannot tell an array from nothing. `length` counts characters, `includes` searches for a substring, `for...of` walks letters, `new Array("2")` builds a one-element array `["2"]`, and `[].concat` and `flatMap` treat the whole string as a single element. The only reliable test is `Array.isArray`.

**Story:** a glacier-tour office in Skaftafell, Iceland, receives a few hundred emails overnight (refunds, weather cancellations, gear questions). An n8n workflow sends each email to a model and asks for JSON matching `{ "labels": string[], "count": number }`; a `Code` node validates the answer and routes the email to queues. An AI assistant shortened the validator with the PR description "shorter array validation, logic unchanged". In the morning the "other" queue holds thirteen entries from a single email, the report says an email without labels "has labels", and the check for the word "weather" only matches the broken answer. Not one error in the log. (Plain node simulation; the three model answers are hard-coded.)

## Round 1 - the validator after the PR (predict the output)

```js
// Biuro wypraw lodowcowych "Jokulferdir" w Skaftafell: klasyfikacja maili przez LLM, walidator structured output w node Code n8n.
// Schema: { "labels": string[], "count": number }. Trzy odpowiedzi modelu z jednej nocy:
const odp = [
  '{"labels": ["zwrot", "pogoda"], "count": 2}',
  '{"labels": "zwrot, pogoda", "count": "2"}',
  '{"labels": null, "count": 0}',
].map(s => JSON.parse(s));

// PR od asystenta AI: "krotsza walidacja tablic, logika bez zmian"
console.log("1)", odp.map(o => typeof o.labels === "object").join(" "));
console.log("2)", odp.map(o => o.labels?.length ?? 0).join(" "));
console.log("3)", odp.map(o => o.labels?.includes("pog") ?? false).join(" "));
console.log("4)", odp.map(o => new Array(o.count).length).join(" "));
```

## Round 2 - separate file: same PR, routing emails to queues

```js
// Starcie 2 - osobny plik: ten sam PR, routing maili do kolejek.
const odp = [
  { labels: ["zwrot", "pogoda"] },
  { labels: "zwrot, pogoda" },
  { labels: null },
];

console.log("5)", odp.map(o => [].concat(o.labels).length).join(" "));

const kolejki = { zwrot: 0, pogoda: 0, inne: 0 };
for (const o of odp) {
  for (const l of o.labels ?? []) kolejki[l in kolejki ? l : "inne"]++;
}
console.log("6)", Object.entries(kolejki).map(([k, v]) => `${k}=${v}`).join(" "));

const unikalne = new Set(odp.flatMap(o => o.labels ?? []));
console.log("7)", unikalne.size, [...unikalne].at(-1));
```

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 7/7 lines identical. The fix was run separately.

```
1) true false true
2) 2 13 0
3) false true false
4) 2 1 0
```

```
5) 2 1 1
6) zwrot=1 pogoda=1 inne=13
7) 3 zwrot, pogoda
```

Diagnosis: line 1 lets `null` through as an "object" and rejects the string. Line 2: 13 is the number of characters in `"zwrot, pogoda"`. Line 3: `includes` on an array compares whole elements (`"pog"` is not an element), on a string it searches for a substring, so the only `true` is the broken answer. Line 4: `new Array("2")` is `["2"]` (length 1), not two slots. Line 5: `[].concat` unpacks arrays only; the string and `null` each enter as one element. Line 6: `for...of` over the string walks 13 characters, none of them is a queue key, so "other" gets 13. Line 7: `flatMap` treats the string as one element, so the set holds three different "labels". Nothing throws because a string has `length`, `includes` and an iterator, and `?.` with `?? []` hid the `null`. Smallest fix: `Array.isArray(o.labels)` at the validator's entry (reject, or normalize with `split(",").map(s => s.trim()).filter(Boolean)`) and `Number.isInteger(o.count)`; after the fix `Array.isArray` gives `true false false` and the normalized lengths are `2 2 0`.

## Quiz

1. What do `typeof null` and `typeof []` return, and why does neither tell you whether the field is an array? (Key: both return `"object"`, a historical quirk for `null`; every object gives the same answer. Use `Array.isArray(x)`.)
2. What is `"zwrot, pogoda".length`, what does `"zwrot, pogoda".includes("pog")` return, and what does `["zwrot", "pogoda"].includes("pog")` return? (Key: `13`; `true`, substring search; `false`, the array compares whole elements.)
3. How does `new Array(2)` differ from `new Array("2")`? (Key: `new Array(2)` has length 2 with empty slots; `new Array("2")` is `["2"]`, because only a single NUMERIC argument means length.)

## Card

**Front:** The model returned `"labels": "zwrot, pogoda"` instead of an array. What does `labels.length` return, and how do you reliably check that the field is an array?
**Back:** `13` (characters, not labels). `typeof` returns `"object"` for `null` too, so the only test is `Array.isArray(labels)`.

## Takeaway

Structured output from an LLM is mostly about validating an answer that almost matches the schema. Asking of every `string[]` field "is this really an array" stops a string posing as a list before the "other" queue fills up with thirteen letters from one email.
