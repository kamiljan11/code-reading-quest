# S104 - Reading a diff: "parallel, logic unchanged" changes WHEN, not WHAT

**Concept:** a diff that turns a loop with `await` into `Promise.all(map(async ...))`, or drops an `await` in front of a call, does not change what the code does, only when it happens. Code before the first `await` runs for every element at once, so a "we already have k chunks" check (`break`/`return`) stops nothing; results land in the order of RESPONSES, not importance; and a function without `await` before a write logs "0" before the write has even happened.

**Story:** a tourist centre in Hofn, Iceland, runs a RAG assistant that builds its context from three indexes in order of importance: terms (refunds, weather cancellations), price list, FAQ. The model gets at most `k = 3` chunks. An AI assistant opened a PR: "parallel index queries and non-blocking logging, faster, logic unchanged". Tests pass (always three chunks, always a log entry). A week later a tourist asks about a refund for a cancelled glacier tour and gets the price list instead of the terms, the search bill grows by a third, and the observability panel shows answers without a logged question. (Pure node simulation; index latencies hard-coded with `setTimeout`.)

## Round 1 - before and after the PR: building the context (order of execution)

```js
// Asystent RAG "Thekking" w centrum turystycznym w Hofn: kontekst z trzech indeksow, PR "rownolegle zapytania, logika bez zmian".
const INDEKSY = [
  { nazwa: "regulamin", ms: 30, wyniki: ["R1"] },
  { nazwa: "cennik", ms: 10, wyniki: ["C1", "C2"] },
  { nazwa: "faq", ms: 20, wyniki: ["F1"] },
];
const szukaj = ix => new Promise(res => setTimeout(() => {
  console.log("  zapytanie:", ix.nazwa);
  res(ix.wyniki);
}, ix.ms));

// PRZED: indeksy po kolei, w kolejnosci waznosci, stop gdy jest k fragmentow
async function kontekstPrzed(k) {
  const out = [];
  for (const ix of INDEKSY) {
    if (out.length >= k) break;
    out.push(...await szukaj(ix));
  }
  return out;
}

// PO (PR): "szybciej, bo rownolegle; logika bez zmian"
async function kontekstPo(k) {
  const out = [];
  await Promise.all(INDEKSY.map(async ix => {
    if (out.length >= k) return;
    out.push(...await szukaj(ix));
  }));
  return out.slice(0, k);
}

(async () => {
  console.log("1)", (await kontekstPrzed(3)).join(","));
  console.log("2)", (await kontekstPo(3)).join(","));
})();
```

## Round 2 - separate file: same PR, query log without `await`

```js
// Starcie 2 - osobny plik: ten sam PR, log zapytan do bazy obserwowalnosci.
const zapis = [];
const zapiszLog = async wpis => { await null; zapis.push(wpis); };

// PRZED: await zapiszLog(...)
// PO (PR): zapiszLog(...) bez await, "zeby log nie blokowal odpowiedzi"
async function odpowiedz(pytanie) {
  console.log("3) start", pytanie);
  zapiszLog("pytanie: " + pytanie);
  const odp = await Promise.resolve("odp na " + pytanie);
  zapiszLog("odpowiedz: " + odp);
  console.log("4) zapis w chwili return:", zapis.length);
  return odp;
}

odpowiedz("godziny").then(o => console.log("5)", o, "| zapis:", zapis.length));
console.log("6) po wywolaniu, zapis:", zapis.length);
```

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 11/11 lines identical. The fix was run separately (`fix: R1,C1,C2`).

```
  zapytanie: regulamin
  zapytanie: cennik
1) R1,C1,C2
  zapytanie: cennik
  zapytanie: faq
  zapytanie: regulamin
2) C1,C2,F1
```

```
3) start godziny
6) po wywolaniu, zapis: 0
4) zapis w chwili return: 1
5) odp na godziny | zapis: 2
```

Diagnosis: before the PR the loop waits for each index, has 3 chunks after terms and price list, and `break` skips the FAQ (2 queries). After the PR `map` starts all three callbacks at once; each checks `out.length` at t=0 (zero) before any query returns, so all three run (3 queries, +50% cost). `push` appends in response order (price list 10 ms, FAQ 20 ms, terms 30 ms) and `slice(0, 3)` cuts the most important, slowest index. In Round 2 line `6)` prints before `4)` because the async function yields at its first `await`; at `return` only 1 of 2 log entries exists, and if `zapiszLog` throws nobody catches it (`unhandledRejection`). Smallest fix that keeps parallelism and order: `const wyniki = await Promise.all(INDEKSY.map(szukaj)); return wyniki.flat().slice(0, k);` because `Promise.all` keeps INPUT order. For the log: `await zapiszLog(...)` or `zapiszLog(...).catch(...)`.

## Quiz

1. In what order are the values in the array returned by `Promise.all`, and in what order do `push` calls inside `map(async ...)` callbacks append? (Key: `Promise.all` keeps input order regardless of who finished first; `push` appends in the order callbacks reach it, i.e. response order.)
2. What does a `console.log` right after calling an async function (that awaits inside) see, and why does it run before the second half of the function? (Key: the call returns a `Promise` immediately; the body runs synchronously up to the first `await`, the rest waits in the microtask queue, so the next line of the file runs first.)
3. What happens to an error thrown in an async function called without `await` and without `.catch`? (Key: the promise rejects with no handler: `unhandledRejection`, which crashes the process by default since Node 15; the caller never learns about it.)

## Card

**Front:** A PR replaced a `for...of` loop with `await` and `break` at k results with `Promise.all(list.map(async ...))` and `return` at k. What changes?
**Back:** The check runs at start for every element (`out` is empty), so ALL queries fire, and `push` orders results by response time. List order comes only from `Promise.all(list.map(search))` + `flat()`.

## Takeaway

RAG is not only retrieval, it is also the order and cost of the queries that build the context. When a diff says "parallel, logic unchanged", ask what used to be checked between the steps and who now decides the order of the chunks, before the refund terms drop out of the prompt.
