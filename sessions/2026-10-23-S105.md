# S105 - Functions: passing a function vs calling it

**Concept:** `f` is a function, `f()` is its RESULT, computed right there. Arguments are evaluated before the receiving function starts, so passing `send(order)` instead of `() => send(order)` to a retry helper, `.then` or `setTimeout` runs the work once, up front, and hands over a value instead of a recipe: the retry has nothing to repeat, `.then` silently ignores a non-function and passes the previous value through, and `setTimeout` throws `ERR_INVALID_ARG_TYPE`.

**Story:** a dairy in Selfoss, Iceland, sends shops' orders to a cold-chain carrier API from an n8n `Code` node. At 6 a.m. the API answers `503` twice before the third call goes through, so the node wraps every send in `zRetry(fn)`, which tries up to three times. An AI assistant opened a PR titled "shorter code, no needless arrow, logic unchanged" and removed `() =>` in three places. From that day order Z-2 never leaves, Z-3 leaves and is reported as a failure (so the dispatcher re-sends it by hand), and the daily report crashes the node.

## Round 1 - retry after the PR (order of execution)

```js
// Mleczarnia "Mjolka" w Selfoss: node Code w n8n wysyla zamowienia sklepow do API przewoznika.
// API przewoznika rano odpowiada 503, dopiero trzecie wywolanie przechodzi.
let wywolania = 0;
function wyslij(z) {
  wywolania++;
  if (wywolania < 3) throw new Error(`503 przy ${z.id}`);
  return `OK ${z.id} (wywolanie ${wywolania})`;
}

function zRetry(fn, max = 3) {
  for (let i = 1; i <= max; i++) {
    try {
      return fn();
    } catch (e) {
      console.log(`  retry ${i}: ${e.message}`);
    }
  }
  return "PORAZKA";
}

// Przed PR:
console.log("1)", zRetry(() => wyslij({ id: "Z-1" })));

// PR od asystenta AI: "krotszy kod, bez zbednej strzalki, logika bez zmian"
wywolania = 0;
try {
  console.log("2)", zRetry(wyslij({ id: "Z-2" })));
} catch (e) {
  console.log("2) wyjatek poza retry:", e.message);
}

wywolania = 2; // przewoznik juz "rozgrzany"
console.log("3)", zRetry(wyslij({ id: "Z-3" })), "| wywolania:", wywolania);
```

## Round 2 - separate file: same PR, batch list, confirmations and report

```js
// Starcie 2 - osobny plik: ten sam PR, lista partii, potwierdzenia i raport.
const log = (t) => {
  console.log("  log:", t);
  return t;
};

function dopisz(id, partia = []) {
  partia.push(id);
  return partia;
}
dopisz("Z-1");
console.log("4)", dopisz("Z-2").join(","));

Promise.resolve("potwierdzone Z-1")
  .then(log("wyslano Z-1"))
  .then((v) => console.log("5)", v));

try {
  setTimeout(log("raport"), 0);
} catch (e) {
  console.log("6)", e.code);
}
```

## Verified

Run as separate files on node v22.22.0 and v24.21.0 before writing the key, 13/13 lines identical. The fix was run separately (`fix: OK Z-2 (wywolanie 3)` after two retries).

```
  retry 1: 503 przy Z-1
  retry 2: 503 przy Z-1
1) OK Z-1 (wywolanie 3)
2) wyjatek poza retry: 503 przy Z-2
  retry 1: fn is not a function
  retry 2: fn is not a function
  retry 3: fn is not a function
3) PORAZKA | wywolania: 3
```

```
4) Z-2
  log: wyslano Z-1
  log: raport
6) ERR_INVALID_ARG_TYPE
5) potwierdzone Z-1
```

Diagnosis: arguments are evaluated before the call, so `wyslij({ id: "Z-2" })` runs once, throws `503`, and `zRetry` never starts; the error goes straight to the outer `try`. A retry protects only what it calls itself. Z-3 left EXACTLY once (`wywolania: 3`), but `zRetry` received the string `"OK Z-3 (wywolanie 3)"` instead of a function; `fn()` on a string throws `TypeError: fn is not a function`, which the retry catches like any other error, three times, and returns `"PORAZKA"` (failure). A dispatcher who trusts the report sends a duplicate delivery. In Round 2 `log("wyslano Z-1")` and `log("raport")` run synchronously while the arguments are evaluated; `.then` with a string registers nothing and passes `"potwierdzone Z-1"` on, and the only real callback (`5)`) waits in the microtask queue until the synchronous code ends. `setTimeout` with a string throws immediately. `4) Z-2` because the default `partia = []` is evaluated on EVERY call, unlike Python. Fix: `zRetry(() => wyslij(z))`, `.then(() => log("..."))`, `setTimeout(() => log("raport"), 0)`.

## Quiz

1. What is the difference between `zRetry(wyslij)`, `zRetry(wyslij(z))` and `zRetry(() => wyslij(z))`, and which one works for order `z`? (Key: the first calls `wyslij` with no argument, `z.id` throws; the second sends immediately and passes the result, or throws outside the retry; only the arrow works, because it is a new zero-argument function that calls `wyslij(z)` on EVERY attempt.)
2. What does `.then("text")` or `.then(undefined)` do with the previous promise's value? (Key: a non-function argument is ignored; the same value, or the same error, is passed through without any warning.)
3. In JS `function f(p = [])` gets a new array on every call without an argument. What about Python's `def f(p=[])`, and why does it matter when porting a script? (Key: Python evaluates the default ONCE, at definition, so one list is shared by all calls; a 1:1 port in either direction changes behaviour. Python idiom: `p=None` and `if p is None: p = []`.)

## Card

**Front:** A PR replaced `zRetry(() => wyslij(z))` with `zRetry(wyslij(z))`. What changes?
**Back:** `wyslij(z)` runs ONCE, before the retry. An error escapes the retry (zero retries); a success hands the retry a string instead of a function: `fn is not a function` x3 and `PORAZKA`, although the order went out. Pass functions without parentheses or wrapped in an arrow.

## Takeaway

Much of n8n work is retries, queues and callbacks inside `Code` nodes. Whoever checks for parentheses inside every `retry(...)`, `.then(...)` and `setTimeout(...)` catches the "no needless arrow" PR before the carrier receives the same order twice while the report says it never arrived.
