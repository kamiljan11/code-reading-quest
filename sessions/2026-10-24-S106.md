# S106 - Objects: Object.assign mutates its target

**Concept:** `Object.assign(target, source)` is not a shorter spread. It WRITES into its first argument and returns that same object. In an API client whose target is the shared `DEFAULTS`, every call leaves a trace for the next one: a limit from one request leaks into all of them, and a nested `headers` object is replaced as a whole, so `Authorization` disappears. Second thread: `new URLSearchParams(obj)` runs `String()` on every value, so `undefined` and `null` reach the API as the words `"undefined"` and `"null"`.

**Story:** a tour operator in Akureyri, Iceland, sells night-time jeep trips to see the northern lights. An n8n `Code` node talks to the jeep partner's API: a list of free cars with limit 5, a booking with an `Idempotency-Key` header, and a nightly report. An AI assistant opened a PR titled "Object.assign instead of spread, shorter, no logic change". From that night on, the partner rejects bookings with `401`, the report fetches 5 items instead of 20, and the search filter sends `do=undefined` to the API.

## Round 1 - API client after the PR (predict the output)

```js
// Biuro wycieczek "Nordurljos" w Akureyri: klient API partnera (rezerwacje jeepow na zorze).
// Wspolne ustawienia dla wszystkich zapytan do API partnera.
const DOMYSLNE = {
  baseUrl: "https://api.partner.is/v1",
  naglowki: { Accept: "application/json", Authorization: "Bearer T-1" },
  limit: 20,
};

// PR od asystenta AI: "Object.assign zamiast spreadu, krocej, logika bez zmian"
// Bylo: return { ...DOMYSLNE, ...opcje };
function zbuduj(opcje) {
  return Object.assign(DOMYSLNE, opcje);
}

const lista = zbuduj({ limit: 5 });
const rezerwacja = zbuduj({ naglowki: { "Idempotency-Key": "R-1" } });
console.log("1)", lista.limit, rezerwacja.limit, DOMYSLNE.limit);
console.log("2)", lista === rezerwacja, lista === DOMYSLNE);
console.log("3)", Object.keys(rezerwacja.naglowki).join(","));

const raport = zbuduj({});
console.log("4)", raport.limit, raport.naglowki.Authorization);
```

## Round 2 - separate file: form filter as a query string

```js
// Starcie 2 - osobny plik: filtr wyszukiwania z formularza zamieniony na query string.
const filtr = {
  od: "2026-11-01",
  do: undefined,
  strona: null,
  tagi: ["zorza", "jeep"],
  dorosli: 2,
};
console.log("5)", new URLSearchParams(filtr).toString());

const czyste = Object.fromEntries(
  Object.entries(filtr).filter(([, v]) => v != null)
);
console.log("6)", new URLSearchParams(czyste).toString());

const kopia = { ...filtr };
kopia.tagi.push("lodowiec");
console.log("7)", filtr.tagi.length, delete kopia.do, "do" in kopia, "do" in filtr);
```

## Verified

Run as separate files on node v22.23.4 and v24.21.0 before writing the key, 7/7 lines identical. The fix was run separately (`fix: 5 20 20 Accept,Authorization,Idempotency-Key Bearer T-1`).

```
1) 5 5 5
2) true true
3) Idempotency-Key
4) 5 undefined
```

```
5) od=2026-11-01&do=undefined&strona=null&tagi=zorza%2Cjeep&dorosli=2
6) od=2026-11-01&tagi=zorza%2Cjeep&dorosli=2
7) 3 true false true
```

Diagnosis: `Object.assign` writes into its first argument and returns it, so `lista`, `rezerwacja`, `raport` and `DOMYSLNE` are one object (`2) true true`); the limit 5 stays in the defaults forever. The booking replaced the WHOLE `naglowki` object (`3)`), and the report shares it, so both go out without `Authorization` (`4) 5 undefined`): the partner answers 401. The pre-PR spread does not mutate, but it would also drop `Authorization` for the booking, because spread merges shallowly. `URLSearchParams` stringifies every value; filtering `v != null` first (line 6) fixes it. Spread copies shallowly: `kopia.tagi` is the same array as `filtr.tagi`, so `push` shows in both, while `delete kopia.do` removes the key only from the copy. Fix: `return { ...DOMYSLNE, ...opcje, naglowki: { ...DOMYSLNE.naglowki, ...opcje.naglowki } };` with `opcje = {}` as the default.

## Quiz

1. What does `Object.assign(a, b)` return and what happens to `a`? How do you build a new object without touching `a`? (Key: it returns `a` itself, now permanently holding `b`'s fields; a new object: `Object.assign({}, a, b)` or `{ ...a, ...b }`.)
2. `{ ...DEFAULTS, ...{ headers: { X: 1 } } }`: what is left of `DEFAULTS.headers.Authorization` in the result? (Key: nothing; spread merges shallowly and the `headers` key on the right replaces the whole object. Merge one level down: `headers: { ...DEFAULTS.headers, ...opts.headers }`.)
3. What does `new URLSearchParams({ a: undefined, b: null, c: [1, 2] }).toString()` produce? (Key: `a=undefined&b=null&c=1%2C2`; every value goes through `String()`, so filter empty fields before building the query.)

## Card

**Front:** A PR replaced `return { ...DEFAULTS, ...opts }` with `return Object.assign(DEFAULTS, opts)`. What changes?
**Back:** `Object.assign` mutates its FIRST argument and returns it: every call modifies the shared defaults, all results are the same object, and a limit or headers from one request leak into the next. Copy: `Object.assign({}, DEFAULTS, opts)`.

## Takeaway

An API client is one settings object and ten places that use it. Whoever checks the first argument of every `Object.assign` and asks what happens to `undefined` in every query string catches this PR in review, before the partner starts rejecting bookings with 401 at 2 a.m.
