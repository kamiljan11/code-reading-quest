# S107 - Errors: Python shouts where JavaScript stays silent

**Concept:** when error handling is ported from Python to JavaScript, the `except` clauses lose their trigger. In Python a missing key raises `KeyError` and `int("two")` raises `ValueError`; in JavaScript the same places return `undefined` and `NaN` and throw nothing, so a `catch` that checks `e.name === "KeyError"` is dead code and bad values flow on as numbers. Second thread: Python's `else` block runs only after a clean `try` and its exceptions skip the `except` clauses; folding it into `try` gives a duplicate booking somebody else's error label. Third: `${e}` already prints `Name: message`, and the cause of an error goes in `new Error(msg, { cause: e })`, not `new Error(msg, e)`.

**Story:** a kayak rental in Stykkisholmur, Iceland, validates bookings from its form and from partners. For two years a `waliduj.py` script did this on a server; now it is being moved into an n8n `Code` node. An AI assistant opened a PR titled "1:1 port of waliduj.py, no logic change": `except KeyError` became `if (e.name === "KeyError")`, `int()` became `parseInt`, and the `else` block went inside `try` "because JS has no else on try". After the first weekend the database holds three bookings priced at `NaN`, and a customer who sent the same booking number twice was told "bad number".

## Round 1 - validation after the PR (find the bug)

```js
// Wypozyczalnia kajakow "Kajakaleiga" w Stykkisholmur: walidacja rezerwacji w node Code.
// Oryginal waliduj.py (Python):
//   try:
//       osoby = int(r["osoby"])
//       cena = CENNIK[r["typ"]] * osoby
//   except KeyError as e:   return f"BRAK POLA {e}"
//   except ValueError:      return "ZLA LICZBA"
//   else:
//       zapisz(r["id"], cena)
//       return f"OK {cena}"
const CENNIK = { pojedynczy: 9000, podwojny: 14000 };
const zapisane = [];
function zapisz(id, cena) {
  if (zapisane.includes(id)) throw new Error(`duplikat ${id}`);
  zapisane.push(id);
}

// PR od asystenta AI: "port 1:1 z waliduj.py, logika bez zmian"
function waliduj(r) {
  try {
    const osoby = parseInt(r.osoby);
    const cena = CENNIK[r.typ] * osoby;
    zapisz(r.id, cena);
    return `OK ${cena}`;
  } catch (e) {
    if (e.name === "KeyError") return `BRAK POLA ${e.message}`;
    return "ZLA LICZBA";
  }
}

console.log("1)", waliduj({ id: "K1", typ: "pojedynczy", osoby: "2" }));
console.log("2)", waliduj({ id: "K2", typ: "pojedynczy" }));
console.log("3)", waliduj({ id: "K3", typ: "trojka", osoby: "3" }));
console.log("4)", waliduj({ id: "K4", typ: "podwojny", osoby: "dwie" }));
console.log("5)", waliduj({ id: "K1", typ: "podwojny", osoby: "1" }));
console.log("6)", zapisane.join(","));
```

## Round 2 - separate file: error logging ported from Python

```js
// Starcie 2 - osobny plik: logowanie bledow przeniesione z Pythona.
// Python: log(f"{type(e).__name__}: {e}")   oraz   raise RuntimeError("import") from e
function log(nr, e) {
  console.log(nr, `${e.constructor.name}: ${e}`);
}

try { JSON.parse("{'id': 'K7'}"); } catch (e) { log("7)", e); }
try { const r = null; r.id; } catch (e) { log("8)", e); }

try {
  try { JSON.parse(""); }
  catch (e) { throw new Error("import", e); }
} catch (e2) {
  console.log("9)", e2.message, e2.cause === undefined);
}

try { throw "timeout"; } catch (e) { console.log("10)", typeof e, e.message); }
```

## Verified

Run with node v22.23.4 and v24.21.0, each round as a separate file, before the key was written. The Python original (python3 3.13.18 and 3.14.4) prints `1) OK 18000`, `2) BRAK POLA 'osoby'`, `3) BRAK POLA 'trojka'`, `4) ZLA LICZBA`, an unhandled `Exception: duplikat K1` and `6) K1`.

```
1) OK 18000
2) OK NaN
3) OK NaN
4) OK NaN
5) ZLA LICZBA
6) K1,K2,K3,K4
```

```
7) SyntaxError: SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)
8) TypeError: TypeError: Cannot read properties of null (reading 'id')
9) import true
10) string undefined
```

Diagnosis: lines 2-5 take a different path than `waliduj.py`. The Python original prints `2) BRAK POLA 'osoby'`, `3) BRAK POLA 'trojka'`, `4) ZLA LICZBA`, raises an unhandled `Exception: duplikat K1` at line 5 and saves only `K1`. In JavaScript nothing in lines 2-4 throws: a missing key is `undefined`, `parseInt("dwie")` is `NaN`, and multiplying by `undefined` is `NaN`, so the code goes straight to `return` and K2, K3 and K4 are saved with price `NaN`. The `KeyError` branch can never run. Because `zapisz` moved from Python's `else` into `try`, the duplicate is caught and labelled "ZLA LICZBA". `${e}` calls `e.toString()`, which already starts with the error name, so the log prints it twice. `new Error("import", e)` treats the second argument as options; a SyntaxError has no `cause` field, so the cause is lost. `throw "timeout"` throws a bare string with no `message`. Fix: explicit checks before computing (`"osoby" in r`, `Object.hasOwn(CENNIK, r.typ)`, `Number.isInteger(Number(r.osoby))`), `zapisz` outside `try`, `String(e)` or `e.message` in the log, and `new Error("import", { cause: e })`.

## Quiz

1. What do you get in JavaScript for `obj.missing`, `parseInt("two")` and `undefined * 3`, and what in Python for `d["missing"]` and `int("two")`? (Key: JS gives `undefined`, `NaN`, `NaN` with no exception; Python raises `KeyError` and `ValueError`. In JS check explicitly with `in` / `Object.hasOwn` and `Number.isInteger`.)
2. What is the `else` block in Python's `try/except/else` for, and how do you express it in JavaScript? (Key: it runs only when `try` raised nothing, and its own exceptions do not reach those `except` clauses. In JS the success code goes AFTER the `try/catch`, not inside `try`.)
3. How do you write Python's `raise RuntimeError("import") from e` in JavaScript without losing the cause? (Key: `throw new Error("import", { cause: e })`; the second argument is an options object with a `cause` key, not the error itself.)

## Card

**Front:** Python's `except KeyError` ported to a JavaScript `catch`. What does it catch when a field is missing?
**Back:** Nothing: in JS a missing key is `undefined`, and `parseInt` and arithmetic give `NaN`, with no exception. Check for missing data explicitly (`in`, `Object.hasOwn`, `Number.isInteger`) and keep the code from Python's `else` outside `try`.

## Takeaway

Porting scripts between Python and an n8n `Code` node is everyday integration work, and error handling ports worst, because Python shouts where JavaScript stays silent. Whoever asks "does JS even throw here?" at every `except` stops the PR before bookings priced at NaN reach the database.
