# S108 - Operators: a model field that came back as text

**Concept:** a field the schema calls `boolean` or `number` can come back from the model as a string, and every operator converts a string its own way. `if (x)` only asks whether the string is empty, so `"false"` is truthy. `x == true` turns both sides into numbers, so `"true"` becomes `NaN` (not equal) while `"1"` becomes `1` (equal). `>=` and `<` turn `null` into `0` and `"95%"` into `NaN`. A "shorter condition" without a type check changes the decision, not just the code.

**Story:** a veterinary clinic in Borgarnes, Iceland, gets messages from pet owners. A model classifies each one into `{ pilne, pewnosc }` (urgent, confidence) and an n8n `Code` node decides: call the on-duty vet (TELEFON), urgent SMS, automatic template reply (AUTO), morning queue (KOLEJKA) or a human at reception (CZLOWIEK). The old version checked types first. An AI assistant opened a PR titled "shorter conditions, logic unchanged". After the weekend the on-duty vet got a night call about a kitten the model had marked as NOT urgent, and a message with no confidence value got an automatic "see you on Monday".

## Round 1 - decision after the PR (what would change if)

```js
// Przychodnia weterynaryjna "Dyralaeknir" w Borgarnes: triaz wiadomosci po klasyfikacji modelu (node Code).
// Model ma zwracac JSON wg schemy: { pilne: boolean, pewnosc: number 0..1 }
// Przed PR: najpierw typy (pilne musi byc boolean, pewnosc liczba, inaczej "CZLOWIEK"), potem o.pilne === true.
// PR od asystenta AI: "krotsze warunki, logika bez zmian"
function decyzja(o) {
  if (o.pilne == true) return "TELEFON";
  if (o.pilne) return "PILNE-SMS";
  if (o.pewnosc >= 0.8) return "AUTO";
  if (o.pewnosc < 0.8) return "KOLEJKA";
  return "CZLOWIEK";
}

console.log("1)", decyzja({ pilne: true, pewnosc: 0.95 }));
console.log("2)", decyzja({ pilne: "true", pewnosc: 0.9 }));
console.log("3)", decyzja({ pilne: "false", pewnosc: 0.3 }));
console.log("4)", decyzja({ pilne: false, pewnosc: "95%" }));
console.log("5)", decyzja({ pilne: 0, pewnosc: "0.85" }));
console.log("6)", decyzja({ pilne: "1", pewnosc: 0.5 }));
console.log("7)", decyzja({ pilne: false, pewnosc: null }));
console.log("8)", decyzja({ pilne: false }));
```

## Verified

Run with node v22.23.4 and v24.21.0, each round as a separate file, before the key was written.

```
1) TELEFON
2) PILNE-SMS
3) PILNE-SMS
4) CZLOWIEK
5) AUTO
6) TELEFON
7) KOLEJKA
8) CZLOWIEK
```

```
9) false true true -1
10) true false 0.95
11) false true true
12) true true true false
```

Diagnosis: the version before the PR (types first, then `=== true`) gives `TELEFON` for line 1 and `CZLOWIEK` for lines 2-8, so the decision changes in lines 2, 3, 5, 6 and 7. Lines 4 and 8 agree only by accident: `NaN` loses both comparisons and the code falls through to the last `return`. `"false"` is a non-empty string, so `if (o.pilne)` is true. `==` between a string and a boolean converts both to numbers: `true` is `1`, `"true"` is `NaN`, `"1"` is `1`. `null < 0.8` is `0 < 0.8`, so a record without confidence lands in the queue as "low confidence", while a missing field is `undefined`, then `NaN`, and falls through to a human. `parseFloat("95%")` gives `95`, a 0-100 scale instead of 0-1. The fix checks `typeof o.pilne === "boolean"` and `Number.isFinite(o.pewnosc)` first; on ten inputs (the eight above plus two valid ones) it prints `TELEFON CZLOWIEK CZLOWIEK CZLOWIEK CZLOWIEK CZLOWIEK CZLOWIEK CZLOWIEK AUTO KOLEJKA`.

## Quiz

1. What do `if ("false")`, `"false" == false` and `JSON.parse("false") == false` give, and why are the three answers not contradictory? (Key: the `if` runs, because a non-empty string is truthy; `"false" == false` is `false` (`NaN` vs `0`); `JSON.parse("false") == false` is `true`, because it is already a boolean. Each operator converts types its own way.)
2. Why is `null < 0.8` true while `undefined < 0.8` is false, and what does that do to a record without confidence? (Key: relational comparison turns `null` into `0` and `undefined` into `NaN`, and every comparison with `NaN` is false. The record goes to the "low confidence" branch instead of to a human.)
3. How do you check in one line that `pewnosc` from the model is a real number (not text, not `null`, not `NaN`)? (Key: `typeof x === "number" && Number.isFinite(x)`, or just `Number.isFinite(x)`, which is false for strings, `null` and `NaN`.)

## Card

**Front:** The model returned `"pilne": "false"` (a string). What does `if (o.pilne)` do, and what does `o.pilne == true` give?
**Back:** The `if` runs, because a non-empty string is truthy. `== true` gives `false`, because `"false"` becomes `NaN` and `true` becomes `1`. Check model fields with `typeof o.pilne === "boolean"` and compare with `=== true`.

## Takeaway

Structured output from an LLM shows up in most integration job ads, and in practice it means every field from the model is suspect until the code checks its type. Whoever asks "what type will this operator convert it to?" at every condition stops the PR before the string `"false"` wakes up the on-duty vet at three in the morning.
