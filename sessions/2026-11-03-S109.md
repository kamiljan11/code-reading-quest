# S109 - Loops: loop boundaries in a RAG pipeline

**Concept:** a `for` condition is checked before every iteration, on the data as it is right now. Moving the bound from `i < t.length` to `i + size < t.length` drops the last chunk of the text (and a document shorter than one chunk entirely), `splice` inside a forward loop skips the item right after the removed one and mutates the input, `for...in` over an array gives string keys (`"0" + 1` is `"01"`) plus any extra property added to the array, and a labelled `continue` skips the rest of the whole outer item.

**Story:** a ferry port in Seydisfjordur, Iceland, runs a RAG assistant that answers passengers from the ferry rules (pets, luggage, campervans). An n8n `Code` node cuts the rules into overlapping chunks, drops hits scoring below 0.5 and builds the context with numbered sources `[1] [2]...` that the model cites. An AI assistant opened a PR "shorter loops in the RAG pipeline, no logic change". A week later a passenger with a dog got an answer without the paragraph about cages (it was at the end of the rules), the model cited source `[11]`, which does not exist, and a hit scoring 0.3 sat in the context.

## Round 1 - pipeline after the PR (predict the output)

```js
// Asystent RAG "Ferjuvakt" w porcie promowym w Seydisfjordur: odpowiada pasazerom na podstawie regulaminu.
// Pipeline: pociac regulamin na okna z zakladka -> odrzucic slabe trafienia -> zbudowac kontekst z numerami zrodel.
// Przed PR: petla "i < t.length" z break po ostatnim oknie, filter(w => w.score >= prog), for...of z licznikiem od 1.
// PR od asystenta AI: "krotsze petle w pipeline RAG, logika bez zmian"
function chunkuj(t, rozmiar, zakladka) {
  const out = [];
  for (let i = 0; i + rozmiar < t.length; i += rozmiar - zakladka) {
    out.push(t.slice(i, i + rozmiar));
  }
  return out;
}
function odfiltruj(wyniki, prog) {
  for (let i = 0; i < wyniki.length; i++) {
    if (wyniki[i].score < prog) wyniki.splice(i, 1);
  }
  return wyniki;
}
function kontekst(fragmenty) {
  let ctx = "";
  for (const i in fragmenty) ctx += `[${i + 1}] ${fragmenty[i].id} `;
  return ctx.trim();
}

console.log("1)", chunkuj("ABCDEFGHIJ", 4, 1).join("|"));
console.log("2)", chunkuj("ABCDEFG", 4, 1));
console.log("3)", chunkuj("ABC", 4, 1).length);

const wyniki = [
  { id: "R1", score: 0.9 }, { id: "R2", score: 0.4 }, { id: "R3", score: 0.3 },
  { id: "R4", score: 0.8 }, { id: "R5", score: 0.2 },
```

## Verified

Run with node v22.23.4 and v24.21.0, each round as a separate file, before the key was written.

```
1) ABCD|DEFG
2) [ 'ABCD' ]
3) 0
4) R1,R3,R4
5) 3 true
6) [01] R1 [11] R3 [21] R4
7) [01] R1 [11] R3 [21] R4 [zrodlo1] undefined
```

```
8) 4 0.7999999999999999 false
9) ABD B
10) 7 6 6
11) 5 prom++++
```

Diagnosis: `i + size < t.length` only lets through chunks that end before the end of the text, so the chunk that reaches the end never gets in (`GHIJ` in line 1, `DEFG` in line 2), and `"ABC"` fails the condition at `i = 0`, so the loop body never runs (line 3). After `splice` removes R2, R3 slides into index 1 while the loop moves on to index 2, so R3 (0.3) is never checked, and `wyniki` itself now has 3 items and is the same object as the result (line 5). `for...in` gives `"0"`, `"1"`, `"2"` as strings, so `i + 1` concatenates, and it also visits the added `zrodlo` key (line 7). In round 2, `0.1` has no exact binary form, so the last threshold is `0.7999999999999999`; `continue zewn` ends the whole outer iteration at the duplicate `B`, so `C` is lost; `.length` counts UTF-16 units (the ship emoji is 2) while `for...of` counts characters; and the loop over `zapytania` re-reads the growing length each time, so only `i < 4` stops it.

Fix (the version before the PR), run separately on both node versions:

```
fix: ABCD|DEFG|GHIJ / ABCD|DEFG / ABC / R1,R4 5 / [1] R1 [2] R4
```

## Quiz

1. Why does `for (let i = 0; i + size < t.length; i += step)` return no chunk at all for a text shorter than `size`, and how do you fix it? (Key: the condition is checked before the first iteration and `0 + 4 < 3` is false. Use `i < t.length` and `break` after the chunk that reaches the end.)
2. What does `splice(i, 1)` in a forward `for` loop do to the item right after the removed one? Name two safe alternatives. (Key: it slides into index `i` and `i++` skips it. Use `filter` or loop from the end.)
3. What type is `i` in `for (const i in array)` and what else does the loop visit? (Key: a string, so `i + 1` concatenates; it also visits any other enumerable property on the array. Use `for...of` or `entries()`.)

## Card

**Front:** `for (let i = 0; i < a.length; i++) if (bad(a[i])) a.splice(i, 1);` - what is wrong?
**Back:** After `splice` the next item slides into index `i` and `i++` skips it, so of two bad items next to each other the second stays. The loop also mutates the input. Use `a.filter(x => !bad(x))` or loop from the end.

## Takeaway

RAG shows up in a steady share of AI integration job ads, and half of a RAG pipeline is loops: chunking, filtering, numbering sources. Whoever asks "when is this condition checked, and on what?" at every loop stops the PR before a passenger with a dog is told the rules say nothing about cages.
