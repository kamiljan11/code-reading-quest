# S110 - Arrays: reference equality and edge values in an n8n Code node

**Concept:** an array method does exactly what its spec says, not what its name suggests. `Set` compares objects by reference (two identical orders are two values), `findIndex` with no match returns `-1` and `splice(-1, 1)` removes the LAST item, `Array(3).fill([])` puts the SAME array into all three slots, an empty array from `filter` is truthy in an `if`, and `Math.max()` of nothing is `-Infinity`.

**Story:** a bakery in Siglufjordur, Iceland, takes morning orders from two webhooks (the web shop and the phone line). An n8n `Code` node merges both lists, removes duplicates, handles cancellations, splits orders into three delivery routes and texts the baker when something is urgent. An AI assistant opened a PR "shorter array operations, no logic change". The next morning the driver of route 2 (which had no orders) got all four, order Z2 was delivered twice, Z3 never arrived although nobody cancelled it, and the baker got a text about an urgent order that did not exist.

## Verified

Run with node v22.23.4 and v24.21.0, each round as a separate file, before the key was written.

```
1) 4 Z1,Z2,Z2,Z3
2) Z1,Z2,Z2
3) 4 true
4) 0 SMS do piekarza
5) -Infinity Infinity
6) undefined Z3
```

```
7) 0 false
8) 3 2 [ 10, <1 empty item>, 14 ]
9) -1 true
10) 3 4
11) [] 3
```

Diagnosis: `Set` uses SameValueZero, which for objects means reference equality, so the two `Z2` objects from two webhooks both stay (line 1). `findIndex` returns `-1` for the missing `Z9`, and `splice` reads a negative index from the end, so the last order `Z3` is removed (line 2). `Array(3).fill([])` evaluates `[]` once and puts that one array in every slot, so every `push` lands in the same box (line 3). `filter` always returns an array and every array, empty or not, is truthy (line 4). `Math.max()` with no arguments is `-Infinity` (line 5), and `arr[-1]` looks up a property named `"-1"` while `at(-1)` counts from the end (line 6). In round 2, spread makes a shallow copy (new array, same item objects), `delete` leaves a hole that `forEach` skips and `map` keeps, `indexOf` uses `===` so it never finds `NaN` while `includes` does, `flat()` goes one level deep, and `map` returns a new array so clearing it leaves `items` alone.

Fix (the version before the PR: dedupe by `id` through a `Map`, a `-1` guard before `splice`, `Array.from` for the routes, `pilne.length > 0`, an empty-route check before `Math.max`), run separately on both node versions:

```
fix: Z1,Z2,Z3 / Z1,Z2,Z3 / [["Z1","Z3"],["Z2"],[]] / spokojny poranek / brak kursu
```

## Quiz

1. Why does `[...new Set(list)]` not remove duplicate orders sent by two webhooks, and how do you dedupe by `id`? (Key: `Set` compares objects by reference. Use `[...new Map(list.map(z => [z.id, z])).values()]` or a `filter` with a `Set` of ids.)
2. What does `list.splice(list.findIndex(cond), 1)` do when nothing matches? (Key: `findIndex` returns `-1` and `splice(-1, 1)` removes the last item. Store the index and only splice when it is not `-1`, or use `filter`.)
3. What is the difference between `Array(3).fill([])` and `Array.from({ length: 3 }, () => [])`? (Key: `fill` puts the same array in every slot; `Array.from` calls the function per slot and creates three separate arrays.)

## Card

**Front:** `const routes = Array(3).fill([]); routes[0].push("Z1");` - how many items does `routes[2]` have?
**Back:** 1. `fill` puts the SAME array into all three slots, so a push to one is visible under every index. Three separate arrays: `Array.from({ length: 3 }, () => [])`.

## Takeaway

n8n is the most common requirement in the AI integration job ads this log tracks, and inside an n8n `Code` node almost everything is an array: `$input.all()` returns a list of items. Whoever asks "how does this compare, what does it return when nothing matches, and is this a new box or the old one?" at every array method stops the PR before an empty route's driver leaves with someone else's bread.
