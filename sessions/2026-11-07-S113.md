# S113 - Objects: own vs inherited keys when an LLM tool call is merged with defaults

**Concept:** `JSON.parse` turns a `"__proto__"` key into an ordinary OWN property, and object spread copies it like any other key. `Object.assign` instead performs an assignment, which hits the `__proto__` setter on `Object.prototype` and REPLACES the target's prototype. From then on a field that is missing from `Object.keys` and `JSON.stringify` still answers through `obj.field`, `in` and `for...in`, and `delete` cannot remove it.

**Story:** an outdoor clothing shop in Reykjavik runs a refund agent in n8n. The model reads a customer email and returns a `refund` tool call as JSON text. A Code node merges the arguments with defaults (currency, a 20000 ISK limit) and decides: automatic payout or human review. An AI assistant opened a PR "shorter tool-argument merge, no logic change" that swapped spread for `Object.assign`. Tests passed and the log looked identical. A week later accounting found an automatic 150000 ISK refund: the customer had pasted "instructions for the system" into the email and the model copied them into the JSON.

## Quiz

1. How does `{ ...a }` differ from `Object.assign({}, a)` when `a` came from `JSON.parse` and has a `"__proto__"` key? **Key:** spread creates an own `"__proto__"` data key and leaves the prototype alone; `Object.assign` assigns through `[[Set]]`, i.e. through the `__proto__` setter, and swaps the target's prototype, so those fields become inherited.
2. Why can `args.hasOwnProperty("kwota")` throw a `TypeError` on model output, and what is the safe check? **Key:** the model can return a `"hasOwnProperty"` key that shadows the prototype method (a string is not a function). Use `Object.hasOwn(obj, "kwota")` or `Object.prototype.hasOwnProperty.call(obj, "kwota")`.
3. Which of these see an inherited field: `obj.x`, `"x" in obj`, `for...in`, `Object.keys`, `JSON.stringify`, `Object.hasOwn`? **Key:** `obj.x`, `in`, `for...in` see it; `Object.keys`, `JSON.stringify`, `Object.hasOwn` do not.

## Card

`Object.assign({}, JSON.parse('{"__proto__":{"x":1}}')).x` - what is it, and why does spread differ? :: `1`. `Object.assign` assigns `"__proto__"` through the setter and sets the target's prototype, so `x` is inherited (absent from `Object.keys` and `JSON.stringify`). Spread turns `"__proto__"` into a plain key, so `.x` is `undefined`.

## Takeaway

Structured output from an LLM is text that becomes an object, and one business decision gets made on its fields. Asking "is this field own or inherited, and who in this line only looks at own fields?" stops a "no logic change" PR before a customer approves their own refund while the log shows nothing wrong.
