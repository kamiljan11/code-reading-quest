# S115 - Operators: bitwise "shortcuts" and operator precedence in an n8n Code node

**Concept:** bitwise operators (`~~`, `| 0`, `&`, `^`, `<<`, `>>`) first convert the number to a signed 32-bit integer. So `~~x` truncates toward zero (not down like `Math.floor`), anything above 2^31 wraps around into garbage, and text without a number silently becomes `0`. On top of that, `&` has LOWER precedence than `==`, and `^` is XOR, not exponentiation.

**Story:** a tomato greenhouse ships boxes to shops. An n8n workflow takes a shop's webhook, and a Code node counts boxes, reads flags (cold storage, express, invoice) and computes a retry delay for the carrier API. An AI assistant opened a PR "faster bitwise rounding and shorter conditions, no logic change". The test on the first order passed. A week later the accountant asks why one shop got no invoices at all, and why a return was credited one box short.

## Round 1 - three orders and "faster" operators (find the bug, predict the output)

```js
// Szklarnia "Gardyrkja Laugaras", node `Code` w n8n: paczki pomidorow dla sklepow.
// PR od asystenta AI: "szybsze zaokraglanie bitowe i krotsze warunki, logika bez zmian".
const CHLODNIA = 1, EKSPRES = 2, FAKTURA = 4;

const items = [
  { id: "Z1", kg: 12.7, flagi: CHLODNIA | FAKTURA },
  { id: "Z2", kg: -3.5, flagi: EKSPRES },          // korekta: sklep oddal 3.5 kg
  { id: "Z3", kg: 8, flagi: FAKTURA },
];

items.forEach((z, i) => {
  const paczki = ~~z.kg;                       // bylo: Math.floor(z.kg)
  const chlodnia = z.flagi & CHLODNIA == 1;    // bylo: (z.flagi & CHLODNIA) !== 0
  const faktura = z.flagi & FAKTURA == 4;      // bylo: (z.flagi & FAKTURA) !== 0
  console.log(`${i + 1}) ${z.id} paczki=${paczki} floor=${Math.floor(z.kg)} chlodnia=${chlodnia} faktura=${faktura}`);
});

const backoff = (proba) => 500 * 2 ^ proba;    // bylo: 500 * 2 ** proba
console.log("4)", [0, 1, 2, 3].map(backoff).join(","));

const termin = Date.UTC(2026, 10, 9, 14, 30);  // ms od 1970
console.log("5)", termin | 0, termin, (termin / 1000) | 0);
console.log("6)", ~"Z1,Z3".indexOf("Z1"), ~"Z1,Z3".indexOf("Z2"), !!~"Z1,Z3".indexOf("Z2"));
```

## Quiz

1. What is `~~(-7.9)`, what is `Math.floor(-7.9)`, and why do they differ? **Key:** `-7` and `-8`. Bitwise conversion drops the fraction toward zero, `floor` always rounds down; for positive numbers the result is the same, so the bug only shows on corrections and returns.
2. What runs first in `flagi & MASKA === MASKA`, and how do you write it correctly? **Key:** `MASKA === MASKA` (true) first, then `flagi & true` = `flagi & 1`. Correct: `(flagi & MASKA) === MASKA` or `(flagi & MASKA) !== 0`.
3. Why are `"12.7kg" | 0` and `"abc" | 0` more dangerous than `Number("abc")`? **Key:** they give `0` with no error and no `NaN`, so bad input looks like a valid zero and flows on; `NaN` breaks every comparison and can be caught with `Number.isNaN`.

## Card

What runs first in `z.flagi & FAKTURA == 4`, and what comes out? :: `FAKTURA == 4` (because `==` binds tighter than `&`), so it is `z.flagi & true` = `z.flagi & 1`: the test checks bit 1, not the FAKTURA bit. Always parenthesise: `(z.flagi & FAKTURA) !== 0`.

## Takeaway

In real n8n work the Code node is where someone "speeds up" a calculation with one character. Checking the precedence of `&` and the 32-bit range in a PR like this catches the missing invoices before the accountant does.
