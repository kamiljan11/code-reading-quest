# S117 - Arrays: a "1:1 port from Python" where every line looks the same and does something else

**Concept:** a list operation copied from Python into JavaScript looks identical and behaves differently, without a single error. `+` and `*` turn arrays into a string or `NaN`, `t[-1]` is `undefined`, `reverse()` changes the original, an empty array is truthy, `==` compares addresses, `map` over the longer list does not truncate like `zip`, `reduce` without an initial value throws on an empty array, `push(array)` nests, `splice(indexOf(x), 1)` deletes the LAST element when `x` is missing, and `copy = t` is the same list. Only `slice` is a real 1:1 equivalent.

**Story:** a snowmobile tour company on a glacier used to build its daily schedule with a Python script. An AI assistant ported it into an n8n `Code` node with the PR title "1:1 port from grafik.py, no logic change", leaving the original Python line as a comment next to each JS line. The workflow ran green. Next morning one driver has no snowmobile, the third snowmobile left without a driver, and booking R3 vanished although the customer cancelled a booking that never existed.

## Quiz

1. What does `[1, 2] + [3]` give in JS, and how do you join two arrays? **Key:** the string `"1,23"`: `+` converts both arrays to text and concatenates. Join with `[...a, ...b]` or `a.concat(b)`.
2. What does `t.splice(t.indexOf(x), 1)` do when `x` is not in the array? **Key:** `indexOf` returns `-1` and `splice(-1, 1)` removes the LAST element, silently. Check for `-1` first.
3. How do you check that a list is empty in JS, and why does `if (list)` not do it? **Key:** `list.length === 0` (or `if (list.length)`); every array, empty or not, is an object, so `if (list)` is always true.

## Card

Porting `everyone = morning + noon` from Python to JS with two arrays: what is in `everyone`? :: A string, not an array: `+` turns both arrays into text (`"Anna,Bjorn" + "Cyril"` = `"Anna,BjornCyril"`) and `length` counts characters. Join arrays with `[...a, ...b]` or `a.concat(b)`.

## Takeaway

Porting a Python script into an automation node is everyday integration work. Asking, for every ported line, what type comes out, whether the method mutates, and what happens when the element is missing catches a schedule stored as a string before a snowmobile leaves with a `null` driver.
