# S118 - Reading a diff: a "simpler model-response parsing" PR that keeps the totals and changes who gets through

**Concept:** a diff where every line looks like a shorter equivalent of the old one changes behaviour exactly at the edges. `indexOf(k) > 0` drops the FIRST element of the list, `.` in a regex does not match a newline, `isNaN` lets `"0.85"` and `true` through, and `=+` is an assignment with unary plus, not addition. The total number of automatic decisions stays the same (3 of 5), so an aggregate metric shows nothing. One change (`replace` instead of `replaceAll`) is harmless here only because the regex below rescues it.

**Story:** a super-jeep tour company gets hundreds of customer emails a day. A model classifies each email into JSON `{kategoria, pewnosc}` (category, confidence), and an n8n `Code` node decides AUTO (the system reschedules or cancels by itself) or RECZNIE (manual queue). An AI assistant opened a PR "simpler model-response parsing, no logic change" and left the old version above each changed line. The dashboard after deploy: 3 AUTO of 5, same as yesterday. A week later a customer arrives for a tour the system cancelled on its own, and the model token bill is far above the limit that was supposed to stop the workflow.

```js
  let w;
  try { w = JSON.parse(wyciagnij(oczysc(odp)) ?? "{}"); }

  if (isNaN(w.pewnosc) || w.pewnosc < 0.8) return "RECZNIE (pewnosc)";
```

Before the PR (same inputs): `AUTO anulacja | AUTO zmiana_terminu | AUTO anulacja | RECZNIE (pewnosc) | RECZNIE (pewnosc)` and `3850 STOP: limit`. Four of five emails changed their fate, the AUTO count did not.

Fix (the PR rewritten so the logic really is unchanged):

```js
const DOZWOLONE = new Set(["zmiana_terminu", "anulacja", "pytanie"]);
const oczysc = (t) => t.replaceAll("```json", "").replaceAll("```", "").trim();
const wyciagnij = (t) => t.match(/\{[\s\S]*\}/)?.[0];
function klasyfikuj(odp) {
  let w;
  try { w = JSON.parse(wyciagnij(oczysc(odp)) ?? "{}"); }
  catch (e) { return "BLAD " + e.name; }
  if (!DOZWOLONE.has(w.kategoria)) return "RECZNIE (kategoria)";
  if (typeof w.pewnosc !== "number" || !Number.isFinite(w.pewnosc) || w.pewnosc < 0.8) return "RECZNIE (pewnosc)";
  return "AUTO " + w.kategoria;
}
const maile = [
  "```json\n{\"kategoria\":\"anulacja\",\"pewnosc\":0.93}\n```",
  "{\"kategoria\":\"zmiana_terminu\",\"pewnosc\":0.97}",
  "Oto klasyfikacja:\n{\n  \"kategoria\": \"anulacja\",\n  \"pewnosc\": 0.95\n}",
  "{\"kategoria\":\"pytanie\",\"pewnosc\":\"0.85\"}",
  "```\n{\"kategoria\":\"anulacja\",\"pewnosc\":true}\n```",
];
console.log("f1)", maile.map(klasyfikuj).join(" | "));
const wywolania = [
  { id: "M1", usage: { input_tokens: 1200, output_tokens: 300 } },
  { id: "M2", usage: { input_tokens: 900, output_tokens: 250 } },
  { id: "M3" },
  { id: "M4", usage: { input_tokens: 1000, output_tokens: 200 } },
];
let tokeny = 0, bezUsage = [];
for (const w of wywolania) {
  if (!w.usage) { bezUsage.push(w.id); continue; }
  tokeny += (w.usage.input_tokens ?? 0) + (w.usage.output_tokens ?? 0);
}
console.log("f2)", tokeny, tokeny > 3000 ? "STOP: limit" : "dalej", "bez usage:", bezUsage.join(","));
```

```text
f2) 3850 STOP: limit bez usage: M3
```

## Quiz

1. What does `["a", "b", "c"].indexOf("a") > 0` return, and how do you check list membership correctly? **Key:** `false`: the first element has index 0 and a missing one is -1. Use `includes(x)`, `indexOf(x) !== -1` or `Set.has(x)`.
2. What is the difference between `x =+ 5` and `x += 5`? **Key:** `x =+ 5` is `x = +5`, an assignment (unary plus) that throws the old value away; `x += 5` adds. Neither throws.
3. Does `/\{.*\}/` find a JSON object spread over several lines? What do you change? **Key:** No: `.` does not match a newline, so `match` returns `null`. Use `[\s\S]*` or the `s` flag.

## Card

`ALLOWED.indexOf(k) > 0` as a "is k on the list" test: where is the hole? :: The first element has index 0, so `> 0` rejects it (missing is -1). Test with `includes(k)`, `indexOf(k) !== -1` or `Set.has(k)`.

## Takeaway

Code that reads a model's structured output and decides AUTO or manual is everyday AI-integration work. Checking every `-`/`+` pair against an input where the two lines differ, and comparing decisions record by record instead of totals, catches a "same as yesterday" dashboard that hides two wrong decisions in each direction and a cost guard that can never fire.
