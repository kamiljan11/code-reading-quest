# S119 - Functions: a "cache search results with a shared memo helper" PR that answers questions with someone else's result

**Concept:** a wrapper is a NEW function that decides on its own what it passes to the original and what it treats as "the same call". `fn(a)` instead of `fn(...a)` passes the whole argument array as the first parameter (the second one falls back to its default), a key of `a[0]` or `String(object)` merges different calls into one, `if (!cache[k])` recomputes every falsy result (0), and a memoized promise remembers failure too, so a single 503 comes back on every later question without a single new attempt.

**Story:** a mountain guiding agency runs a RAG assistant that answers hikers about trails, river fords and huts. An n8n `Code` node queries a document index and an embeddings API, and both calls cost money. An AI assistant opened a PR "cache search results with a shared memo helper, logic unchanged" and left the pre-PR version above each helper. After the deploy the dashboard looks great: a third fewer index queries. A week later a Polish hiker gets instructions in English, every question about the ford fails although the embeddings API has been up since morning, and the language filter no longer filters anything.

## Round 1 - memo in the document search (find the bug + predict the output)

```js
// Agencja przewodnikow gorskich "Tindar" w Landmannalaugar: asystent RAG odpowiada turystom
// o szlakach, brodach i schroniskach. Node Code w n8n, wspolny helper cache.
// PR od asystenta AI: "cache wynikow wyszukiwania przez wspolny helper memo, logika bez zmian".
const baza = [
  { id: "D1", jezyk: "pl", tekst: "Szlak zamkniety po 18:00" },
  { id: "D2", jezyk: "en", tekst: "Trail closed after 18:00" },
  { id: "D3", jezyk: "pl", tekst: "Brod na rzece: tylko 4x4" },
  { id: "D4", jezyk: "pl", tekst: "Schronisko: 40 miejsc" },
];
let wywolaniaIndeksu = 0;
function szukaj(pytanie, opcje = { k: 3 }) {
  wywolaniaIndeksu++;
  return baza
    .filter((d) => !opcje.jezyk || d.jezyk === opcje.jezyk)
    .slice(0, opcje.k)
    .map((d) => d.id);
}

// przed: const memo = (fn) => { const c = new Map();
// przed:   return (...a) => { const key = JSON.stringify(a);
// przed:     if (!c.has(key)) c.set(key, fn(...a)); return c.get(key); }; };
const memo = (fn) => {
  const cache = {};
  return (...a) => {
    const key = a[0]; // "pytanie jest unikalne, opcje nie zmieniaja wyniku"
```

## Round 2 - embeddings and filtered search (separate file)

```js
// Starcie 2 - osobny plik: embeddingi pytan i wyszukiwanie z filtrem, ten sam PR.
let proby = 0;
async function embed(tekst) {
  proby++;
  if (proby === 1) throw new Error("503 Service Unavailable"); // pierwsze wywolanie: chwilowa awaria API
  return [tekst.length, 0.5];
}

// przed: const memoAsync = (fn) => { const c = new Map();
// przed:   return (x) => { const k = JSON.stringify(x);
// przed:     if (!c.has(k)) c.set(k, fn(x).catch((e) => { c.delete(k); throw e; }));
// przed:     return c.get(k); }; };
const memoAsync = (fn) => {
  const c = new Map();
  return (x) => {
    const k = String(x);
    if (!c.has(k)) c.set(k, fn(x));
    return c.get(k);
  };
};

const embedM = memoAsync(embed);
const wyszukaj = memoAsync(async (filtr) => `wyniki dla ${filtr.jezyk}`);

async function main() {
  let n = 8;
  for (const t of ["brod", "brod", "szlak"]) {
    const nr = n++;
    try { console.log(`${nr})`, t, await embedM(t)); }
    catch (e) { console.log(`${nr})`, t, "BLAD", e.message); }
  }
  console.log(`${n++})`, proby);
  console.log(`${n++})`, await wyszukaj({ jezyk: "pl" }), "|", await wyszukaj({ jezyk: "en" }));
}
main();
```

Fix (the helper rewritten so the logic really is unchanged; with objects whose key order may differ, build the key from explicit fields instead of `JSON.stringify`):

```js
const baza = [
  { id: "D1", jezyk: "pl", tekst: "Szlak zamkniety po 18:00" },
  { id: "D2", jezyk: "en", tekst: "Trail closed after 18:00" },
  { id: "D3", jezyk: "pl", tekst: "Brod na rzece: tylko 4x4" },
  { id: "D4", jezyk: "pl", tekst: "Schronisko: 40 miejsc" },
];
function szukaj(pytanie, opcje = { k: 3 }) {
  return baza.filter((d) => !opcje.jezyk || d.jezyk === opcje.jezyk).slice(0, opcje.k).map((d) => d.id);
}
// klucz = WSZYSTKIE argumenty, obecnosc przez has(), wywolanie ze spreadem, odrzucenie nie zostaje w cache
const memo = (fn) => {
  const c = new Map();
  return (...a) => {
    const key = JSON.stringify(a);
    if (!c.has(key)) {
      const w = fn(...a);
      c.set(key, w instanceof Promise ? w.catch((e) => { c.delete(key); throw e; }) : w);
    }
    return c.get(key);
  };
};
const szukajM = memo(szukaj);
console.log("f1)", szukajM("brod", { k: 1 }), szukajM("brod", { k: 2, jezyk: "pl" }), szukajM("szlak", { jezyk: "pl" }));
let proby = 0;
const embedM = memo(async (t) => { proby++; if (proby === 1) throw new Error("503 Service Unavailable"); return [t.length, 0.5]; });
const wyszukaj = memo(async (f) => `wyniki dla ${f.jezyk}`);
(async () => {
  const out = [];
  for (const t of ["brod", "brod", "szlak"]) {
    try { out.push(JSON.stringify(await embedM(t))); } catch (e) { out.push("BLAD"); }
  }
  console.log("f2)", out.join(" | "), "proby:", proby);
  console.log("f3)", await wyszukaj({ jezyk: "pl" }), "|", await wyszukaj({ jezyk: "en" }));
})();
```

## Quiz

1. What is the difference between `fn(a)` and `fn(...a)` when `a = ["brod", { k: 1 }]` and `fn` takes two parameters? **Key:** `fn(a)` passes ONE argument, the whole array, and the second parameter gets `undefined` (its default, if any). `fn(...a)` is `fn("brod", { k: 1 })`.
2. What does `String({ jezyk: "pl" })` give and why is it a bad cache key? **Key:** `"[object Object]"`, the same for every plain object, so all filters share one cache entry. Build the key with `JSON.stringify` or from explicit fields.
3. Why does `if (!cache[k])` recompute a result of `0`, while `if (!c.has(k))` does not? **Key:** `!cache[k]` asks whether the VALUE is truthy, and `0`, `""`, `null`, `false` are falsy; `has` asks whether the KEY exists.

## Card

A `memo` helper with `if (!cache[k]) cache[k] = fn(...)` wraps an async function: what are the two holes? :: A falsy result (0, "", null) is recomputed on every call, and a rejected promise stays in the cache forever (every later call gets the same error without a new attempt). Check `Map.has(k)` and delete the key in `catch` on failure.

## Takeaway

Caching shows up in every RAG project, because index queries and embeddings cost money. Reading each helper with two questions, "what key does it compute" and "what does it really call the original with", shows that "a third fewer queries" means questions that were answered with somebody else's result.
