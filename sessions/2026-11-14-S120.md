# S120 - Objects: a "brutto as a getter, hidden API key, archive copy via spread" PR that ships invoices without a total

**Concept:** a getter (`get brutto()`) and a property created with `Object.defineProperty` are not plain fields, they are fields with RULES. A getter runs on every read, but spread, `Object.assign` and `JSON.stringify` read it ONCE and store a plain number (the copy stops recalculating). A getter declared in a `class` lives on the prototype, so spreading an instance does not copy it at all. `defineProperty` with only a `value` creates a property that `Object.keys`, spread and JSON cannot see, and that is read-only: outside strict mode a new value is silently ignored.

**Story:** a coffee roastery invoices cafes from an n8n `Code` node: a line item with net amount and VAT, a copy for the invoice archive, then a call to the accounting system's API. An AI assistant opened a PR "brutto as a getter, API key hidden, archive copy via spread, logic unchanged" and left the pre-PR version in comments. Tests pass: the gross amount is right and the key is not in the log. A month later the accountant sees an archived correction with net 500 and gross 1240, after an API key rotation the workflow still sends the old key, and the "send to accounting" node receives an invoice with no gross amount.

## Round 1 - a getter and a hidden key on the invoice line (predict the output + find the bug)

```js
// Palarnia kawy "Kaffibrennslan" w Akureyri: node Code w n8n liczy faktury dla kawiarni.

// przed: const pozycja = { netto: 1000, vat: 0.24, kluczApi: "sk-live-9f2" };
// przed: const { kluczApi, ...doLogu } = pozycja; // klucz wycinany tylko z logu
```

With `"use strict"` line 5 throws `TypeError: Cannot assign to read only property 'kluczApi' of object '#<Object>'`. As an ES module line 8 throws `TypeError: Cannot read properties of undefined (reading 'vat')`.

Fix (gross as a function computed at use, an explicit snapshot, the key as a plain field cut out of the log only, `toJSON` in the class, a method plus `bind`):

```js
const brutto = (p) => Math.round(p.netto * (1 + p.vat));
const pozycja = { netto: 1000, vat: 0.24, kluczApi: "sk-live-9f2" };
const archiwum = { ...pozycja, brutto: brutto(pozycja) }; // migawka jawnie
pozycja.netto = 2000;
console.log("f1)", brutto(pozycja), archiwum.brutto, archiwum.kluczApi);
archiwum.netto = 500; console.log("f2)", brutto(archiwum));
const { kluczApi, ...doLogu } = pozycja; console.log("f3)", JSON.stringify(doLogu));
pozycja.kluczApi = "sk-live-NOWY"; console.log("f4)", pozycja.kluczApi);
const stawki = { vat: 0.24, liczF(n) { return Math.round(n * (1 + this.vat)); } };
const liczF = stawki.liczF.bind(stawki); console.log("f5)", liczF(1000));
```

## Quiz

1. What does the copy `{ ...obj }` get when `obj` has `get suma() { ... }` in an object literal? **Key:** a plain number: spread reads the getter ONCE at copy time and stores the result as a normal field, so the copy does not recalculate when other fields change.
2. Why does `{ ...new Faktura(1000) }` have no `brutto`, although `new Faktura(1000).brutto` works? **Key:** the class getter lives on `Faktura.prototype`, and spread copies only own, enumerable instance fields (`netto`). Reading `f.brutto` looks it up on the prototype.
3. What does `Object.defineProperty(o, "k", { value: 1 })` do to the visibility and writability of `k`? **Key:** the property is non-enumerable (invisible to `Object.keys`, spread, `JSON.stringify`, `for...in`), read-only and non-configurable; a write is silently ignored outside strict mode and throws `TypeError` in strict mode. `in` and dot access still see it.

## Card

`const copy = { ...obj }`, where `obj` has `get brutto()` in the literal and a field from `Object.defineProperty(obj, "key", { value })`: what does the copy have? :: `brutto` as a plain number computed once at copy time (no longer recalculated) and NO `key` (non-enumerable). A getter declared in a `class` does not survive spread at all, because it lives on the prototype.

## Takeaway

In n8n, objects travel from node to node through spread or JSON. Ask of every field: "a value or a rule, where does the rule live, and does it survive a copy?" The tests checked the original; accounting received the copy.
