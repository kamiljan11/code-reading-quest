# S121 - Reading errors: a "one AbortController for the whole retry" PR that makes three attempts in zero milliseconds

**Concept:** an abort error describes the state of the SIGNAL, not of the server. An `AbortController` that was aborted once stays aborted forever, so every later attempt that reuses its `signal` rejects immediately with the same error and sends nothing. The error name depends on who aborted: `AbortSignal.timeout()` gives `TimeoutError`, `abort()` gives `AbortError`, and `abort("text")` rejects with the bare string (no `name`, not an `Error`). A timeout built with `Promise.race` only stops waiting: the request keeps running, the server still saves it, and a retry duplicates it.

**Story:** a horse riding stable sells rides through a booking partner. An n8n `Code` node sends each booking to the partner's API with a 100 ms timeout and retries. An AI assistant opened a PR "one AbortController for the whole retry, retry after every abort, logic unchanged". After one slow response every such booking ends with "failure after 3 attempts", although the partner answers in 20 ms. The second variant from the same PR (timeout via `Promise.race`) works, but the partner sees booking R7 twice.

## Round 1 - one AbortController for the whole retry (order of execution + predict the output)

```js
// Stadnina "Hestaland" w Helli: node Code w n8n wysyla rezerwacje przejazdzek do API partnera.
// PR od asystenta AI: "jeden AbortController na caly retry, ponawiamy po kazdym przerwaniu, logika bez zmian".
function api(nazwa, czas, { signal } = {}) {        // atrapa fetch: honoruje signal tak jak fetch
  return new Promise((ok, nie) => {
    if (signal?.aborted) return nie(signal.reason);
    const t = setTimeout(() => ok(`${nazwa}: 201`), czas);
    signal?.addEventListener("abort", () => { clearTimeout(t); nie(signal.reason); }, { once: true });
  });
}

// przed: for (...) { const signal = AbortSignal.timeout(100); // nowy sygnal na kazda probe
// przed:   ... if (e.name !== "TimeoutError") return "BLAD, bez ponowienia"; }
async function zarezerwuj(czasy) {
  const c = new AbortController();
  setTimeout(() => c.abort(), 100);                 // "jeden timeout na caly retry, prosciej"
  for (let nr = 1; nr <= czasy.length; nr++) {
    try {
      return await api(`proba ${nr}`, czasy[nr - 1], { signal: c.signal });
    } catch (e) {
      console.log(`   proba ${nr}: ${e.name} | ${e.message}`);
      if (e.name !== "AbortError" && e.name !== "TimeoutError") return "BLAD, bez ponowienia";
    }
  }
  return "PORAZKA po " + czasy.length + " probach";
}

(async () => {
  console.log("1)", await zarezerwuj([300, 20, 20]));  // pierwsza proba trafia w zamulony serwer
  console.log("2)", await zarezerwuj([20]));

  const s1 = AbortSignal.timeout(10);
  const c2 = new AbortController(); c2.abort();
  const c3 = new AbortController(); c3.abort("limit czasu");
  await new Promise((r) => setTimeout(r, 50));
  for (const [n, s] of [["timeout(10)", s1], ["abort()", c2.signal], ["abort(tekst)", c3.signal]])
    console.log("3)", n, "|", s.reason?.name, "|", s.reason instanceof Error, "|", typeof s.reason);
})();
```

## Round 2 - timeout via Promise.race (separate file)

```js
// Starcie 2 - osobny plik: druga wersja z tego samego PR, "timeout przez Promise.race, bez AbortController".
const zapisane = [];
const serwer = (id, czas) => new Promise((ok) => setTimeout(() => { zapisane.push(id); ok(`${id}: 201`); }, czas));
const zTimeoutem = (p, ms) =>
  Promise.race([p, new Promise((_, nie) => setTimeout(() => nie(new Error(`timeout ${ms} ms`)), ms))]);

(async () => {
  let wynik;
  for (let nr = 1; nr <= 2 && !wynik; nr++) {
    try {
      wynik = await zTimeoutem(serwer(`R7/p${nr}`, nr === 1 ? 200 : 20), 100);
    } catch (e) {
      console.log(`4) proba ${nr}:`, e.message, "| zapisane:", zapisane.length);
    }
  }
  console.log("5)", wynik, "| zapisane:", zapisane.length);
  await new Promise((r) => setTimeout(r, 150));
  console.log("6) po chwili zapisane:", zapisane.join(","));
})();
```

Fix for Round 2 (the same idempotency key for every attempt of one booking):

```js
// Poprawka Starcia 2: ten sam Idempotency-Key we wszystkich probach, serwer zapisuje rezerwacje raz na klucz.
const zapisane = new Map();
const serwer = (klucz, id, czas) => new Promise((ok) => setTimeout(() => {
  if (!zapisane.has(klucz)) zapisane.set(klucz, id);
  ok(`${zapisane.get(klucz)}: 201`);
}, czas));
const zTimeoutem = (p, ms) =>
  Promise.race([p, new Promise((_, nie) => setTimeout(() => nie(new Error(`timeout ${ms} ms`)), ms))]);

(async () => {
  const klucz = "R7-2026-11-15";                 // jeden klucz na rezerwacje, nie na probe
  let wynik;
  for (let nr = 1; nr <= 2 && !wynik; nr++) {
    try {
      wynik = await zTimeoutem(serwer(klucz, `R7/p${nr}`, nr === 1 ? 200 : 20), 100);
    } catch (e) {
      console.log(`f4) proba ${nr}:`, e.message, "| zapisane:", zapisane.size);
    }
  }
  console.log("f5)", wynik, "| zapisane:", zapisane.size);
  await new Promise((r) => setTimeout(r, 150));
  console.log("f6) po chwili zapisane:", [...zapisane.values()].join(","));
})();
```

## Quiz

1. What happens to a second `fetch(url, { signal: c.signal })` if `c.abort()` was already called during the first one? **Key:** it rejects immediately without sending anything, with the same `signal.reason` (a `DOMException` named `AbortError`). An aborted signal stays aborted, so a retry needs a new controller or `AbortSignal.timeout()` per attempt.
2. How does the error from `AbortSignal.timeout(100)` differ from the one from `c.abort()` and from `c.abort("limit")`? **Key:** `timeout()` gives a `DOMException` with `name: "TimeoutError"`, `c.abort()` a `DOMException` with `name: "AbortError"`, and `c.abort("limit")` rejects with the bare string `"limit"` (no `name`, no `message`, not `instanceof Error`).
3. Why does a timeout built with `Promise.race` not protect against a double booking on retry? **Key:** the race only stops waiting for the slower request, it does not cancel it, so the server still performs it and the retry adds a second one. Only the same idempotency key on every attempt makes the server save it once.

## Card

A retry with one `AbortController` created before the loop: what do attempts 2 and 3 do after the first timeout? :: They send nothing: after `abort()` the signal is aborted forever, so every later attempt rejects at once with the same `AbortError`. Use a new signal per attempt (`AbortSignal.timeout(ms)`), and the same Idempotency-Key against duplicates.

## Takeaway

Timeouts and retries live in every API client. Draw the timeline in milliseconds and write down, for each attempt, the state of the signal and what the server is doing at that moment: three attempts in the log can be one attempt and two echoes, and a "timed out" request can still be the one that got saved.
