# S123 - Loops: a "shorter loops in validation and streaming" PR where every field is missing, a valid retry result turns into null and the agent runs one turn past its limit

**Concept:** a loop does exactly what its header and its last line say, not what the PR description says. `for (const [i, field] of ARRAY)` over strings destructures each STRING into characters (without `.entries()`, `i` is the first letter and `field` the second). `const result` inside the loop body is a NEW variable that disappears with the block, so the outer `result` stays `null`. A loop over stream chunks ends with a remainder in the buffer that has to be handled AFTER the loop. `do...while` runs its body once before checking the condition, and `<=` in the condition gives one extra turn.

**Story:** a lava cave tour company classifies customer emails with a model, and an n8n `Code` node reads the structured output: it checks required fields, retries when the model returns prose instead of JSON, assembles the answer from a stream and runs an agent loop that calls tools. An AI assistant opened a PR "shorter loops in validation and streaming, logic unchanged" and left the pre-PR version in comments. Since then every email lands in manual review, the retry reports `null` although the model answered correctly, the daily report is missing the last email of each batch, and accounting asks who approved a refund after the two-turn limit.

## Round 2 - the agent loop with tools (separate file)

```js
// Starcie 2 - osobny plik: ten sam PR, petla agenta z narzedziami (tool calling).
function agent(odpowiedzi, MAX) {
  let tura = 0;
  let odp = odpowiedzi[0];
  const wykonane = [];
  do {                                               // przed PR: while (odp.stop === "tool_use" && tura < MAX) {
    for (const call of odp.calls) wykonane.push(call.name);
    tura++;
    odp = odpowiedzi[tura];
  } while (odp && odp.stop === "tool_use" && tura <= MAX);   // przed PR: brak do...while, tura < MAX
  return `tury: ${tura} | narzedzia: ${wykonane.join(",") || "-"}`;
}

const ROZMOWA = [
  { stop: "tool_use", calls: [{ name: "szukaj_rezerwacji" }] },
  { stop: "tool_use", calls: [{ name: "sprawdz_pogode" }, { name: "szukaj_rezerwacji" }] },
  { stop: "tool_use", calls: [{ name: "zwrot_pieniedzy" }] },
  { stop: "tool_use", calls: [{ name: "zwrot_pieniedzy" }] },
  { stop: "end_turn", text: "Zwrot zlecony." },
];
console.log("4)", agent(ROZMOWA, 2));

const POWITANIE = [{ stop: "end_turn", text: "Dzien dobry, w czym pomoc?" }];
try {
  console.log("5)", agent(POWITANIE, 2));
} catch (e) {
  console.log("5)", e.constructor.name, "|", e.message);
}
```

## Quiz

1. What do `i` and `field` get in `for (const [i, field] of ["kategoria", "pewnosc"])`, and what with `.entries()`? **Key:** without `.entries()` `for...of` yields strings, and `[i, field]` destructures a string into characters: `i = "k"`, `field = "a"`, then `"p"` and `"e"`. With `.entries()` you get `[index, string]` pairs: `[0, "kategoria"]`, `[1, "pewnosc"]`.
2. Why does `const result = JSON.parse(txt); break;` in a retry loop leave the outer `let result = null` unchanged? **Key:** `const` inside the block declares a new variable with the same name that shadows the outer one and disappears at the end of the block. Assign to the outer one without `const`: `result = JSON.parse(txt);`.
3. How does `do { ... } while (condition)` differ from `while (condition) { ... }` when the condition is false from the start? **Key:** `do...while` runs the body once before checking the condition (it checks at the end); `while` checks first and with a false condition never runs the body.

## Card

Loops around a model response: what do `for (const [i, x] of strings)`, `const result` inside the loop body and `do...while` on a first `end_turn` response do? :: Without `.entries()`, `[i, x]` splits a string into letters; `const result` in the block is a new variable (the outer one is unchanged); `do...while` runs the body once without checking the condition. Also: handle the stream buffer remainder AFTER the loop, and the turn limit is `turn < MAX`.

## Takeaway

Structured output from an LLM usually means four loops around the model: field validation, retry, stream assembly and the agent loop. A "shorter loops" PR passes review because the headers look familiar. Ask three questions for each loop: what the loop variable receives, which block the result lives in, and what is left after the last iteration.
