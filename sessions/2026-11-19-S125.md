# S125 - Reading a diff: a "parallel sends instead of a loop, faster, no logic changes" PR where the n8n Code node returns zero items before the first SMS goes out, `finally` reports done before the CRM write, and a 429 error skips the fallback queue

**Concept:** a diff that only changes WHEN a line runs also changes WHAT comes out. `forEach(async ...)` fires every send and waits for none of them, so the log and `return items` run before the first SMS (zero items go to the CRM). `return promise` without `await` inside `try` leaves the function at once, so `finally` prints before the write, and the rejection bypasses `catch` and the fallback queue.

**Story:** a photo tour company sends participants of the morning tour an SMS with the meeting time. An n8n `Code` node sends the messages through an SMS gateway and returns items with the sent bookings to the next node, which marks them in the CRM. A second file writes bookings to the CRM and puts failed ones in a fallback queue. An AI assistant opened a PR "parallel sends instead of a loop, faster, no logic changes" and removed a "redundant" `await` next to `return`. The pre-PR version is left in comments.

## Round 1 - sending SMS and items for the next node (order of execution + predict the output)

```js
// Wycieczki fotograficzne "Kirkjufell" w Grundarfjordur: node Code w n8n wysyla SMS-y z przypomnieniem
// o zbiorce i zwraca items z wyslanymi rezerwacjami do nastepnego node'a (zapis w CRM).
// PR od asystenta AI: "rownolegle wysylki zamiast petli, szybciej, logika bez zmian". W komentarzu wersja sprzed PR.
const czekaj = (ms) => new Promise((r) => setTimeout(r, ms));
const REZ = [{ id: "R1", ms: 30 }, { id: "R2", ms: 10 }, { id: "R3", ms: 20 }];
const wyslane = [];

async function wyslij(r) {
  console.log("  start", r.id);
  await czekaj(r.ms);               // bramka SMS odpowiada po r.ms
  wyslane.push(r.id);
  console.log("  SMS", r.id);
}

async function main() {
  REZ.forEach(async (r) => { await wyslij(r); });   // przed PR: for (const r of REZ) await wyslij(r);
  console.log("1) zapisano w logu:", wyslane.length);
  const items = wyslane.map((id) => ({ json: { id } }));
  console.log("2) node zwraca items:", items.length);
  return items;
}

main().then((items) => console.log("3) node Code zakonczony, do CRM idzie:", items.length));
```

## Round 2 - CRM write with a fallback queue (separate file)

```js
// Starcie 2 - osobny plik: ten sam PR, zapis rezerwacji w CRM z kolejka zapasowa przy bledzie.
// Zmiana w PR: "return await to nadmiarowy await, usuwam, logika bez zmian".
const czekaj = (ms) => new Promise((r) => setTimeout(r, ms));

async function zapiszDoCRM(id) {
  await czekaj(5);
  if (id === "R2") throw new Error("CRM 429");
  console.log("  CRM zapisal", id);
  return "OK " + id;
}

async function bezpiecznie(id) {
  try {
    return zapiszDoCRM(id);                           // przed PR: return await zapiszDoCRM(id);
  } catch (e) {
    return "KOLEJKA " + id + " (" + e.message + ")";
  } finally {
    console.log("  finally", id);
  }
}

async function main() {
  const wyniki = await Promise.allSettled(["R1", "R2", "R3"].map(bezpiecznie));
  console.log("4)", wyniki.map((w) => (w.status === "fulfilled" ? w.value : "ODRZUCONE: " + w.reason.message)).join(" | "));
  const ok = wyniki.filter((w) => w.status === "fulfilled").length;
  console.log("5) zapisane:", ok, "| w kolejce zapasowej:", wyniki.filter((w) => String(w.value).startsWith("KOLEJKA")).length);
}
main();
```

## Quiz

1. What does `[1, 2, 3].forEach(async (x) => { await save(x); })` return, and does the next line wait for the saves? **Key:** `undefined`. `forEach` ignores the promises returned by the callback, so the next line runs immediately.
2. Inside `try { ... } catch { ... }` in an `async` function, what is the difference between `return f()` and `return await f()` when `f()` returns a rejected promise? **Key:** `return f()` leaves `try` at once: `finally` runs before the result and the rejection skips `catch` and goes to the caller. `return await f()` waits inside `try`, so `catch` sees the error and `finally` runs after the result.
3. How do you rewrite a parallel send so the line after it sees every result? **Key:** `const results = await Promise.all(x.map(f))` (or `Promise.allSettled` if one failure must not stop the rest). The results keep the input order, whichever response arrived first.

## Card

A diff replaces `for (const r of x) await f(r)` with `x.forEach(async r => await f(r))` and drops `await` from `return await f()` inside `try`. What changes? :: `forEach` does not wait: the log and `return items` run before the results, so the node returns empty items; use `for...of` or `await Promise.all(x.map(f))`. Without `await` inside `try`, `finally` runs before the result and the rejection skips `catch`; inside `try` always `return await`.

## Takeaway

An n8n `Code` node ends with a result for the next node. This PR did not change a single value, only the order, and that was enough for the CRM to mark nobody and for one booking to vanish without a trace. When a diff touches `async` code, ask one question for every promise: who is waiting for it?
