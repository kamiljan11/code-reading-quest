# S126 - Functions: a "pass methods directly instead of arrows, hoist the error array, no logic changes" PR where the agent can no longer check a time slot and the structured-output validator rejects valid emails

**Concept:** a method handed on without its object is a plain function, and `this` is decided at CALL time. `NARZEDZIA[c.name](...)` makes the tool map `this`, so `sprawdz_termin` throws a TypeError, while `bind` pins the object for good. A function returned from a factory remembers the factory's variables: an error array hoisted above `return function` is shared by every email, so one bad email pollutes the next. A default parameter is evaluated on every call and only for `undefined`, never for `null`.

**Story:** a glacier tour company runs an n8n agent that answers customer emails through a model. The model returns structured output with a list of tool calls (`zarezerwuj`, `sprawdz_termin`, `podsumuj`) and a `Code` node runs them by name on a guides' calendar object. A second node validates the model's email classification before it reaches the CRM. An AI assistant opened a PR: "pass methods directly instead of arrows, hoist the error array, shorter, no logic changes". Tests passed because they only covered `zarezerwuj`.

## Round 1 - tool calls from the model (predict the output, then: what if the PR were reverted?)

```js
// Wycieczki na lodowiec "Solheimajokull": node Code w n8n wykonuje tool calls zwrocone przez model
// (structured output: lista wywolan) na obiekcie kalendarza przewodnikow.
// PR od asystenta AI: "metody przekazane bezposrednio zamiast strzalek, krocej, logika bez zmian". W komentarzu wersja sprzed PR.
const kalendarz = {
  wolne: ["10:00", "14:00"],
  sprawdz(args) { return this.wolne.includes(args.godzina) ? "wolne" : "zajete"; },
  zarezerwuj(args) {
    this.wolne = this.wolne.filter((g) => g !== args.godzina);
    return "zarezerwowano " + args.godzina;
  },
};

const NARZEDZIA = {
  sprawdz_termin: kalendarz.sprawdz,                  // przed PR: (a) => kalendarz.sprawdz(a)
  zarezerwuj: kalendarz.zarezerwuj.bind(kalendarz),   // przed PR: (a) => kalendarz.zarezerwuj(a)
  podsumuj: () => "wolne: [" + kalendarz.wolne + "]",  // bez zmian
};

const odp = JSON.parse(`{"calls":[
  {"name":"zarezerwuj","args":{"godzina":"10:00"}},
  {"name":"sprawdz_termin","args":{"godzina":"10:00"}},
  {"name":"constructor","args":{"godzina":"12:00"}},
  {"name":"pogoda","args":{}},
  {"name":"podsumuj","args":{}}]}`);

odp.calls.forEach((c, i) => {
  if (!NARZEDZIA[c.name]) return console.log(`${i + 1})`, c.name, "-> nieznane narzedzie");
  try {
    console.log(`${i + 1})`, c.name, "->", NARZEDZIA[c.name](c.args));
  } catch (e) {
    console.log(`${i + 1})`, c.name, "->", e.constructor.name + ":", e.message);
  }
});

const rezerwuj = NARZEDZIA.zarezerwuj;
console.log("6)", rezerwuj({ godzina: "14:00" }), "|", NARZEDZIA.podsumuj());
```

## Round 2 - structured-output validator (separate file)

```js
// Starcie 2 - osobny plik: ten sam PR, walidator structured output (klasyfikacja maili przez model).
// Zmiana w PR: "tablica bledow wyciagnieta przed funkcje, zeby nie tworzyc jej przy kazdym mailu, logika bez zmian".
let MAX_TOKENOW = 50;

function zrobWalidator(wymagane) {
  const bledy = [];                                   // przed PR: ta linia byla pierwsza linia w waliduj()
  return function waliduj(obj, limit = MAX_TOKENOW) {
    for (const p of wymagane) if (!(p in obj)) bledy.push(obj.id + ": brak " + p);
    if (obj.tokeny > limit) bledy.push(obj.id + ": " + obj.tokeny + " > " + limit);
    return bledy.length === 0 ? "OK" : bledy.join("; ");
  };
}

const waliduj = zrobWalidator(["kategoria", "pewnosc"]);
const M = [
  { id: "M1", kategoria: "rezerwacja", pewnosc: 0.9, tokeny: 40 },
  { id: "M2", kategoria: "skarga", tokeny: 30 },
  { id: "M3", kategoria: "pytanie", pewnosc: 0.8, tokeny: 45 },
];

console.log("7)", waliduj(M[0]));
console.log("8)", waliduj(M[1]));
console.log("9)", waliduj(M[2]));
MAX_TOKENOW = 42;
console.log("10)", waliduj(M[2], undefined));
console.log("11)", waliduj(M[0], null));
```

## Quiz

1. What is `this` in `const f = obj.method; f()`, and in `const g = obj.method.bind(obj); g()`? **Key:** `f()` loses the object: `this` is `undefined` in strict mode or `globalThis` in a sloppy script, so `this.x` does not read `obj.x`. `g()` always has `this` = `obj`, however it is called.
2. How many times is a variable created when it is declared in the factory above `return function`, versus inside the returned function? **Key:** the first once per factory call, shared by every call of the returned function (state leaks between emails); the second fresh on every call.
3. When is `function f(x = DEFAULT)` evaluated, and for which arguments? **Key:** on every call, with the current value of `DEFAULT` (unlike Python, where a default is evaluated once at `def`). Only when the argument is missing or `undefined`; `null`, `0` and `""` pass through.

## Card

A diff replaces `(a) => obj.method(a)` with plain `obj.method` in a tool map and hoists `const errors = []` above `return function`. What changes? :: A method without its object gets `this` from the caller (here the tool map), so `this.field` is undefined and a TypeError is thrown; an arrow or `bind` keeps the object. An array above `return function` is shared by every call, so one email's errors stick to the next ones.

## Takeaway

LLM and structured-output work is mostly code that takes a list of calls from a model, runs functions by name and validates the answer. This PR changed no rule, only which `this` and which array a function starts with, and that was enough for the agent to lose its calendar and for the validator to reject valid emails. For every function in a diff, ask: who calls it, and what does it remember?
