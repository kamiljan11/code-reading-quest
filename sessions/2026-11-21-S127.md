# S127 - Objects: a "the body is already parsed, sign JSON.stringify(body), Object.fromEntries and Object.groupBy instead of hand-written code, no logic changes" PR that rejects 4 of 5 genuine payment webhooks and drops payments from the refund filter

**Concept:** an object is not the text it was parsed from. `JSON.stringify(JSON.parse(raw))` produces different bytes: `12000.50` becomes `12000.5`, integer-like keys are reordered ascending, only the last of a duplicated key survives and whitespace disappears. An HMAC computed over the re-serialised object therefore no longer matches the partner's signature. When building objects from pairs, `Object.fromEntries` and key normalisation keep the last value of a repeated key, and `Object.groupBy` returns an object with a `null` prototype, so it has no `hasOwnProperty`.

**Story:** a glacier tour and basecamp company receives payment webhooks (payments and refunds) from a payment partner. An n8n `Code` node verifies the HMAC-SHA256 signature (the partner signs the RAW body, exactly the bytes it sent) and routes events by a query-string filter. An AI assistant opened a PR: "the Webhook node already gives us a parsed object, so we sign `JSON.stringify(body)`; manual query parsing replaced with `Object.fromEntries`, `reduce` replaced with `Object.groupBy`, headers normalised to lower case; shorter, no logic changes". The test passed because the test webhook looked like ev_1.

## Quiz

1. Why is a webhook signature computed over the raw body and not over `JSON.stringify` of the parsed object? **Key:** the partner signed specific bytes. Parsing and re-serialising can change numbers, integer-key order, duplicates, whitespace and escapes, so the HMAC of the new text does not match even though the data looks the same. In n8n enable the raw body and verify against it, ideally with `crypto.timingSafeEqual`.
2. What does `Object.fromEntries(new URLSearchParams("a=1&a=2"))` return, and how do you read both values? **Key:** `{ a: "2" }`, because the last value of a repeated key wins; `params.getAll("a")` returns `["1", "2"]`.
3. Why does `Object.groupBy(list, f).hasOwnProperty("x")` throw a TypeError, and what works instead? **Key:** `Object.groupBy` returns an object with a `null` prototype, so it does not inherit `hasOwnProperty` from `Object.prototype`; use `Object.hasOwn(obj, "x")` or `"x" in obj`.

## Card

A diff replaces `HMAC(req.raw)` with `HMAC(JSON.stringify(body))` because "the body is already parsed". What changes? :: The signature stops matching for every body whose serialisation is not canonical: `12000.50` -> `12000.5`, integer-like keys ascending, only the last duplicate key kept, whitespace removed. Always verify a signature over the exact bytes that arrived.

## Takeaway

REST, API and webhook work largely means accepting other people's webhooks and proving they are genuine. This PR touched no business rule; it only turned text into an object and back, and 4 out of 5 genuine payments would have been rejected, because an HMAC sees bytes, not data. For every webhook in a diff, ask: what exactly is the signature computed over, and how many times was the body parsed on the way?
