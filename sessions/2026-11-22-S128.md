# S128 - Errors: a "1:1 port of rezerwacje.py and dostepnosc.py, no logic changes" PR that saves a booking for zero people, rejects a customer with no reason, blames the customer for our own bug and never retries a network failure

**Concept:** an error moved from Python to JS has to be read again, because the same words throw something else or nothing at all. `console.assert` only prints `Assertion failed` and carries on, `throw "text"` throws a bare string with no `message`, a single `catch` catches every type (including our own bug in code that sat in Python's `else:`), and `new Error(msg, e)` does not set `cause`, so a retry decision based on the cause never happens.

**Story:** an ice cave tour company has two old scripts: `rezerwacje.py` validates bookings before they are saved to the CRM, and `dostepnosc.py` asks a partner for free places and retries only network failures. Everything now has to run in an n8n `Code` node, so an AI assistant opened a PR: "1:1 port from Python, `assert` -> `console.assert`, `raise` -> `throw`, `else` folded into `try`, `raise ... from e` -> `new Error(msg, e)`; no logic changes". The test with R1 passed.

## Round 1 - booking validation (predict the output)

```js
// Jaskinie lodowe "Ishellir" w Hofn: node Code w n8n waliduje rezerwacje przed zapisem do CRM.
// PR od asystenta AI: "port 1:1 z rezerwacje.py, logika bez zmian". Oryginal w Pythonie:
//   def waliduj(r):
//       assert r["osoby"] > 0, "osoby musza byc > 0"
//       if r["termin"] < "2026-12-01":
//           raise ValueError("termin przed sezonem")
//       return r
//   for r in REZ:
//       try:
//           ok = waliduj(r)
//       except (ValueError, AssertionError) as e:
//           print(r["id"], "ODRZUCONA:", e)
//       else:
//           zapisz(ok)      # blad przy zapisie to NIE odrzucenie klienta: leci wyzej, do alertu
const REZ = [
  { id: "R1", osoby: 4, termin: "2026-12-03", email: "anna@fjord.is" },
  { id: "R2", osoby: 0, termin: "2026-12-04", email: "bjorn@fjord.is" },
  { id: "R3", osoby: 2, termin: "2026-11-28", email: "cyril@fjord.is" },
  { id: "R4", osoby: 3, termin: "2026-12-10" },
];
const CRM = [];

function waliduj(r) {
  console.assert(r.osoby > 0, "osoby musza byc > 0");          // assert -> console.assert
  if (r.termin < "2026-12-01") throw "termin przed sezonem";    // raise ValueError(...) -> throw
  return r;
}

function zapisz(r) {
  const domena = r.email.split("@")[1];
  CRM.push(`${r.id}@${domena}`);
}

let odrzucone = 0;
REZ.forEach((r, i) => {
  try {
    const ok = waliduj(r);
    zapisz(ok);                                                 // else: zapisz(ok)
    console.log(`${i + 1})`, r.id, "zapisana");
  } catch (e) {
    odrzucone++;
    console.log(`${i + 1})`, r.id, "ODRZUCONA:", e.message);    // print(..., e)
  }
});
console.log("5) CRM:", CRM.join(","), "| odrzucone:", odrzucone, "| alerty: 0");
```

## Round 2 - wrapping the partner error, same PR (separate file)

```js
// Starcie 2 - osobny plik: ten sam PR, dostepnosc miejsc od partnera (dostepnosc.py).
// Oryginal:  except Exception as e:
//                raise RuntimeError(f"dostepnosc {t}") from e
//            a wyzej: ponow tylko gdy isinstance(blad.__cause__, ConnectionError)
function pobierz(t) {
  if (t === "12-05") throw new TypeError("fetch failed");   // siec padla, warto ponowic
  if (t === "12-06") throw new RangeError("miejsca: -2");    // zly payload partnera, nie ponawiac
  return 8;
}

function dostepnosc(t) {
  try {
    return pobierz(t);
  } catch (e) {
    throw new Error(`dostepnosc ${t}`, e);                    // raise RuntimeError(...) from e
  }
}

["12-05", "12-06"].forEach((t, i) => {
  try {
    dostepnosc(t);
  } catch (blad) {
    const ponow = blad.cause instanceof TypeError;
    console.log(`${i + 6})`, blad.message, "|", blad.cause, "|", ponow ? "PONAWIAM" : "PORAZKA bez ponowienia");
  }
});

const e1 = new TypeError("fetch failed");
console.log("8)", new Error(e1).message, "|", new Error(e1) instanceof TypeError);
console.log("9)", String(e1), "|", String(e1) === "fetch failed");
console.log("10)", new Error("x", { cause: e1 }).cause.name, "|", "cause" in new Error("x", e1));
```

## Quiz

1. What does `console.assert(false, "x")` do in Node, and how is it different from Python's `assert`? **Key:** it prints `Assertion failed: x` to stderr and does NOT throw; execution continues. Python's `assert` raises AssertionError. In a port use `if (!cond) throw new Error("x")` or `assert` from `node:assert`.
2. How do you write Python's `raise RuntimeError("msg") from e` in JS so the cause survives? **Key:** `throw new Error("msg", { cause: e })`. `new Error("msg", e)` treats `e` as the options object and sets no `cause`.
3. Why does moving code from Python's `else:` into the `try` block change behaviour? **Key:** `else` runs only after a successful `try` and its errors are NOT caught by `except`. In JS the code inside `try` is guarded by the same `catch`, which catches every type, so our own write error looks like a data rejection. Call the write outside `try`, or check the error type and rethrow.

## Card

A 1:1 port from Python: `assert` -> `console.assert`, `raise ValueError("t")` -> `throw "t"`, `raise X from e` -> `new Error(m, e)`. What breaks? :: `console.assert` does not throw (it only logs), throwing a string gives `e` without `message`, `new Error(m, e)` sets no `cause` (use `{ cause: e }`), and one `catch` instead of `except` + `else` also catches our own write errors. For every error in a port ask: does it throw, what does it throw, and who catches it.

## Takeaway

Python work in automation roles very often means moving an old script into an n8n `Code` node. This PR changed no business rule, yet the CRM got a booking for zero people, a customer with a valid date got a refusal with no reason, our own bug was logged as the customer's fault, and network failures stopped being retried. In a port, read the errors separately from the logic: do they fire at all, what are they, and where do they land.
