# S130 - Loops: a "generator instead of an intermediate array, less memory, no logic changes" PR that sends zero passes to the lift gates, counts zero paid passes and texts a pass called undefined

**Concept:** a generator or iterator (`function*`, `map.keys()`) can be looped over ONLY ONCE. A second loop over the same object does zero iterations and throws no error. In the same PR, `do...while` runs its body before checking the condition, `for...in` does not see Map entries, and `for...of` over a string walks its characters.

**Story:** a ski area above Akureyri sells lift passes at the ticket desk. Every morning an n8n `Code` node totals the revenue, sends the list of passes to the lift gates and texts "your pass is ready". An AI assistant opened a PR: "generator instead of an intermediate array, less memory, no logic changes". The test only checked the revenue, and it passed.

## Quiz

1. How many times can you loop with `for...of` over the object returned by a `function*`? **Key:** once. After that the generator is exhausted and every further loop or spread does zero iterations, with no error. Materialise it into an array once (`[...gen]`) or call the generator again.
2. How does `do { ... } while (w)` differ from `while (w) { ... }` on an empty queue? **Key:** `do...while` runs the body once before checking the condition (here: an SMS for `undefined`); `while` checks first and runs nothing.
3. What does `for (const k in map)` count for `new Map([["a", 1]])`, and how do you loop over Map entries? **Key:** zero iterations: `for...in` walks the object's own enumerable properties, and Map entries are not properties. Use `for (const [k, v] of map)` or `map.forEach`.

## Card

What happens on a second `for...of` over the same generator or `map.keys()`? :: Nothing: the iterator is exhausted, the loop does zero iterations and throws no error. Arrays (`items.map`, `[...map.keys()]`) can be read many times. When a PR says "generator instead of an array", count how many times the code reads the result.

## Takeaway

An n8n `Code` node often reads the same items several times: a total, a list for the gates, a filter. A PR that swaps the array for a generator "to save memory" throws nothing, the revenue test passes, and the lift gates receive zero passes. In review, ask how many times the result is read.
