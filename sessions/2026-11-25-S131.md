# S131 - Arrays: a "shorter ranking and category validation, no logic changes" PR that sends a booking email to the refunds queue and makes the validator reject every category

**Concept:** every array method has a contract. A `sort` comparator must return a number (a boolean gives only 1 and 0, so nothing moves), `sort` changes the original and returns THE SAME array, `includes` looks for THE SAME object and the same type, `for...in` yields indexes as strings, and `forEach` returns `undefined`.

**Story:** a visitor centre at Thingvellir gets hundreds of emails a day. An n8n `Code` node sends each one to a model that returns structured output: a list of candidate categories with confidence scores and a priority. The code picks the most confident category, checks it against an allow-list and routes the email to a queue. An AI assistant opened a PR: "shorter ranking and category validation, no logic changes". The tests only checked that nothing throws, and they passed.

console.log("3)", DOZWOLONE.includes({ kategoria: ranking[0].kategoria }));

const PRIORYTETY = [1, 2, 3];
// przed PR: PRIORYTETY.includes(Number(odp.priorytet))

## Quiz

1. Why does `sort((a, b) => a.pewnosc < b.pewnosc)` not sort in descending order? **Key:** the comparator returns true/false, i.e. 1/0, and `sort` needs a negative, zero or positive number; without a negative value it never knows when to swap. Correct: `(a, b) => b.pewnosc - a.pewnosc`.
2. What does `[{ id: 1 }].includes({ id: 1 })` return, and how do you check for an element with that `id`? **Key:** `false`, because `includes` compares references and the literal is a new object. Check by field: `some(x => x.id === 1)`.
3. What type is `i` in `for (const i in ["a", "b"])`, and what follows for `i === 0`? **Key:** a string ("0", "1"), so `i === 0` is always false and `i + 1` concatenates. For numeric indexes use `forEach((e, i) => ...)` or `for (const [i, e] of t.entries())`.

## Card

What does the comparator `(a, b) => a.x < b.x` return, and why does `sort` not work with it? :: true/false, i.e. 1/0, never a negative number, so `sort` cannot tell when to swap (in V8 here: order unchanged). A comparator must return a number: `b.x - a.x` for descending.

## Takeaway

An LLM returns a list of candidates with confidence scores and the code takes the first one. No test fails: the booking email simply lands in the refunds queue. In review, ask what the comparator returns and whether anyone still reads the original array.
